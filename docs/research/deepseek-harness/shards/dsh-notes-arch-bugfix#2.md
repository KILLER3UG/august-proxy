# deepseek-harness / dsh-notes-arch-bugfix#2

## Shard shape

This shard is 260 files in a single directory, `.agents/notes/archived/bug-fix/`, and it is one artefact type repeated: 86 English "Agent Note" RFCs, their 87 Chinese counterparts (`.zh.md`, one of which — `2026-08-11-synchronous-subprocess-exit-cleanup` — has no English sibling in this shard), and 87 `.i18n.yaml` bilingual-pairing sidecars that record the git blob hash of each side. The notes run from 2026-08-11 to 2026-09-19 and are all `Status: implemented` — they are frozen snapshots of shipped decisions, not proposals. Every note follows the same skeleton the repo's `verify-agent-note-format` gate enforces (`## Problem` / `## Decision` / `## Alternatives considered` / `## Consequences`, with `## Testing` or `## Verification` where the note has evidence), and the two sections that carry most of the value are the *alternatives* and the *consequences* — each note records what was rejected and why, plus the cost the decision accepted. Content-wise the shard maps onto five clusters that interlock: the **agent loop and session protocol** (turn/step events, projections, replay state, tool-result pairing, goal pause, fork boundaries, subagent message ordering); the **web client** (composer, trigger menu, sidebars, stats strip, diff cards, popovers, connection recovery); the **Windows/host platform layer** (junction handling, UTF-16 picker paths, subprocess console visibility, atomic replace, file locks); the **model adapter layer** (DeepSeek vision/token pricing, Messages history compatibility, pi-ai credentials and catalogs, session-reference budgets); and the **experimental CPython code runtime**, which three of the notes harden in sequence. The notes are unusually good engineering records: most quote a measurement, a reproduction, or an explicit "verified fail-before" line, and several carry a table of accepted residual costs.

### .agents/notes/archived/bug-fix/2026-08-12-collapsed-sidebar-shared-entry-motion.md
- Purpose: Fixes a visual mismatch in the collapsed sidebar rail, where four upper controls (shell toggle + New Session; workspace add + search) shared an opacity timeline but not a geometry timeline, so right-aligned controls appeared to move later than left-aligned ones.
- Key abstractions: Two-package ownership (shell owns toggle/New Session, `ui-workspace` owns add/search); "rail settle point"; a single 150ms `translateX(49px)` -> final 10px inset keyframe.
- Data flow: The shell applies the translation to its own two seats and once to the workspace *region*; add/search inherit the path by being inside the translated region, with no nested transforms.
- Non-obvious design decisions: Animation ownership stays in the sidebar shell — animating each workspace button independently would duplicate shell timing inside `ui-workspace` and could stack a region transform with a child transform. The bottom settings control is excluded because it is a foot-pinned action, not part of the upper control sequence, so it gets an opacity-only keyframe with the same duration/easing.
- Edge cases / failure handling: A page that starts collapsed renders the rail with no entry animation (no startup motion); `prefers-reduced-motion` disables both keyframes.
- Surprising: Opacity and geometry are decoupled — the settings seat fades in place while everything else slides. Style tests pin the shared animation assignments, the translation distance, base anchors, and the settings exception.

### .agents/notes/archived/bug-fix/2026-08-12-composer-overlay-seat-width-compensation.md
- Purpose: Stops the chat-column scrollbar gutter reservation from taxing overlay views; the trajectory ledger's full-width dividers stopped 8px short of the pane edge because the scroller reserved a gutter for a bar it never draws.
- Key abstractions: `scrollbar-gutter: auto` on the overlay branch; a `--dsh-scrollbar-width` CSS variable defined in `ui-theme/scrollbar.css` beside the `::-webkit-scrollbar` rule it mirrors; the overlay composer seat compensated with `right: var(--dsh-scrollbar-width)`.
- Data flow: Chat reserves the gutter (engine-resolved width); the overlay seat (absolutely positioned against the padding box) gives the same width back so the input card holds one horizontal position across the Chat and Trajectory tabs.

The premise changed (the overlay branch now reserves nothing), so the same design was re-adopted with the 8px mirrored into a variable in the same diff — and a scrollbar-styles spec pairs variable, mirrored rule, and consumer so a one-sided change fails the gate.
- Edge cases / failure handling: Accepted residual cost stated openly: Chat reserves the engine-resolved width while the compensation stays a fixed 8px, so on the Firefox path (`scrollbar-width: thin` resolving per platform) the card drifts by half the difference on tab switch. The e2e runs only on Chromium; no measurement of the Firefox thin width exists.

### .agents/notes/archived/bug-fix/2026-08-12-fix-pwsh-terminal-overlay-dup.md
- Purpose: Fixes a boot-time crash in the web E2E seed lane: `TypeError: duplicate loader entry id: tool-pwsh` from `vendor/loader/src/config/group.ts:64`, which made every `check:ci:snapshot` / `test:web` run red regardless of the change under test.
- Key abstractions: The cordis-style *loader composition* — `insert` blocks add rows, while a top-level id-targeted override replaces a composed row; a base bundle row with `disabled: !!js process.platform !== 'win32'`.
- Data flow: `apps/web/tests/pwsh-terminal.e2e.ts` applies an `extraOverlayPath` after the shipped web composition; the overlay's `insert` of `tool-pwsh` collided with the id that commit `86b6979bdc` had already moved into `packages/bundle/base/cordis.patch.yml`.

The Windows seam (base `pwsh-sandbox` beside the inserted `pwsh-local`) is not exercised by any CI lane — `test:web` runs only on Linux — so that path is composable but unproven.

### .agents/notes/archived/bug-fix/2026-08-12-full-session-turn-step-counts.md
- Purpose: Makes the web chat stats strip report whole-session figures (turns, steps, LLM/tool wall times, TTFT, throughput) instead of figures folded over the currently loaded conversation window, which grew on every "load earlier" page.
- Key abstractions: A new function plugin `@deepseek-ai/dsh-session-stats` registering a `sessionStats` projection unit on `ctx.sessionProjections`; the value shape `{ turns, steps, llmMs, toolMs, ttftMs, ttftSteps, decodeMs, decodeTokens }` deliberately mirroring the old window fold so the two swap wholesale.
- Data flow: The projection is fed by the existing projection seam — history tail-page block, `session/projection` push frames, list rows — with zero changes to apiproxy, wire schemas, or the client runtime. `StatsLine` reads `useProjection('sessionStats')` and falls back to the window fold when the key is undefined (an assembly without the unit). `steps` counts `step/end`; `turns` counts distinct turns with at least one (turn numbers are monotonic, so one `lastTurn` slot suffices); `llmMs` sums `step/start` -> `assistant/message`; TTFT records the first non-empty delta chunk per step; `toolMs` pairs `tool/call` -> `tool/result` by callId with unresolved calls dropped at `turn/end`.
- Non-obvious design decisions: `step/end` is counted, not `assistant/message`, for two reasons: a max-tokens step appends an empty-content message that exists only to host usage (overcounting a step the transcript does not show), and a cancelled step aborts before its message assembles (undercounting common cancelled steps). `step/end` is appended exactly once in the loop's `finally`, so completed/failed/cancelled/max-tokens steps all land one and the counter advances at step settlement — the same moment the window fold advanced, so live behavior does not shift. The `isTokenDelta` predicate moved to `@deepseek-ai/dsh-llm/message` (beside the `StreamChunk` type it discriminates) so host fold and client timing index share one implementation. Registering the unit in `core/agent-loop` was refused: "plugins, not loop changes".
- Edge cases / failure handling: A step that failed before content still counts; a step interrupted by a crash counts once recovery closes it with a synthetic `step/end` on reload (`interruptedTurnClosers`); a cancelled step is counted but contributes no wall time; a max-tokens usage-host message contributes model time the surface does not show. TUI and headless assemblies serve no `sessionStats` key, so any consumer falls back to window folding.
- Surprising: The unit's internal state changes on step boundaries and first-token chunks, so the change feed emits several *value-identical* frames per step. Two e2e probes that had parsed the strip as a loaded-window measure (`chat-scroll-contract`, `complex-history.perf`) now count mounted flow rows instead.

### .agents/notes/archived/bug-fix/2026-08-12-onboarding-reads-every-provider.md
- Purpose: Stops the first-run credential prompt and the Models page setup card from demanding a DeepSeek key from users who had configured some other provider, and makes the setup card's Cancel button work.
- Key abstractions: One predicate `providerUsable(row)` = the route is registered with the adapter registry (`entry.active`) AND the credential its resolved profile names is stored; `onboardingReadiness` (renamed from `deepSeekReadiness`, which no longer described what it read); `needsSetup(row, anyUsable)`.
- Data flow: The first-run step and the Models page both read a join describing every provider. `providerUsable` is true when a profile names no reference (it authenticates through the provider's own path) or when a live route has no settings address. `onboardingReadiness` returns `provider-ready` as soon as *any* joined row is usable; only a user with none reaches the DeepSeek lookup.
- Non-obvious design decisions: Registration, not configurability, is what makes a provider usable — requiring `row.configured` would exclude exactly the routes a deployment mounts through `cordis.yml` without a configurable-provider declaration. The narrowing subsumes two old diagnostics (`settings-unavailable`, `credential-ref-unavailable`) because both described an active route the new gate calls usable. Dismissal is *viewing state*: a component-local `dismissedSetup` set, not a persisted setting, because the credential itself already ends the posture permanently and every other card on the page is session-local.
- Edge cases / failure handling: Each card kind owns its own close handler — `closeSetup` records the provider in `dismissedSetup` and touches nothing else, because the previously shared handler unconditionally cleared all three states (row-editor/add/declare), so cancelling the card that owned none of them discarded the add card's draft while staying open itself. Both close paths route the post-save reload through one `announceSaved` helper.
- Surprising: A user with a working model already selected in the composer was taken over by a full-screen credential prompt on every blank session, with no escape except storing a DeepSeek key. Deriving readiness from `session/modelCatalog` was refused because it costs a per-provider listing round trip and a transient listing failure would re-open onboarding.

### .agents/notes/archived/bug-fix/2026-08-12-resolve-store-pwsh-aliases.md
- Purpose: Makes Microsoft Store installs of PowerShell 7 resolve ahead of the Windows PowerShell 5.1 fallback — `resolvePwshPath`'s `existsSync` probe followed reparse points, and the Store's `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe` app-execution-alias target directory ACL refuses stat (EACCES), so the probe missed it.
- Key abstractions: `candidateExists` — accepts a candidate that stats as a file OR that `lstat` sees as a link-shaped reparse point.
- Data flow: `resolvePwshPath` -> `candidateExists` -> PATH candidates in order -> Windows PowerShell 5.1 fallback. Spawning the alias path works because CreateProcess resolves app execution aliases.
- Non-obvious design decisions: A *dangling* link-shaped candidate is accepted deliberately, so a broken pwsh fails loudly at spawn instead of silently downgrading to 5.1 — "the 5.1 fallback for stat failures" was rejected because it silently runs a different shell than the one installed.
- Edge cases / failure handling: Real-file candidates and all non-Windows behavior are unchanged; the dangling-symlink unit test pins the stat/lstat split on every platform. Probing the WindowsApps package directory directly was rejected because that path is versioned and ACL-hidden, duplicating packaging knowledge that PATH plus the alias already owns.
- Surprising: The same "does this path exist" question has three different correct answers depending on whether you want to *read* it, *spawn* it, or *delete* it — this shard contains all three variants (stat vs lstat here, `unlink` vs `rmSync` in the two unlink notes).

### .agents/notes/archived/bug-fix/2026-08-12-unlink-fixture-junctions-before-delete.md
- Purpose: Stops fixture teardown from deleting the repository's own tracked sources — Git's `worktree remove` followed a Windows directory junction (MOUNT_POINT reparse point) into the repository's real `scripts/`, `node_modules` and tsx package directories.
- Key abstractions: `scripts/test-fixture-cleanup.ts` owning junction-safe teardown: `unlinkFixtureLinks` (walk + unlink every reparse point) then `removeFixtureSafely` (remove the now link-free tree, with Windows async-handle retries).

### .agents/notes/archived/bug-fix/2026-08-12-unlink-stale-profile-fallback-links.md
- Purpose: Fixes a Windows boot crash — `healProfilesModuleFallback` re-points `$DSH_HOME/profiles/node_modules` entries after an installation moves, and `ensureSymlink` removed a stale junction with `rmSync(link)`, which Node treats as a directory and refuses without `recursive` (`ERR_FS_EISDIR`).
- Key abstractions: `ensureSymlink`; `unlinkSync` as the repository's existing junction-cleanup idiom; the two-anchor fallback resolution owned by a separate architecture note (this note owns only the removal primitive).
- Data flow: `healProfilesModuleFallback` detects a stale entry -> `ensureSymlink` unlinks it -> re-creates the link. Every launch from a moved installation or a second worktree went through this path.
- Non-obvious design decisions: `unlink` deletes the reparse point or symlink itself on every platform and never descends into the target, which preserves the function's fail-loud guarantee that a real directory is never deleted. `rmSync(link, { recursive: true })` was rejected even though it works on Node 24, because `recursive` would silently delete a real directory that replaced the link between the `lstat` guard and the removal — weakening the exact contract that motivates the guard.
- Edge cases / failure handling: Two concurrent healers deleting the same stale link still surface the second deletion as `ENOENT` — unchanged from the previous `rmSync` implementation. POSIX behavior is unchanged because `unlinkSync` also unlinks plain symlinks. Delete-and-recreate-unconditionally was rejected: it churns unchanged links on every launch and widens the concurrent-heal race window.
- Surprising: The `replaces a wrong symlink` unit test had been *reproducing the crash on Windows* at the exact removal call — a test that was documenting the bug as expected behaviour.

### .agents/notes/archived/bug-fix/2026-08-13-bounded-cold-blank-verification.md
- Purpose: Makes the web session tree's blank-Session detection and recency ordering bounded and artifact-I/O-free — the cold list used the JSONL artifact mtime for `updatedAt`, so a pickup with no human prompt (which appends `session/end-seed`) promoted a Session above recently used conversations.
- Key abstractions: A `sessionListMetadata` projection registered by `dsh-api-session-controller`, carrying `blank` and `lastPromptAt`; the attached summary folds the same functions over the live log.
- Data flow: `blank` changes only from true to false on `turn/start`; `lastPromptAt` changes only on a `user/message` whose source kind is `user`. `updatedAt` = max(`createdAt`, `lastPromptAt`). A cold summary trusts cached `blank: false` (a checkpoint prefix containing `turn/start` remains non-blank); a cache *miss* is served `blank: false` (visible), because a miss does not prove the log is blank.
- Non-obvious design decisions: Trusting cached `blank: true` was rejected because the projection cache deliberately permits a persisted log to advance beyond its checkpoint — a crash or fail-soft write failure after the first `turn/start` would hide a real conversation and could make the client reuse it as New Session. The earlier physical-size probe (a `locate()` path plus a `coldBlankProbeMaxBytes` eligibility threshold gating an exact `readFrom(id, 0)` fold) was removed with the seam's path query.
- Edge cases / failure handling: Blank cold Sessions with no cached non-blank projection remain visible; missing or delayed recency cache entries fall back to `createdAt`. The error direction is always conservative: the UI may show an extra empty row or order a Session too low, but never hides a conversation or promotes one merely because it was opened. An authoritative persistence index was deferred because the shipped JSONL provider has an immutable first line and would need a second durable artifact with ordered updates.
- Surprising: The projection is gateway-owned, so it is an effect of the gateway fiber — unloading the gateway removes the key. Unit coverage pins stale-true rejection, monotonic false reuse, cache-miss visibility, human-prompt recency, and fiber disposal.

### .agents/notes/archived/bug-fix/2026-08-13-feedback-note-editor-popover.md
- Purpose: Fixes the message-feedback note editor, whose 260px textarea plus Save/Cancel were mounted inline into the assistant message's fixed-height 28px `IconActions` flex row and spilled past the conversation column (168px of overflow at a 1680px viewport, 444px at 600px).
- Key abstractions: The popover pattern — a fixed-position panel portaled to `document.body`, positioned from the trigger's rect, reusing `ui-primitives/useAnchoredPosition` (measure-offset-clamp-and-track) and the portal mechanism `ui-primitives/Menu` uses for anchored menus; `ui-subagent`'s catalog popover is built on the same primitive.
- Data flow: The trigger is a plain button (`aria-haspopup="dialog"`, `aria-expanded` while open) showing "Add a note" before a note exists and the note text afterwards; the panel contains the textarea, Save, Cancel, and any note-save failure as `role="dialog"` with a title distinct from the textarea's own label. It opens 4px beneath the trigger, clamps 12px from the viewport edges, auto-focuses the textarea, and closes on Escape or outside pointer-down.
- Non-obvious design decisions: The editor does not enter the row's flex layout at all — portaling out escapes the column's `overflow` clip, so the panel is not cropped at the scroll edge and it tracks the message as the transcript scrolls. `Menu` keeps its own effect because it also resolves `side`/`align` variants and an optional caller-supplied anchor rect. Focus returns to the trigger *only when the panel was really open*, never on initial mount (a freshly rendered rated message must not pull focus into its action row). Failure surfaces split by where the human is looking: a rating/list-load failure shows beside the buttons; a note-save failure shows inside the popover and the panel stays open so the draft survives.
- Edge cases / failure handling: The note enumerates accepted limitations honestly — a rating click while the panel is open closes it and focus returns to the trigger (keyboard users feel the move); the clamp assumes the panel fits, so a panel taller than the viewport cuts off its head, mitigated by `.notePanel` bounding height at `calc(100vh - 24px)` and scrolling its own content; if the rating disappears while the editor is open, the panel unmounts but `noteOpen` stays true, so the document-level listeners remain attached; a failure landing after close-and-reopen is dropped rather than mislabelling a reseeded draft. Also names four undefined `--dsw-alias-*` tokens that made the whole declaration invalid at computed-value time (no border, no surface, unreadable Save label).
- Surprising: The overflowing controls stayed hit-testable while invisible, so no behavioural assertion noticed — the shipped e2e covered rate/note/reload/retract and the 24 UI snapshots are width-independent DOM. The fix is proven by a six-viewport e2e that pins one line, zero overflow, panel-outside-column, inside-viewport, and by-trigger, plus a style spec that checks the tokens against the theme's committed source.

### .agents/notes/archived/bug-fix/2026-08-13-oauth-only-providers-withheld.md
- Purpose: Removes `openai-codex` from the configurable-provider directory, which had been offered with the keyless placeholder every pi-ai provider carries — configuring it that way failed the turn with `Provider is not configured: openai-codex` (catch-all `PI_AI_ERROR`).
- Key abstractions: `catalogProviderTakesApiKey(provider)` — whether pi-ai's installed provider for a route declares an api-key method; `directoryEntries()` skipping catalog routes that fail it; `catalogProviderIds()` (unchanged) keeping the `declared` flag meaningful.
- Data flow: `PiAiAdapter.current()` constructs its pi-ai collection with `createModels()` and no options, so the `CredentialStore` is pi-ai's default `InMemoryCredentialStore` — empty at every boot and rebuilt from scratch on each configuration snapshot. pi-ai reaches an OAuth provider only through a credential already in that store; `openai-codex` is the one installed provider declaring `auth.oauth` with no `auth.apiKey` beside it, and nothing here runs `Models.login()`.
- Non-obvious design decisions: The withholding is deliberately *narrow*: catalog membership is unchanged (so `declared` keeps meaning "no installed provider answers for this route"), and the profile half of the union is unconditional (a stored `openai-codex` profile stays visible, editable and deletable rather than being stranded in the settings document). Resolution is untouched — a profile naming `apiKeyEnv` on an OAuth-only route still builds a working provider, because `routeAuth` adds the harness api-key method beside the catalog's OAuth.
- Edge cases / failure handling: Enforcing the withholding in `resolveProfiles` was rejected for its *boot* behaviour: `validate` runs at boot as well as at write time, so one stored keyless OAuth route would fail the whole namespace's registration rather than one provider — a release trading a one-provider defect for a total one. The gap is named: the *offer* was fixed, not the capability; a deployment can still hand-write the route the page can no longer add. Reading `~/.codex/auth.json` into a `CredentialStore` was deferred as an OAuth-work decision, not a release fix.
- Surprising: The note records its own retirement — the later "credential records and authorization flows" architecture note gave the adapter a durable credential store and a login flow, so `openai-codex` is offered again and `catalogProviderTakesApiKey` is gone. The two boundaries are what kept that reversal to one predicate and one filter.

### .agents/notes/archived/bug-fix/2026-08-13-safari-textarea-soft-wrap-reflow.md
- Purpose: Repairs Safari 26.5.2 retaining the textarea's former native line layout when Backspace moves a draft across a soft-wrap threshold: the mirror, backdrop, grow stack and textarea box all became 28px, but the textarea still reported `scrollHeight=52`, `scrollTop=20`, leaving the caret in a stale line.
- Key abstractions: The composer's three-layer text model (transparent native textarea owns caret/selection, backdrop paints glyphs, hidden mirror measures height) and the *single-scrollport* decision it depends on (the textarea must own no scrollable overflow: `scrollHeight == clientHeight`, `scrollTop == 0`).
- Data flow: A Safari identity probe (Apple vendor + `Version/... Safari/...` UA form, rejecting `CriOS`/`FxiOS`/`EdgiOS`/`OPiOS`) plus a native-shrink signal (the change handler records whether the edit shortens the controlled draft) gate a layout effect that checks the overflow invariant only when both are present. On mismatch it changes the textarea's real height by one pixel, forces layout, restores the owned height, forces layout again, then repeats the one-pixel invalidation on `[data-input-scroll]` to fix the scrollport's auto height.
- Non-obvious design decisions: The recovery must be *ordered* — textarea-only leaves the scrollport at 52px, scrollport-only leaves the native overflow untouched, so the ordered pair is the smallest complete recovery. Geometry is read only after a *shortening* edit, because reading `scrollHeight`/`clientHeight` after React updates the mirror can synchronously lay out even a healthy growing draft. The value, selection, IME state and undo transaction are never touched (rewriting the value would rebuild the control but destroy IME composition).
- Edge cases / failure handling: A browser shell indistinguishable by identity fields must still violate the textarea overflow invariant before any layout mutation happens, so a look-alike browser cannot trigger four forced layouts for nothing. Reduced-motion is irrelevant here; non-Safari browsers, programmatic draft updates and non-shortening edits perform no geometry read at all.
- Surprising: `color` is not a layout input — changing it inline leaves the stale `52/28/20` state intact, while editing the *stylesheet rule* happens to trigger broader rule invalidation and clears it, which is why Web Inspector makes the declaration look causal. Playwright WebKit 26.5 settles correctly without the workaround, so the Chromium browser lane cannot reproduce the defect; the focused component test pins the engine state instead.

### .agents/notes/archived/bug-fix/2026-08-15-max-token-replay-state-alignment.md
- Purpose: Fixes a permanent session failure — `INVALID_REPLAY_STATE: block count does not match assistant content` — caused by two representations of one response being snapshotted at different pipeline points, with index alignment enforced only by a read-time hard error.
- Key abstractions: The `ReplayEnvelope` — an opaque `response` half plus optional opaque *per-block* entries aligned with the emitted block sequence; pi-ai's version-2 split of its former flat state; `BlockAssembler.blocks()` (which drops tool calls from a `max-tokens` response because a truncated call is unsafe to execute).
- Data flow: Write side — the finish chunk's `replayState` becomes a typed `ReplayEnvelope`; `BlockAssembler` computes its keep/drop decision **once** and applies it to blocks and envelope entries together, so any transformation prunes the matching metadata by construction; retained blocks keep their entries (a truncated response keeps signatures for the reasoning and text it kept); an envelope whose entry count does not match the emitted block count is discarded whole. Read side — `toPiAssistant` treats replay state as fidelity metadata, not a load-bearing input: another adapter's kind, another version (including the flat version-1 form already on disk), malformed metadata, or a mismatched block shape degrades that one message to the foreign provider-neutral conversion and reports the diagnostic through the plugin's `onReplayDegrade` hook.
- Non-obvious design decisions: The request must *proceed* after a degrade — that is what lets sessions poisoned before the change continue instead of erroring forever, and it bounds every future divergence source to a fidelity loss on one message. Relaxing pi-ai's block-count validation to "attach what fits" was rejected because index-aligned signatures attached to a different block list would present false native history to the provider; degrading attaches nothing. Teaching each adapter to rewrite its own state was rejected as an adapter obligation with an opaque blob.
- Edge cases / failure handling: Legacy flat version-1 state on disk takes the same degrade path. On-disk `replayState` values changed shape under the pre-release no-compatibility stance. Validation itself is unchanged and still precedes any native reconstruction. This supersedes the read-time hard-error rule in the provider-routed-adapter architecture decision *for unusable state*.

### .agents/notes/archived/bug-fix/2026-08-11-synchronous-subprocess-exit-cleanup.zh.md
- Purpose: (Chinese-language note; the only file in this shard without its English sibling in the same shard.) It records the decision to synchronously clean up managed child processes when the *host* exits, because a fatal launcher may call `process.exit()` before the async Cordis dispose completes — the fail-loud release waits at most two seconds while local processes may have a longer termination grace — and once Node enters its synchronous exit phase, pending Promises and upgraded timers do not continue, so children ignoring TERM can outlive the host and keep consuming CPU, memory or ports.
- Key abstractions: `LocalSubprocessRuntime`'s synchronous Node `exit` listener installed in its own Cordis effect; the service's existing live-handle set; the public `SubprocessHandle` / `SubprocessTerminalHandle` interfaces (which deliberately do *not* expose the final operations).
- Data flow: The listener is removed only after the normal dispose has settled. While async cleanup is still waiting, ordinary and terminal handles stay in the service's live set, so a shorter outer exit ceiling still sees and force-kills them; when a waiting dispose reports cleanup failure, the service runs the same synchronous final operations before clearing the set and removing the listener. Ordinary handles immediately SIGKILL the detached POSIX process group, or run `taskkill /PID <pid> /T /F` synchronously on Windows. Terminal handles synchronously SIGKILL every captured and currently observable descendant, terminate the PTY root, then scan once more and kill members that became observable during that boundary. The callback creates no Promise or timer, writes no diagnostics, and does not change the original exit code or error.
- Non-obvious design decisions: The public subprocess seam's promise to wait for a complete stop during normal dispose is *not* weakened — the defect belongs to a separate final host-exit path below the seam, and the launcher must not repeat process ownership. Calling the existing async `terminate()` from the `exit` listener was rejected because Node does not wait for exit listeners, so Promises, timers, output draining and quiescence polling could not complete. Adding a raw `forceKill()` to the public handle was rejected because consumers need only one cooperative termination convention — immediate final termination is an implementation duty used only by the local service's host-exit owner. Relying only on launcher release callbacks was rejected because not every entry point provides one and a bounded release can still end before the provider's grace period and timers complete. Handing every failure mode to an external supervisor was rejected as the *only* answer, because Node provides reliable synchronous callbacks for several common fatal paths and the provider already knows the exact targets.
- Edge cases / failure handling: The note tabulates the three host paths — normal Cordis dispose (cooperative termination, bounded escalation, wait for full quiescence before dispose settles), `process.exit()` / default uncaught exception / default unhandled rejection (synchronous final signals to the service's live set), and the paths in-process operations cannot run at all (`SIGTERM`/`SIGINT`/`SIGHUP` with no handler installed, `SIGKILL`, fatal OOM, `process.abort()`, a native crash, power loss) which must be owned by an external supervisor, container or OS. The remote provider keeps owning its own sandbox and does not inherit the local Node listener. The listener cannot cover failures that do not execute JavaScript, and cannot find terminal descendants that escaped before the provider's first observation — that ownership gap is tracked by Issue #1726.
- Surprising: The synchronous path deliberately does *not* publish completion results or claim that the OS process tree is gone when the callback returns — a fatal exit trades grace, output draining and in-process quiescence proof for the strongest available termination action before the host disappears.

## Ideas worth stealing

- **Put environment facts *after* the reusable instructions, so the cacheable prefix is byte-identical across users** - `.agents/notes/archived/bug-fix/2026-09-06-environment-prompt-suffix.md:14` - The system-prompt registry is ordered `identity (0) -> reusable instructions -> HARNESS_SOURCE (10000) -> WEB_SURFACE (10100) -> DEPLOYMENT_PERSONA_SUFFIX (10200)`, and only `Your working directory is {{cwd}}.` is demoted to the suffix. August's prompt builder is one flat string today, so the *mechanism* transfers directly: give every environment-specific fact its own section key, sort sections by an explicit numeric order, and the per-install part of the prompt stops poisoning the provider's prefix cache. The note is honest that hit rate is not measured — the win is structural, not proven.

- **Emit reasoning content on every reasoned turn, not only on tool-call turns** - `.agents/notes/archived/bug-fix/2026-08-19-deepseek-reasoning-passback-every-turn.md:16` - A gateway that re-encodes a DeepSeek conversation for another vendor has no slot for the upstream thinking signature and recovers it by *hashing the replayed chain of thought*; a plain-answer turn that withholds reasoning reaches the gateway with no chain at all, so the reconstructed conversation diverges from the recorded one and the failure looks intermittent (it only shows on turns the model did not call a tool). August's `llm-deepseek` adapter has the same shape, and August runs on cheap local models behind gateways — the rule "a reasoned turn replays its reasoning, always" is a two-line change with a large blast radius avoided.

- **Make pricing and payload come from ONE solver, and let the provider own the projection** - `.agents/notes/archived/bug-fix/2026-09-10-deepseek-v41-request-image-projection.md:16` - `llm-deepseek` keeps the provider's published token-grid solver and derives the request image's *target dimensions* from it; the attachment store only resizes and encodes to the target it is handed, and pricing prices the same target. The note also records the rejected alternative in detail: a `token-grid` projection kind inside the provider-neutral `dsh-attachment` package was *built first* and then thrown away, because it put one provider's layout formula and patch constants into a generic-looking name and needed an `unscaled` flag to distinguish "send the source" from "send the solved size". August's `dump_openai_upstream_body` / `dump_anthropic_upstream_body` and per-model pricing have exactly this shape of risk — the transferable rule is "the provider package computes the target; the store moves bytes".

- **Derive a context budget from the *live* model, and spill what the budget dropped** - `.agents/notes/archived/bug-fix/2026-09-05-session-reference-model-budget.md:16` and `.agents/notes/archived/bug-fix/2026-09-05-session-reference-spill-reuse.md:18` - The budget is `max(65536, floor(contextWindow x 4 x fraction))` with a 64 KiB floor, and the model route is learned by observing the *completed* `system-prompt/assemble` waterfall into a WeakMap keyed by Agent (line 14) — not by re-reading the session header, which can be stale after a live model switch. The spill side then saves the *same captured projection* the preview was derived from, so the artifact and the preview can never disagree, and records the omission in a notice that lives **outside** the bounded preview JSON so a tiny budget cannot hide it. August's compaction/relief ladder is currently one fixed budget; the pair of notes is a complete recipe for making it model-relative without letting a small budget hide the fact that content was dropped.

- **Cap in-flight work per macrotask, after the microtask queue drains — and re-check at the settlement door** - `.agents/notes/archived/bug-fix/2026-08-29-code-runtime-python-call-backlog-and-binding-metadata-snapshot.md:16` - The child flooded calls against a binding whose promise never settled; the cap counted only *resolved* calls, so one async closure accumulated per frame until the wall clock. The fix counts outstanding calls, releases the slot in the `finally`, and checks **once per macrotask** (after microtasks drain) rather than per frame or per event, because a per-frame check kills a legitimate 1025-call `asyncio.gather` and a per-event snapshot is stale when several `data` events fire in one macrotask. The `done` handler independently re-checks the count before accepting the frame, closing the same-batch window. August's `MAX_MANAGED_TOOL_ROUNDS` and the Bot-to-Bot ceiling are per-turn counters; this is the same discipline for *in-flight* work, and the "check after the microtask queue drains" rule is the part that is easy to get wrong.

- **Bound a parse by the host heap, not just by a byte cap** - `.agents/notes/archived/bug-fix/2026-08-29-code-runtime-python-call-backlog-and-binding-metadata-snapshot.md:32` - `JSON.parse` of a wide-object frame materializes several times the raw bytes in V8's property storage (measured 6.4x for a 3,000,000-key frame; a 256 MiB host OOMs outright), so the effective frame cap is `min(protocol cap, floor((heap_size_limit - baseline) / 16))` derived from `v8.getHeapStatistics().heap_size_limit`, and the load gate *rejects* a budget whose frame could not be parsed safely. August's `/v1` proxy and MCP surfaces accept caller-supplied bodies; a "bytes on the wire" ceiling is not a "bytes in the parser" ceiling, and this is the arithmetic that closes the gap.

- **Split a fallible fold into plan/commit so retry identity is preserved by ordering, not by copying** - `.agents/notes/archived/bug-fix/2026-08-24-token-meter-surface-fold-plan-commit.md:14` - The copy existed for exactly one property (a throw must leave the caller's `ReplayState` untouched so a malformed event fails identically on every retry) and cost ~99.9% of an append, giving an O(S^2) term on the streaming path. The plan/commit split keeps the property by *ordering* — plan (all fallible work) -> validate -> commit in place (infallible by construction). August's `turn_outcomes` / `replay` handling and the token-meter fold have the same coupling; the generalisable trick is that "atomicity" can be a sequencing property rather than an allocation.

- **Record an unknown tool outcome instead of leaving a tool call unanswered** - `.agents/notes/archived/bug-fix/2026-09-19-failed-step-tool-results.md:14` - A committed assistant message can request tools whose scheduler fails before all results are recorded; closing the step with those calls unanswered makes every later provider request invalid, and because the error turn is already closed, crash-tail repair cannot recover it. The driver therefore records `TOOL_OUTCOME_UNKNOWN` (with text warning against blindly retrying an operation that may have side effects) or `TOOL_NOT_STARTED` *before* closing the step — the only window in which a failed turn can still be made valid. August's tool-boundary guard and its `_stuckRequestEscape` ladder both assume paired call/result histories; this is the upstream half of that assumption.

- **Give a child agent exactly one delivery mode, so ordering cannot vary by deployment** - `.agents/notes/archived/bug-fix/2026-08-17-subagent-message-settlement-ordering.md:16` - Every model-authored child message uses fixed Steer delivery; there is no quiet and no next-turn *model* option, because a later settlement notice entering a different queue could reach the parent before the earlier child message. The wake generation is renewed *before* the send returns, so a receiving activation cannot settle over an accepted waking send. August's subagents and Bot DMs have the same two-queue reality (`next-step` vs `next-turn`); the transferable rule is "the model does not choose a delivery mode, so ordering is a property of the system, not of the caller".

- **Make a stale config *repairable*: tolerate catalog diagnostics at registration, be strict on writes** - `.agents/notes/archived/bug-fix/2026-09-07-pi-ai-settings-catalog-recovery.md:14` - An installed provider catalog can invalidate unchanged user settings; rejecting the whole namespace at registration makes unrelated providers disappear and *removes the controls needed to fix the configuration*. The fix splits the two moments (registration tolerates catalog diagnostics, writes strictly validate only changed providers), keeps per-model diagnostics next to the model, and reports `INVALID_CONFIG` before credentials or network I/O. August has the same shape in its brain-config + provider tables and its `check:brain-config` gate; "a broken config must stay *editable*" is the idea to steal.

- **Degrade the cache conservatively: a cache miss must never hide a conversation** - `.agents/notes/archived/bug-fix/2026-08-13-bounded-cold-blank-verification.md:18` - A cached `blank: true` is rejected (the cache deliberately permits the log to advance past its checkpoint), and a cache *miss* is served as non-blank so the row stays visible. Every failure direction is chosen so the UI may show one extra empty row but can never hide a real conversation or promote one merely because it was opened. August's `turn_outcomes` ledger and its brain projection caches need the same one-way conservatism.

- **Stale-while-revalidate, with the pending window made an explicit no-op** - `.agents/notes/archived/bug-fix/2026-08-28-trigger-menu-stale-while-revalidate.md:16` - The menu keeps the previous rows and marks the groups pending instead of collapsing to a skeleton on every keystroke; `pick()` requires the group to be `ready`, and Enter during the pending window is an explicit `'consumed'` no-op — it neither picks the stale row nor falls through to send the draft. The note's reason is the transferable part: with retained rows the user is looking at a highlighted candidate, so a few hundred ms of dead key is safer than sending the whole draft under it. August's file/reference picker and its composer `@`-mention path are the same shape.

- **Let the *target element* be the completion signal of a scroll/reveal, not the caller** - `.agents/notes/archived/bug-fix/2026-09-03-session-search-result-reveal.md:16` - A matching mounted row scrolls itself into view and acknowledges the target id, which prevents later renders from repeating the scroll; the parent cannot complete the operation before a folded target row mounts, so it must not try. August's session list and transcript surfaces have the same "the element that owns the DOM does the work" requirement, and the note shows how a one-shot reveal is cancelled and re-armed without a second state machine.

- **Normalise a model-facing error at the model boundary, and keep the machine code intact** - `.agents/notes/archived/bug-fix/2026-09-03-normalized-unread-fs-tool-diagnostic.md:14` - `remediateFsError` replaces every `FS_NOT_OBSERVED` message with one actionable string while preserving the structured code and chaining the source as `cause`; the machine-readable code and the model-readable text are deliberately decoupled, and the provider/policy keep their own wording because other consumers do not share the tool's presentation. August's `FS_NOT_OBSERVED`-style tool errors reach the model with source-specific wording today; this is the exact seam to normalise at.

- **Declare a durable state the *model* may not undo** - `.agents/notes/archived/bug-fix/2026-09-03-user-owned-goal-pause-activation.md:18` - `update_goal resume` refuses a durable paused goal with `GOAL_TOOL_RESUME_PAUSED` before it reaches the goal service, while still resuming an active-but-disarmed goal; activation is kept process-local (never in the durable snapshot or a checkpointed projection) and exposed through a dedicated `goal/activation-changed` event. August's `update_state(phase=…)` is explicitly only progress tracking — the transferable lesson is that a *user* control and a *model* control over the same object need two doors, with the model door closed at the tool.

- **Cherry-pick a community fix verbatim and keep the author** - `.agents/notes/archived/bug-fix/2026-08-23-win32-utf16-nul-truncation.md:16` - The UTF-16 terminator fix was adopted byte-identical from a community branch, with both upstream commit hashes recorded in the note and the original author named, because "a byte-identical cherry-pick preserves provenance and credit" — and rejecting a community patch to rewrite it locally was explicitly refused. Small, unglamorous, and worth copying: August's Windows host layer has the same class of bug.

- **Write the *measurement design* into the note, and publish a benchmark without a CI wall-clock gate** - `.agents/notes/archived/bug-fix/2026-09-11-incremental-terminal-retention.md:24` and `.agents/notes/archived/bug-fix/2026-08-28-linear-stream-queue-drain.md:39` - The terminal note documents the benchmark's inputs, what is excluded (shell startup, PTY transport, model latency, browser rendering), and the exact reference expectations it scales; the deque note ships a reproducible benchmark script but states that "CI does not enforce a wall-clock threshold — deterministic unit coverage owns the algorithm and compaction paths". The August repo has no test suite at all, which makes this pair the most directly usable: publish the measurement recipe and the deterministic assertions, and do not pretend a flaky timing budget is a gate.

- **Test the *absence* of a read, not the shape of an output** - `.agents/notes/archived/bug-fix/2026-09-19-declared-session-attachment-carriers.md:14` - Attachment readers select content by built-in event type and keep every other field opaque; the refusal tests assert that attachment storage is *never read*, and the archive test additionally compares the exported log text to prove the complete logical log survives. The note's rule — "a plugin needs a supported content occurrence or its own reader" — is a clean ownership boundary for any capability that authorises bytes.
