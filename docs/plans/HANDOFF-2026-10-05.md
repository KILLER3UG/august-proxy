## 7. Traps that already cost time here

- **A completion notice said `exit code 0` over a run whose log said 1.** Twice.
- **Modules without a logger**: `workbench/providers.py` and
  `harness_self_improve.py` have no module-level `logger`; the latter uses
  `logging.getLogger(__name__)` at call sites. Adding one that does not exist
  type-checks fine and fails at runtime — ruff caught it, twice.
- **Source-grep tests match their own docstrings.** A guard that asserted
  "reviewer never touches `_APPROVERS`" failed because the docstring *mentions*
  it. Use `ast` and assert on what the function calls.
- **`resolve()` fabricates a provider** when nothing matches (by design, so a
  bare model name can carry its own provider). Do not treat its return as proof
  a provider exists.
- **`list_available()` filters by enabled+apiKey** and returns `[]` when no keys
  are configured. It cannot distinguish "configured" from "absent".
- **`assertPytestDataDirIsolated` used to only warn** — that is how
  `judge-model-x` sat in the user's real config for a month. Any new guard that
  protects user data must be proven to fire, and proven to stay inert in normal
  runs.
