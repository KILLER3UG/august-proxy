# deepseek-harness / dsh-notes-impl-arch#3

## Shard shape

This shard is 11 files and nothing else: three *implemented* architecture Agent Notes in `.agents/notes/implemented/architecture/`, each shipped as a **triplet** — the English note, its Simplified-Chinese translation (`*.zh.md`), and a machine-checkable consistency record (`*.i18n.yaml`) holding one content hash per heading section for each side. The three notes are (a) *Continuous CUA hover without cross-call ownership* and *Background hover and screenshot coordinates*, which record the computer-use tool's hover routing (AX alternate-UI first, system pointer as fallback) and its model-facing coordinate contract (screenshot pixels by default, integer thousandths on request, Host-owned mapping); (b) *Team identity in required runtime context*, which moves a teammate's role out of its initial task and into a `required` dynamic context contribution, and (c) *Boot the Preview Worker from the shipped profile and fetch lazy chunks on demand*, a long note about making a browser-hosted preview boot the **same** profile composition the served web deployment boots, plus Node internal-module shims, typed platform degradation, and per-chunk lazy archives. The notes are the durable decision record for code that lives elsewhere in the repo — `packages/experimental/cua*` (TypeScript + a Swift native layer), `packages/experimental/tool-agent-team` + `packages/core/agent-loop`/`packages/core/system-prompt`, and `packages/experimental/webworker-{packer,runtime}` + `packages/boot/app-boot` — so reading this shard alone gives the *why*, and the *what* has to be chased into `packages/`. The house style is rigid and load-bearing: a fixed four-section shape (Problem / Decision / Alternatives considered / Consequences), an explicit "this supersedes exactly this much of that older note" line, measured numbers instead of adjectives, and a Consequences section that lists the *costs* as prominently as the benefits.

## Per-file notes

### .agents/notes/implemented/architecture/2026-10-13-cua-continuous-hover.md
- Purpose: Records the decision that a computer-use `hover` must be a standalone *unpressed movement* operation that does not disturb the user's pointer or dismiss a revealed popup, and that the CUA layer must not reserve an application across calls.
- Key abstractions: `App.hover` / `Window.hover` over an observed AX element index **or** an explicit coordinate target; the "shared helper" that serializes *complete individual operations*; "cross-call ownership" as the named anti-pattern.
- Data flow: model issues `hover` → native route decides between an AX alternate-UI reveal and a system-pointer move → result records the route and whether the pointer moved → the model observes AX/screenshot state to confirm the popup appeared → the model issues a second `hover` for an intermediate point inside the popup, then a click.
- Non-obvious design decisions: Completion, AX reads and screenshots deliberately **do not restore** the previous pointer position (restoring it is what dismisses a popup); a click never sends an off-window priming click; earlier arrival, a retained app object and Session lifetime explicitly do **not** establish task priority, and waiting for the model does not reserve the application — ordering is the caller's job via explicit task coordination (stated at :15).
- Edge cases / failure handling: Other input or application-driven changes can race the hover check; dispatch success does **not** mean the hover delay elapsed or a popup appeared, so the caller must re-observe; PID-directed virtual movement is rejected as unreliable (a fresh window ignores it, later pointer checks dismiss the content), so the unreliable route is not reported as continuous hover.
- Surprising: The note insists that a *recorded session* covers hover dispatch and observed popup content but explicitly "does not substitute for native event verification" (:27) — a replay is not proof of the event layer.

### .agents/notes/implemented/architecture/2026-10-13-cua-hover-routes-and-coordinates.md
- Purpose: The decision note for *how* hover is routed and *what coordinate space* the model is allowed to speak in.
- Key abstractions: the AX alternate-UI route (an element **or ancestor** advertising both `AXShowAlternateUI` and `AXShowDefaultUI`), the system-pointer fallback (foreground-app check + AppKit mouse hit test, which excludes input-transparent overlays), `relative: true` coordinate mode, and `LlmAdapter.imageRequestTarget` as the single place the provider's image geometry is published.
- Data flow: observation → `CuaCoordinates.observe()` records per-window geometry → `screenshot()` binds the exact model-request image size to the window → the model sends pixels (or thousandths) → `CuaCoordinates.parameters()` converts once, before native dispatch, into native window points → the native layer moves the pointer.
- Non-obvious design decisions: Model-facing coordinates default to **pixels in the returned screenshot**, and the provider — not the Host — owns the projection formula, because "making the model convert them duplicates provider geometry rules" (:9); `relative: true` is an *explicit* opt-in so the unit of a coordinate is never guessed from its value (:23); a window **resize invalidates** the old image while a **move preserves** local coordinates; a scoped observation preserves other windows' image mappings, an application-wide one refreshes the inventory; the native PNG metadata is checked against the decoded source dimensions before any input mapping is published.
- Edge cases / failure handling: An unavailable AX route falls back to the real system pointer; an **AX action failure propagates** rather than trying another input route, because "received effects may be uncertain" (:13); browser-engine/Electron page input can hover without moving the pointer but needs a separately established connection that a generic native app handle does not provide.
- Surprising: The result of a hover records *which route ran* and *whether the system pointer moved* — the model can therefore tell the difference between "I hovered in the app" and "I moved the user's mouse".

### .agents/notes/implemented/architecture/2026-10-13-team-identity-runtime-context.md
- Purpose: The decision that a teammate's identity (role, name, addressing instructions) belongs in a **required** dynamic runtime-context contribution rather than in the initial task text or the system prompt.
- Key abstractions: `tool-agent-team` registering `team:identity` through the Agent-scoped `systemPrompt.context()` registry with `required: true`; the fixed collaboration policy staying in a system-prompt *section*; the loop's retained-snapshot comparison and re-admission after compaction.
- Data flow: Team membership changes → the `team:identity` provider re-renders from **current** membership → the loop projects the joined runtime-context snapshot → if the text differs from the retained snapshot, the whole snapshot is appended as a user message *after* the inherited history; if it is unchanged, **no message is added**.
- Non-obvious design decisions: Identity is deliberately *not* in the system prompt, because per-member system text would break the shared request prefix on routes that cannot update the system message in history (:23); it is deliberately *not* in the initial task, because compaction can remove it and a fork from a teammate would inherit the old role (:21); the note supersedes **only** the initial-task identity decision of the earlier Agent Teams note and leaves its roster/mailbox/task decisions in force (:17) — a partial, named supersession rather than a blanket one.
- Edge cases / failure handling: Optional-context suppression cannot remove a required contribution; no Team-specific retention state, event type or log migration is introduced — the loop's existing runtime-context projection is reused; existing recorded identity reminders stay historical messages.
- Surprising: "Members pay for identity within the full runtime-context snapshot" (:29) — the mechanism re-sends the *entire* snapshot, not a diff, and the note says so plainly as a cost; and "actual provider cache hits remain best-effort" is stated rather than promised.

### .agents/notes/implemented/architecture/2026-10-14-webworker-preview-profile-parity.md
- Purpose: The long decision note for making the browser-hosted Preview boot the **same** profile composition the served web deployment boots, and for splitting lazily loaded chunks into per-chunk archives fetched on demand.
- Key abstractions: `PROFILE_TEMPLATES` + `OPTIONAL_BUNDLES` (the two tables the Plugins page already reads) as the single source of the image roster; a manifest-only installation anchor; a `home/cordis.patch.yml` carrying the platform's overrides; `ModuleLoader.fromInternal()` and `node-addon-require-builtin.requireBuiltin(id)` as the Node internal-module surfaces the Worker must provide; `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM`; `MemoryVfs.deferArchive` / `ERR_DSH_VFS_DEFERRED`.
- Data flow: packer → roster from app-boot's two tables → materialize packages + bundle patches → sweep page assets for `require.async("./client.<name>.js")` literals → emit one deterministic `lazy/<sha256>.tar.gz` per chunk and record `{archive, files:[{path,size}]}` in the manifest → Worker registers each file with `deferArchive` → the first asynchronous read of any file in an archive fetches, inflates, validates paths+sizes, materializes the files, and every concurrent reader shares that one fetch.
- Non-obvious design decisions: The old pack-time composition (`dsh --profile web --dump-config` written into the image) was **removed** because it made the preview a different system from production: the image collected only rows the dump happened to contain (so none of the 11 default-off optional bundles appeared), and bundle layers applied *before* the profile patch, so base rows did not exist yet and patches were skipped with `entry not found` warnings (:13-14). The fix is to reproduce the production launch path, and to confine the platform's differences to a single enumerated home patch row (`compression: none` for `session-persistence-jsonl`) (:34). The measured parity statement is precise: with no bundle enabled the two compositions differ in **one of 188 rows** (:17). The Node shim is *interfaces only* — five module ids, Node's member names and signatures, every other id refused with Node's own platform code — rather than porting Node's CJS loader, because porting it would need Node's condition set, cjs-module-lexer, and ~300 KB more, "while callers need only the internal-module interfaces" (:76).
- Edge cases / failure handling: The Inspector degrades **only** when its Worker fails with `ERR_FEATURE_UNAVAILABLE_ON_PLATFORM`; any other startup failure fails the fiber (:50). Before an archive arrives, synchronous reads *and* all writes/appends/truncate/chmod/rename/link are refused with `ERR_DSH_VFS_DEFERRED` naming the archive, and a directory rename that would move a registered file is refused *before* the destination changes (:58). A failed fetch fails only the waiting reads; the files stay registered and the next asynchronous read fetches again (:57). The archive name's digest is **not** verified — only registered paths and sizes are (:57, :96). A request for a chunk the package does not publish **fails the pack** (:54).
- Surprising: The Consequences section is a list of *known* defects the mechanism accepts: HMR replaces no modules and still reports `applied`; `require('stream')` returns the module namespace instead of the `Stream` constructor; reporting `process.versions.node` as `24.18.0` can change third-party behaviour; browser-incapable bundle capabilities (sqlite, terminals, local speech) "fail when used" rather than at enable time; and an image packed with a composed configuration **must be repacked** because the layout no longer carries `config/cordis.yml` (:88-96). Sizes are measured, not asserted: base image 9.20 MiB vs 12.79 MiB before (−28%), plus 5 lazy archives totalling 4.45 MiB (:86).

## Ideas worth stealing

- **Put a subagent/team-member's identity in a `required` dynamic context contribution, not in the initial task and not in the system prompt** — `.agents/notes/implemented/architecture/2026-10-13-team-identity-runtime-context.md:13` (impl `packages/experimental/tool-agent-team/src/index.ts:178-190`; the required-context rule is enforced at `packages/core/system-prompt/src/index.ts:591`, and a *missing* required registration is restored in registry order at `:594-600`). The identity provider re-renders from **current** membership on every read, so a compaction that deleted the identity, or a fork that inherited a stale role, both self-heal; the system prompt stays byte-identical across members because the per-member text lives in the runtime-context snapshot, not in the prefix. For August this is directly transferable: a delegated worker whose "you are reviewer, address the lead" line is currently embedded in the initial task is exactly the failure this removes.

- **Re-send the *whole* runtime-context snapshot only when it changed, and append it after the inherited history** — `2026-10-13-team-identity-runtime-context.md:15` (impl `packages/core/agent-loop/src/runtime-context.ts:152-162`, where `project()` returns `undefined` when `this.retained?.text === snapshot`, and `packages/core/agent-loop/src/agent.ts:427-440`, where the snapshot is appended as a `user/message` after the claimed messages). The snapshot text itself declares its own precedence — "Current runtime context. This snapshot supersedes earlier runtime-context snapshots." (`packages/core/system-prompt/src/index.ts:317`) — so the model never has to reconcile two context blocks. This is a *diff-free* re-admission protocol: whole-value comparison, no partial patching, no per-subsystem retention state, and it survives compaction for free.

- **Keep the cached request prefix stable by splitting fixed policy (a prompt *section*) from per-run facts (a dynamic *context*)** — `2026-10-13-team-identity-runtime-context.md:13` and `:23` (impl `packages/experimental/tool-agent-team/src/index.ts:173-177` for the section vs `:178-190` for the context; the projection that decides whether a changed prompt is appended after cached history or normalizes the head is `packages/core/agent-loop/src/runtime-context.ts:88-103`). The note's stated reason is that per-member system text "can rewrite the inherited request prefix on routes without in-history system updates" — for August, whose provider-prefix cache is explicitly a design concern, this is the same trade-off stated in a mechanism.

- **Let the provider publish its own image geometry instead of re-deriving it in the Host** — `2026-10-13-cua-hover-routes-and-coordinates.md:17` (impl `packages/llm/llm/src/index.ts:248` and `:692-693`; the DeepSeek and pi-ai implementations at `packages/llm/llm-deepseek/src/adapter.ts:45` and `packages/llm/llm-pi-ai/src/adapter.ts:238`; consumed by CUA at `packages/experimental/cua/src/index.ts:133`). The note's reason is exact: "making the model convert them duplicates provider geometry rules". August's screenshot/attachment path has the same hazard — a Retina capture, an attachment normalization step and a model-request resize all sit between the pixels and the pointer.

- **Convert model-facing coordinates once, in the Host, and make the failure modes typed** — `2026-10-13-cua-hover-routes-and-coordinates.md:15` (impl `packages/experimental/cua/src/coordinates.ts:55-76`, with `STALE_SNAPSHOT`, `SCREENSHOT_REQUIRED` and `INVALID_ARGUMENT` as distinct error codes, and `packages/experimental/cua/src/protocol.ts:17` for the `relative: z.literal(true)` schema). Two coordinate modes coexist — screenshot pixels by default, integer thousandths 0..1000 on explicit request — and the unit is never guessed from the value (:23). The relative path is resolution-independent and clamped inside the window, so a screenshot that was resized for the provider cannot silently mis-aim a click.

- **Make the tool's guidance text a recovery protocol, not documentation** — `2026-10-13-cua-hover-routes-and-coordinates.md:13` and `2026-10-13-cua-continuous-hover.md:13` (impl `packages/experimental/cua-macos/src/guidance.ts:40-42`). The guidance enumerates each error code and the exact next action: `STALE_APP` requires `getApp` again, `STALE_SNAPSHOT` requires `getState` again, `SCREENSHOT_REQUIRED` means capture a fresh screenshot, `WINDOW_CHANGED` requires fresh state before any retry, `PERMISSION_DENIED` requires the user to grant access and then observe fresh state — and it says "A successful action means dispatched, not verified completion" and "never retry uncertain input without observing". This is the tool-call-reliability lens answered in the tool's own schema text, where the model actually reads it.

- **Prefer a background/alternate route that does not disturb the user, and report which route ran** — `2026-10-13-cua-continuous-hover.md:13` and `2026-10-13-cua-hover-routes-and-coordinates.md:13` (impl `packages/experimental/cua-macos/native/Sources/CuaNative/AXHover.swift:12-35`, which walks up to an ancestor advertising both `AXShowAlternateUI` and `AXShowDefaultUI`, performs `AXShowDefaultUI` to restore and `AXShowAlternateUI` to reveal, and falls back only when no such element exists; the result identifies `hoverRoute` as `accessibility` or `system-pointer`). The note's "Problem" section is the transferable part: treating *every* hover as a system movement unnecessarily disturbs the user's pointer, and the fallback is gated on a foreground-PID check plus an AppKit mouse hit test that excludes input-transparent overlays.

- **Serialize the operation, not the application — no cross-call ownership** — `2026-10-13-cua-continuous-hover.md:15` and `:19` (impl: the shared native helper the note names, `2026-10-09-cua-shared-native-helper.md`). The stated reason is that "cross-call application reservation would block other tasks throughout observation and model inference without evidence that the first task deserves priority", and that "waiting for the model does not reserve the application". For August this is the multi-agent concurrency rule in one sentence: a long inference must not hold a resource another task needs, and ordering is explicit task coordination, not arrival order.

- **Make a not-yet-arrived artifact fail *explicitly* with a typed code, and make only the async face wait** — `2026-10-14-webworker-preview-profile-parity.md:58` (impl `packages/experimental/webworker-runtime/src/storage/memory.ts:383-394` for the `ERR_DSH_VFS_DEFERRED` refusal and `:331-336` for the single shared fetch). The rule: synchronous reads and every mutation of a registered-but-absent file are refused with a code that names the archive, while `fs.promises.readFile` / `open` / `cp` / `createReadStream` wait; the first waiter fetches once for everybody; a failed fetch leaves the registration so the next read retries; and a directory rename that would move a registered file is refused *before* the destination changes. That last clause is the steal — refusing *before* mutating is what keeps a partial failure from corrupting state.

- **Refuse a platform capability with one error code, and let only that code trigger a degraded mode** — `2026-10-14-webworker-preview-profile-parity.md:50` (impl `packages/experimental/inspector/src/host/plugin.ts:68-76`, where `isUnavailableOnPlatform(error)` is the only branch that survives a startup failure, and `:190` for the code check that inspects the code and never the message). A degraded Inspector warns once, keeps a bootstrap route that answers 503, registers no DevTools route, and loads no Node-only package — while *every other* startup failure still rolls the fiber back.

- **Reproduce the production launch path in the preview instead of special-casing it, and confine the difference to one enumerated patch** — `2026-10-14-webworker-preview-profile-parity.md:21-34` (impl `packages/experimental/webworker-packer/src/repository.ts:107-113` for the roster read from app-boot's `PROFILE_TEMPLATES` + `OPTIONAL_BUNDLES`, and `:124-132` for the single home-patch row per `PLATFORM_ENTRY_CONFIG` entry). The measurable acceptance criterion is the interesting part: "with no bundle enabled, the two compositions differ in only one of 188 rows" (:17) — a *row-level diff between the preview and production* as the parity test. August has the same class of problem (the packaged desktop app vs the dev web app) and could adopt a row-diff as its parity gate.

- **Split the artifact by scanning for the literal request form, and make an unpublished request a build error** — `2026-10-14-webworker-preview-profile-parity.md:54` (impl: the packer's `lazyChunksOf` scanning every page asset for `require.async("./client.<name>.js")`). The subtle bit is that a chunk requested *by another chunk* is found without tracing requests from the entry point, and a target named by a package's `./client` export under any condition stays in the base image; a request for a chunk the package does not publish fails the pack. Per-chunk deterministic `lazy/<sha256>.tar.gz` archives (:55) then make the split cacheable and reproducible across packs.

- **State the invariant you do *not* check, in the same note** — `2026-10-14-webworker-preview-profile-parity.md:57` and `:96` ("The digest in the archive name is not verified"; "the Worker checks only the registered paths and sizes of an arrived archive, not the digest that names it"). August's own notes repeatedly argue that a gate that cannot see a defect should say so; this note generalises it to *security-relevant* invariants — the archive's content hash is not checked, only its path/size manifest.

- **A bilingual pair is three files, and the consistency record's diff IS the act of confirmation** — `2026-10-13-team-identity-runtime-context.i18n.yaml:1-4` (impl `scripts/translation-pairing-record.ts:149-199` for the per-section hash that excludes fenced code blocks and generated regions, and `docs/i18n/README.md:11-22` for the contract). The properties worth stealing: the record is **section-keyed**, so two branches editing different sections do not conflict in Git; regenerating a region or editing a code block on both sides leaves the record unchanged; and `--write` requires naming the pairs you confirmed, because "that yaml diff is the reviewable act of confirming consistency". The owning contract also states the limit flatly: "a green gate means the pair was confirmed consistent at these exact contents, not that the confirmation was sound."
