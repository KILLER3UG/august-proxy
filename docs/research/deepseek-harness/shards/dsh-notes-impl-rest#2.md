# deepseek-harness / dsh-notes-impl-rest#2

## Shard shape

This shard is **not code at all** — it is the *decision-record layer* of deepseek-harness: 93 files in `.agents/notes/implemented/`, made of 31 English architecture notes, their 31 Chinese mirrors, and a 31-file bilingual-pairing hash record. The files split evenly into two campaigns. `simplification/` holds 13 notes that each remove one thing — a second agent/session identity, implicit send batching, synthetic turns, a second SQLite persistence format, transactional loader rollback, the E2B remote-execution providers, per-request subagent persona overrides, an ACP editor UI, a Desktop profile-cleanup step. `testing/` holds 18 notes that each *make a gate*: a real-API CI lane, a keyless browser e2e lane over the whole assembled web chain, a session-log snapshot corpus, four calibrated performance-budget lanes, a memory-limited benchmark rerun, a human-facing scaling report, and a family of Windows-lane and Desktop-updater qualification harnesses. Together they answer "why is the harness shaped this way" — the *reasons* behind the code other shards read. The Chinese files are line-for-line translations, and the `.i18n.yaml` files are per-heading hashes that make a translation pair mechanically checkable. Nothing here is generated or binary; every file was read end to end.

## Per-file notes

### .agents/notes/implemented/simplification/2026-06-20-unify-agent-and-session-id.md
- **Purpose:** Collapse the agent's registry id and its session's id into one identity, because "no production path reattaches one live agent object to several sessions or drives one session through several agent ids."
- **Key abstractions:** `AgentCreationTransaction` (one transaction for create *and* resume), `Session.header.id` as the single home of session identity, `Session.id` as a derived accessor, `CreateAgentOptions.sessionId`, `resumeSessionId`.
- **Data flow:** `agents[].id` stays a *stable configuration label*; a fresh start mints `${label}-session-${randomUUID()}`; resume registers under `resumeSessionId`; in-process subagent creation uses the child session id; a remote ACP run keeps one parent-minted lifecycle id while the child server's wire-local id stays private to ACP.
- **Non-obvious design decisions:** The two exact-id inputs (`sessionId` vs `resumeSessionId`) are *mutually exclusive* — the config-driven path uses a "resume-or-create" form so a config-created agent and the UI share one opaque identity across loop reloads instead of guessing from a prefix. `agent/created`/`agent/disposed` survive as *paired publication lifecycle events*, explicitly "not identity aliases."
- **Edge cases / failure handling:** Final-entry collision checks, exact-entry detach semantics, rollback and quiescence are all retained unchanged; the ACP bridge verifies exact `Agent` ownership from the forward session map and forwards only lifecycle events whose service-snapshotted `local` flag is true.
- **Surprising:** The note forecloses latent multi-session-actor and session-handoff designs *retroactively* — it is a decision that removes a future capability, not one that adds one.

### .agents/notes/implemented/simplification/2026-07-17-one-send-one-turn.md
- **Purpose:** Remove implicit batching from ordinary sends: two `Agent.send()` calls must never silently become one turn.
- **Key abstractions:** FIFO inbox queue item per send, `MessageId`, `Inbox.replace()`/`Inbox.remove()`, `agent/pre-step` (rejects or returns the complete entering batch), `agent/inbox/inserted { message }`, `turn/start`/`turn/end` + durability checkpoint as the unit of work.
- **Data flow:** A send inserts one item; the driver claims it after pending next-step input; the next send's turn starts only after the previous turn recorded `turn/end` *and* its durability checkpoint settled — so B's model request sees A's closed result in the same session log.
- **Non-obvious design decisions:** The guarantee is deliberately "at most one turn" (not "exactly one"), because an item can be dropped before it starts. `steer()` (next-step inbox, wakes the driver) and `inject()` (model-facing context only, never wakes the driver) are *outside* the no-batching rule. "Checkpoint error is reported, but settlement only releases this ordering barrier; it does not make a failed write durable."
- **Edge cases / failure handling:** Pre-step rejection closes a blocked no-step turn *without writing model-visible history*; broad `cancel()`, disposal, or a failure before `turn/start` discard an unstarted item rather than opening an empty turn.
- **Surprising:** The stated reason is *scheduling determinism*: grouping depended on whether calls came from the same stack, neighboring microtasks, or a model callback. The cost is explicit — more model requests and more checkpoints — and batching may only return through "an explicit, measured contract."

### .agents/notes/implemented/simplification/2026-07-23-acp-automation-only-protocol.md
- **Purpose:** Demote ACP from "second interactive product UI" to "automation transport," so TUI and Web alone own human interaction.
- **Key abstractions:** `@deepseek-ai/dsh-acp` outside the `ui` package group; per-session Promise chain preserving commit order; `AttachmentStore.saveImages()`; one-shot `session/request_permission` as a *machine* policy channel; interface-level agent/session/approval services (not the concrete agent loop).
- **Data flow:** A prompt snapshots its exact provider/model route *before* asynchronous admission, strictly decodes image blocks, delegates the whole batch to `AttachmentStore.saveImages()`, and only then publishes the user event; assistant image references are asynchronously re-read and integrity-verified for base64 delivery.
- **Non-obvious design decisions:** Image capability is **truthful rather than structural** — `initialize` advertises it only when a durable attachment store exists *and* the configured exact route resolves with explicit image input; "Unknown capability is false at initialization." Raw chunks, todos, plans, titles, retry markers, terminal metadata and diffs stay off the wire: only *committed semantic facts* are emitted. A completed content-addressed write "may remain unreachable because destructive rollback is not valid for a deduplicated store." stdout carries framed JSON-RPC only, so the app mounts no stdout logger and the bridge does not monkey-patch process output.
- **Edge cases / failure handling:** Cancellation reserves and aborts the admission slot *before* any async work and waits for already-started writes to quiesce; missing/corrupt assistant objects fail prompt delivery rather than becoming placeholders; caller-correctable image-policy failures map to invalid parameters while route/storage/persistence failures stay internal faults. Disconnect and plugin disposal share one memoized quiescence boundary; a create that loses the close race disposes its unpublished handle.
- **Surprising:** The note records that `session/new`'s real-stdio close race is **coverage-exempt** because the in-memory transport cannot reproduce that ordering — an explicit, documented hole rather than a silent one.

### .agents/notes/implemented/simplification/2026-07-28-remove-synthetic-log-only-turns.md
- **Purpose:** Stop wrapping log-only events (titles) in synthetic `turn/start`/`turn/end` pairs.
- **Key abstractions:** `SessionStore.appendOutOfBand()` (deleted), `OutOfBandSessionEventMap`/`OutOfBandSessionEventType` (deleted), `ctx.sessions.flush(session)` as the explicit durability barrier, `session/title`, `session/title-llm-request`, `compaction/* { turn: null }`.
- **Data flow:** A plugin that owns a log-only event appends it through `Session` between turns; persistence admits it via the bounded `session/event` path and drains it at ordinary checkpoints.
- **Non-obvious design decisions:** The universal turn-enclosure rule existed only because persistence recovery once treated the last `turn/end` as the committed boundary; the scanners now preserve every valid contiguous event, so the rule was retired. "Core permits merge-extensible events between turns because only their declaring plugin knows whether they are execution-scoped or standalone." Manual compaction *does* explicitly flush, because `/compact` promises durability before releasing queued prompt admission.
- **Edge cases / failure handling:** Standalone events consume session sequence numbers but *not* turn numbers. `SessionStore.fork()` preserves standalone title and other plugin-owned log-only records.
- **Surprising:** The generic helper was rejected not because it was generic but because it "duplicated domain policy" — the title capability already owned cancellation, liveness and stale-result rules, and the helper's marker map was a second copy of that policy.

### .agents/notes/implemented/simplification/2026-08-09-explicit-schedule-time-zone.md
- **Purpose:** Stop turning a browser fact (time zone) into shared product state.
- **Key abstractions:** request-local `clientTimeZone` on the RPC boundary; time-context derived from *original user-rpc messages in the open turn*; Schedule's `at` as strict RFC-3339-with-offset or exact `{ date, time, time_zone }`; canonical UTC `scheduledAt`.
- **Data flow:** The Web client samples `Intl.DateTimeFormat().resolvedOptions().timeZone` per prompt; the Host validates/canonicalizes it and logs it on that exact `user-rpc`; time-context derives *unique / mixed / missing* and either formats the clock for the model or tells it to ask the user.
- **Non-obvious design decisions:** The browser zone crosses into Schedule *only* through the model's explicit tool arguments — Schedule "does not import time-context, inspect user-message sources, read a Session header, or produce a confirmation error." The configured/process zone is only a display fallback and is "never presented as user authority." DST gaps are rejected and overlaps resolve to the first instant.
- **Edge cases / failure handling:** Invalid `clientTimeZone` values reject prompt admission before the agent is entered; mixed browser-zone records make the model ask rather than mutate shared state.
- **Surprising:** The whole subsystem (Session header field, JSONL header field, SQLite column + migration, create/resume/fork conflict rules) was deleted rather than added — the note argues a durable Session default "duplicated an assumption instead of strengthening the absolute-time boundary."

### .agents/notes/implemented/simplification/2026-08-30-jsonl-only-session-persistence.md
- **Purpose:** Make JSONL the only first-party physical Session store, deleting the optional SQLite Session-persistence provider.
- **Key abstractions:** `ctx.sessionPersistence` service definition (backend-neutral, out-of-tree providers still allowed); `@deepseek-ai/dsh-session-persistence-jsonl`; `@deepseek-ai/dsh-session-query-sqlite` (a *disposable derived FTS5 index*, not authority); `@deepseek-ai/dsh-storage-sqlite` (generic domain KV).
- **Data flow:** The SQLite query provider observes persistence through `ctx.sessionPersistence` and maintains its own rebuildable index; cross-package tests use the real JSONL provider or an owner-local fake.
- **Non-obvious design decisions:** The argument is *obligation counting*, not preference: an unselected production provider "multiplies every durable-format, lifecycle, platform, and migration obligation" even though shipped profiles never select it. The migration stack keeps one per-Session JSONL generation path, bytes and inode unchanged while publishing only a final successor — no parallel database transaction protocol.
- **Edge cases / failure handling:** Explicit compatibility cut: existing databases written by the removed provider are not opened or migrated; operators must export the logical Session with a build that still contains the provider.
- **Surprising:** The note distinguishes three SQLite packages by *role* (authoritative log / derived query index / generic KV) — conflating any two of them is the error it warns about.

### .agents/notes/implemented/simplification/2026-09-09-nontransactional-loader.md
- **Purpose:** Revert transactional config reload: Loader mutates eagerly and never rolls back a failed plugin.
- **Key abstractions:** vendored `Loader`/`EntryGroup`/`EntryTree`/`Fiber`/`Entry`/`isolate`; Include's parse validation and patch reapplication; `internal/update` waterfall; vendor ledger recording every retained deviation from the pinned upstream.
- **Data flow:** EntryGroup starts siblings concurrently and logs application failures; EntryTree waits for outstanding work but does not reject on failed fibers. Application consumers own their completion checks — CLI waits for its fallback HMR service, the directory chooser checks the entries it mounts, the chooser and browser package runner capture the *first* fiber-disposal result before removing the entry and await it before reporting teardown complete.
- **Non-obvious design decisions:** Two upstream changes are kept for concrete, reproduced reasons: awaited initial-file creation + forced rereading in Include (restoring the pre-#932 debounced sequence reproduces `ENOENT` in the missing-file init test) and Schemastery conditional exports (removing them reproduces `ERR_REQUIRE_ESM_RACE_CONDITION` while the Web preset suite boots).
- **Edge cases / failure handling:** "A plugin activation failure can leave the new options and a failed fiber in place. Callers that require active plugins must audit after settlement; awaiting `Loader.create()` alone does not establish activation." Durable Include writes drain before *and* after child removal so a later teardown write cannot erase an earlier terminal write failure.
- **Surprising:** The note admits "a plugin activation failure can leave a partially applied tree" and treats that as an accepted, documented consequence rather than a bug to fix.

### .agents/notes/implemented/simplification/2026-09-11-remove-e2b-providers.md
- **Purpose:** Remove the E2B sandbox/filesystem/subprocess providers, keeping the *interfaces* they exercised.
- **Key abstractions:** `ctx.fs` / `ctx.subprocess` (one path namespace + one process world); providers own path conversion, executable lookup, ordinary streams, terminal allocation and managed cleanup; consumers retain tool semantics, policy and presentation.
- **Data flow:** The E2B experiment supplied a remote filesystem/process world while harness, credentials, model transport and session state stayed on the host; the three providers demonstrated that consumers can share the existing interfaces without provider-specific tools.
- **Non-obvious design decisions:** Async terminal contracts are retained even though local implementations complete synchronously, because "a local implementation completing these calls synchronously does not justify removing the asynchronous behavior required by remote providers." The reason for removal is *transport economics*: the pinned `e2b@2.29.1` SDK retained complete stdout/stderr even under consumer backpressure, so stream-level queue bounds could not bound host memory.
- **Edge cases / failure handling:** "A connection loss cannot justify replaying a possibly executed program or claiming unobserved cleanup succeeded." PTC Node confinement needs bidirectional control traffic separate from stdin/stdout/stderr — the SDK exposed no extra descriptor transport, and a descriptor created in the VM is not exposed to the host.
- **Surprising:** The note keeps the *portability decision* alive while retiring one realization, and preserves the POSIX SSH providers as the working remote-execution evidence, including a "Reintroduction conditions" section.

### .agents/notes/implemented/simplification/2026-09-17-unified-subagent-activations.md
- **Purpose:** Give every subagent provider one entry point, one ownership graph and one capacity accounting.
- **Key abstractions:** `startActivation()`; published handle = child identity + result promise + disposal of *that exact activation*; `prepareContinuable()`; parent-owned catalog of child membership; `mode: 'external'` entries.
- **Data flow:** Local spawn/fork providers contribute only `prepareContinuable()` data — the subagent service owns Agent creation and residency. Local results wait for pending input and owned descendants before closing admission, so descendant replies can contribute to the final answer. Both local and external result promises settle *after* cleanup and notifications.
- **Non-obvious design decisions:** The model-facing tool always returns a background child id and promises the manager's completion notice — no foreground switch, no Job integration. The parent notice includes final text *regardless of whether the child called `send_message`*, because "tool availability cannot establish that the child sent its answer." Accepted duplication ("an answer already sent through the tool can appear twice") is preferred over making delivery depend on model compliance.
- **Edge cases / failure handling:** A captured execution result survives cleanup failure, which disposal reports separately. Membership is recorded once at creation; execution and cleanup do not update the catalog. The native Session reader rejects duplicate child membership for local and external entries.
- **Surprising:** The note explicitly rejects Jobs for background children ("a second work registry and cancellation authority") and rejects always sending results to the parent (duplicate context, may disturb a parent awaiting the workflow tool).

### .agents/notes/implemented/simplification/2026-09-19-remove-desktop-profile-core-cleanup.md
- **Purpose:** Delete the Desktop production step that deleted core packages from the user's profile before every launch.
- **Key abstractions:** `DesktopProjectManager.applyRelease`; shared `removeLinkProjections`; profile resolution = nearest-wins (`profile/node_modules` beats `$DSH_HOME/profiles/node_modules`); `desktop-runtime-state.json` (no longer read).
- **Data flow:** Earlier Desktop builds had installed core packages into the profile as local tarballs (writing declarations, overrides and a lockfile), and the link backend's dev mode projected the installation closure into the same `node_modules`. Under nearest-wins resolution those copies shadowed the bundled runtime, combining an old Web frontend with new plugins.
- **Non-obvious design decisions:** The cleanup fought the next pnpm operation (pnpm reinstalls from retained declarations), and had to rerun on every production launch. Official packages now keep only pure-function packages under `dependencies` and declare every module-level-identity package as a *peer*, so a plugin that pulls an identity-bearing dsh package as a real dependency makes that packaging choice for itself.
- **Edge cases / failure handling:** Reintroduction conditions are written down: a released Desktop writing core-package copies into external users' profiles, or official packages changing dependency conventions. Capability given up: earlier-Desktop core-package copies in a profile need one manual removal.
- **Surprising:** A regression test asserts the profile's `node_modules`, manifest declarations, `desktop-runtime-state.json` and lockfile are *byte-for-byte unchanged* after a launch — a test for the absence of a mutation.

### .agents/notes/implemented/simplification/2026-09-26-team-direct-inbox.md
- **Purpose:** Delete the Team outbox and deliver Team messages through the target agent's inbox.
- **Key abstractions:** live Lead `Steer`; host-only subagent Steer adapter; `agent-message` source; `MessageId` returned or throw.
- **Data flow:** A send returns the accepted inbox `MessageId` or throws; acceptance follows ordinary Agent persistence; the sender is retained via the existing `agent-message` source and the member name in the content.
- **Non-obvious design decisions:** Acceptance "neither confirms model processing nor adds a synchronous flush guarantee." Team keeps no unaccepted intent, does not retry after restart and does not deduplicate explicit resends — a second delivery owner beside the Agent inbox was judged to cost more than the undelivered old messages it could recover.
- **Edge cases / failure handling:** Historical mailbox records stay *decodable and projected* so existing Lead logs replay, but Team never delivers or acknowledges them — a historical message its target had not recorded before the upgrade is never delivered.
- **Surprising:** Deleting the decoder was explicitly considered and rejected, because Lead logs containing mailbox records would then fail to replay.

### .agents/notes/implemented/simplification/2026-10-05-native-or-ptc-presentation.md
- **Purpose:** One tool-invocation form per agent: `native` (visible capability schemas) or `ptc` (only `run_code` + generated SDK). `both` is rejected in configuration.
- **Key abstractions:** the tool registry's presentation mode; the PTC decision that still owns the registry, runtime and nested-call rules.
- **Data flow:** Presets may select different supported modes in one application, so a native agent and a PTC agent can coexist; the presentation mode is chosen at agent configuration, not per step.
- **Non-obvious design decisions:** Mixed presentation "adds schema-ordering, admission, configuration, and test combinations without a separate execution capability." Silently mapping `both` to another mode was rejected because either mapping changes how existing programs or direct calls execute — the choice is made *visible* by an explicit configuration rejection plus an upgrade guide.
- **Edge cases / failure handling:** Older Session generations and explicitly retained recordings keep their original bytes and remain readable; the removal changes *accepted configuration*, not the plugin-author registration API or the guarded execution pipeline.
- **Surprising:** A short note with a large decision: "an agent cannot alternate between direct end-tool calls and `run_code` through one mixed presentation."

### .agents/notes/implemented/simplification/2026-10-09-preset-owned-subagent-composition.md
- **Purpose:** Let Agent Presets own a child agent's persona and tools instead of per-request `persona`/`toolFilter` inputs.
- **Key abstractions:** Agent Preset plugin list (persona + tools); fork inherits the parent's preset revision; model and effort selection keep existing configuration.
- **Data flow:** New subagent requests select an Agent Preset where the provider supports it; persona and tools come from its plugin list. The six shipped child schedule deny lists (standard, PTC and Cordis presets) are removed; reminder schemas inherited from the preset stay visible and each executor refuses delegated callers.
- **Non-obvious design decisions:** `dsh-tool-subagent` **rejects the removed keys at load**, including empty values, "because deleting Schemastery fields alone does not reject unknown configuration." The note is explicit that the children still receive four reminder schemas whose executors always refuse them, and that "neither their prompt cost nor a provider cache-hit improvement has been measured; other request inputs can still differ" — i.e. the cache-hit claim is deliberately *not* made.
- **Edge cases / failure handling:** Released child descriptors keep their persona and filter fields, parsing and cold-resume application — new-request simplification does not authorize rewriting released Session data.
- **Surprising:** This is the shard's only note that touches *provider prefix-cache stability* and it explicitly refuses to claim a cache-hit win; "no preset-level filter or finer plugin split is added without a concrete consumer."

### .agents/notes/implemented/testing/2026-06-19-real-api-e2e-ci.md
- **Purpose:** Make real-API e2e a merge signal without destroying the keyless, forkable default gate.
- **Key abstractions:** `.github/workflows/e2e.yml` (separate from `ci.yml`); `test:e2e` / `*.e2e.ts`; `describe.skipIf(!process.env.DEEPSEEK_API_KEY)`; repo secret `DEEPSEEK_API_KEY_EXTERNAL` → env `DEEPSEEK_API_KEY`.
- **Data flow:** Triggers = `workflow_dispatch` + push to main/master + nightly `17 0 * * *` + `pull_request`. A job-level `if:` skips fork PRs *and* Dependabot PRs; a preflight turns an empty key into `exit 1` with a `::error::` annotation before the suite runs.
- **Non-obvious design decisions:** "Different lifecycles → different files" — the keyless gate stays forkable and always-green. The Dependabot clause keys on `pull_request.user.login` (PR **author**) rather than `github.actor` (run trigger), so a maintainer re-running a Dependabot PR does not make the keyless PR look trusted. A *job-level* `if:` skip reports as a successful check (unlike a workflow-level skip, which stays pending), so the workflow is safe to mark required.
- **Edge cases / failure handling:** Step-scoped `env:` so checkout/setup-node/install never see the key; `permissions: contents: read`; `DEEPSEEK_BASE_URL` pinned so a stray repo-root `.env` cannot redirect the run; the preflight prints only "present." — never the value or its length. A missing secret becomes a *visible* failure rather than a suite that self-skips to all-green.
- **Surprising:** Contains a full, reusable threat model (who can reach the secret; what changes when the repo goes public; a `SECURITY —` comment forbidding `pull_request_target`) and names the operational steps for flipping visibility, including "rotate on flip."

### .agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md
- **Purpose:** A keyless, deterministic browser e2e lane over the *entire assembled* web chain — chromium page → client plugin bundles → HTTP unary RPC + two SSE streams → `toFetchHandler`/apiproxy → host agent loop, tools and JSONL persistence.
- **Key abstractions:** `dsh-llm-replay` (in-process replay model behind the real backend contract); `apps/web/tests/scaffold.ts` (boot wiring + browser glue only); `DSH_SNAPSHOT=replay|record|refresh`; normalized `ariaSnapshot()` goldens; `snapshot.yml`; `ReplayHandle.assertConsumed()`; `llm-retry` mounted in the shipped composition.
- **Data flow:** The scaffold boots the *real* `base.cordis.yml` + `web.cordis.yml` through the vendored Loader's include mechanism, patched for a temp persistence root, pinned skill roots, `agent-instructions` off, `session-title-llm` off, webserver port 0, and the `llm-deepseek` row disabled. `installLlmReplay` fills the empty adapter registry on the settled root ctx. `seedSession()` seeds cold sessions through the *real* persistence API, never raw file writes.
- **Non-obvious design decisions:** The barrier stack is ordered and explicit: (1) host-side `await agent.whenIdle()` under a timeout keyed on the in-process `turn/end` (the idle flip follows the persistence flush, so one await covers turn completion *and* durability), then (2) a browser settled poll. Polling persistence files as a durability barrier is banned (slow on NFS, superseded by `whenIdle`); `networkidle` is banned outright (never resolves while an SSE stream is open). An in-process `turn/end` listener alone is a *wrong* barrier. Every scenario fails on any `pageerror` and on the client's connection-loss/gap-repair console warnings, because "the reconnect machine plus history resync would otherwise self-heal a dead SSE path and the suite would certify a broken wire." No vitest retry; one browser per file and engine, fresh context and fresh host per scenario.
- **Edge cases / failure handling:** Replay's first-call-order binding constrains scenarios to one prompting session each, with the consumption assertion as the tripwire. `compaction-basic` shares the session's replay cursor and stays inert only under the published 128k catalog window. The ARIA format is Playwright-owned — the one committed snapshot format the repo does not control — so Playwright bumps must be deliberate bump-and-refresh commits.
- **Surprising:** A "Prior art" section surveys LibreChat/ai-chatbot/open-webui/OpenHands and concludes that *no* surveyed project replays a recorded agent-event log through the real backend for UI tests, so the session-log-as-fixture design "goes one step beyond prior art." It also refuses browser-level SSE interception (`page.route`) because `route.fulfill` cannot stream — exactly where both confirmed GUI P0s hid.

### .agents/notes/implemented/testing/2026-08-03-opt-in-reasoning-chunk-browser-stress.md
- **Purpose:** Bound the React/render cost of long reasoning streams without losing any chunk from the durable stream.
- **Key abstractions:** `Notifier.markDirty()`; `requestAnimationFrame` publication mode; `BoundConversation` owning one pending frame per Session; `assistant/live-chunk`; `assistant/message` / `assistant/attempt` durable settlements.
- **Data flow:** The Session Controller appends every Client-only live chunk to its event source; Conversation folds it into each matching Definition State; Chat and Trajectory Definitions request `animation-frame` publication for `block-start`, `text-delta`, `reasoning-delta`, `tool-call-delta`, `block-end`. The first change schedules one rAF; later chunks keep updating State; the frame callback materializes **one** accumulated snapshot from the latest State. `usage` and `finish` request no publication.
- **Non-obvious design decisions:** "Microtask batching alone" is rejected because each async `yield` can create a microtask boundary, so the microtask queue drains between adjacent chunks and batching degrades to one notification per chunk. Dropping/sampling live chunks before folding is rejected because live state would diverge from the durable embedded stream. `BoundConversation` makes a later frame callback harmless ("no dirty Context remains"). The Think row's horizontal tail-follow is a *separate* visual policy: one update every three frames, reading `scrollWidth`/`clientWidth` from the latest DOM and writing `scrollLeft` directly — it never delays body scrolling, history-prepend anchoring or user `scrollIntoView`.
- **Edge cases / failure handling:** Environments without `requestAnimationFrame` publish immediately. A settlement may skip one intermediate partial that has not yet appeared, while the published final content and durable embedded stream remain complete. The decision "reduces snapshot rebuilding and React work without pretending to solve raw-stream parsing cost" — ingestion, ordering, logging, string concatenation and accumulator updates still run for every raw chunk.
- **Surprising:** The stress lane is *opt-in and keyless* (`pnpm run test:web:stress`): a test-owned adapter emits 100,000 `reasoning-delta` chunks through the real Host/Gateway/WebSocket/Session reduction; each 128-chunk batch waits for one browser timer turn so a 50 ms heartbeat and a pre-scheduled DOM event measure one bounded ingestion/render interval rather than accumulated socket backlog. Pacing by animation frames was rejected — it would give the page implicit backpressure absent from a real network stream.

### .agents/notes/implemented/testing/2026-08-23-installed-python-wheel-black-box-ci.md
- **Purpose:** Validate the Python SDK and packaged runtime as *installed artifacts* on every native target before merge.
- **Key abstractions:** the pure SDK wheel + per-platform runtime wheel; a fresh Python 3.10 venv; `PYTHONPATH`/`DSH_RUNTIME_MODE` unset; the packaged executable; `dsh plugin`; Zstandard persistence.
- **Data flow:** Each native target installs both local wheel files, `chdir`s to a temp directory outside the repo, and invokes only public Python modules plus the packaged executable. A local SSE model keeps outputs deterministic while the public SDK exercises the default profile, ordered patch overlays, external bundle installation, persistent PTY/editor behavior, PTC Node program and workflow execution, ripgrep search, external stdio MCP, model-visible and durable snapshots, Zstandard persistence, direct JSON-RPC and shutdown.
- **Non-obvious design decisions:** A dedicated **installed-artifact identity check runs before the first agent request** and rejects a non-venv process, a repo-relative cwd, a source/editable import, unequal distribution versions, an SDK dependency that does not exactly pin the runtime version, an executable outside the installed runtime package, or an executable absent from the runtime distribution record — "so a behavior pass cannot conceal that the wrong code ran."
- **Edge cases / failure handling:** The restart snapshot launches two complete SDK runtime processes against one persistence root and pins their isolated histories and separate durable logs. Fork and Dependabot PRs never receive the secret; `pull_request_target` is forbidden. Decoded record content and completed-turn durability are *deterministic keyless* obligations owned by the restart snapshot rather than inferred from compressed live-provider bytes.
- **Surprising:** The live-provider check is deliberately a *two-turn* task: turn 1 asks the model to write an exact sentinel file through the platform shell, turn 2 reads it back — proving the tool call, the persistence and the turn reason, not just a completion.

### .agents/notes/implemented/testing/2026-08-24-session-log-snapshot-corpus.md
- **Purpose:** Give the keyless corpus a clear ownership rule: `snapshots/` and `*.snapshot.ts` are reserved for scenarios that own or reference recorded session JSONL.
- **Key abstractions:** the recorded session as *both* replay input and expected output; `snapshot.yml` (profile, patch, lifecycle control, platform, header pin, workspace facts the completed session cannot express); typed relationship-preserving redaction map; `session[.<ordinal>][.vN].jsonl` naming; `writer.expected.jsonl`; `snapshot.yml` header pins.
- **Data flow:** Each process-level scenario launches a shipped profile through `dsh`; a small adapter controls headless/SDK/ACP/Web behavior without becoming another application entrypoint. ### .agents/notes/implemented/testing/2026-10-11-user-text-credential-matching.md
- **Purpose:** Make credential detection in sent user text linear in the length of the text *and* in the number of queries over it.
- **Key abstractions:** the format literal table (all starting literals in one literal-only alternation scanned with `test`); a hit-identification table keyed by the last two code units; a per-instance `Int32Array` memo (four `[A-Za-z0-9_-]` slots, one per other class, next digit, next valid `END` line); the `://`-anchored address-password walk.
- **Data flow:** The UserText scheduler queries the matcher again after each accepted node, so a text costs the sum of all its queries. The scan finds starts, identifies the format, applies numeric format checks, measures runs with sticky `[class]*` patterns, and joins candidates in start order; masks are slices of the first 8 characters plus a shared mark string.
- **Non-obvious design decisions:** "Scanning is native, decisions are JavaScript": in V8 a per-character JS loop is slower than a native literal scan, so all work proportional to input length uses non-backtracking native patterns and JS makes a constant number of decisions per hit. Pruning depends on the *formats* only — starts come from format literals, not from character frequency — "so text with any character distribution pays the same linear cost." The memo is keyed by *text*, owned by the instance and cleared when a query names another text, because "a memo inside one query cannot stop later queries from measuring the same characters again."
- **Edge cases / failure handling:** Overlapping literals resume the scan at the suffix (at most one character back per hit). `://` inside an offset is checked directly; otherwise the matcher first confirms `:`, a non-empty password and `@` follow the offset before walking back over the user name (≤258 characters). Nothing is allocated before a node is returned. A range that reaches the end of the text ends the scan. The literal-pattern unit test rejects quantifiers and the benchmark rejects superlinear scans and extra allocation.
- **Surprising:** The benchmark doubles as a **rejection oracle**: "the same benchmark fails when pointed at the regular-expression implementation or at an implementation that rebuilds its memo per query," and equivalence tests compare the implementation with the regex oracle node-by-node through the production scheduler from every query offset.

## Ideas worth stealing

- **One send is at most one turn — grouping must not depend on scheduling** — `.agents/notes/implemented/simplification/2026-07-17-one-send-one-turn.md:17` — the mechanism is that each `send()` becomes its own FIFO queue item and the *next* send's turn may not start until the previous turn recorded `turn/end` **and** its durability checkpoint settled, so turn B's model request always sees turn A's closed result in the same session log. August's own AGENTS.md shows the same class of hazard (a tool call's result must be visible to the next turn) and this gives the exact ordering rule plus the three exceptions (`steer`, `inject`, whole-agent `cancel`) — and it names the cost honestly: more model requests, more checkpoints.
- **Coalesce *publication*, never *ingestion* — rAF instead of microtask batching** — `.agents/notes/implemented/testing/2026-08-03-opt-in-reasoning-chunk-browser-stress.md:15` — the mechanism: fold every raw chunk into State immediately (so live state never diverges from the durable embedded stream) but publish one accumulated snapshot per `requestAnimationFrame`, with structural events and durable settlements preempting. August's streaming Think/assistant rows re-render per delta; this is the transferable boundary — "microtask batching alone" degrades to one notification per chunk because each async `yield` drains the microtask queue.
- **A barrier *stack*, with `whenIdle()` first and `networkidle` banned outright** — `.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md:27` — the mechanism: host-side `await agent.whenIdle()` keyed on the in-process `turn/end` (the idle flip follows the persistence flush, so one await covers turn completion *and* durability), then a browser settled poll; polling persistence files as a durability barrier is banned, and `networkidle` is banned because it never resolves while an SSE stream is open. August's SSE/TUI surfaces have exactly this barrier problem, and the "which barrier is wrong" table is the transferable part.
- **Fail the test on any pageerror and on connection-loss console warnings — a self-healing client must not certify a dead wire** — `.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md:35` — the mechanism is that reconnect + history resync would otherwise heal a broken SSE path and the suite would go green on a broken product. August's harness has the same reconnect-plus-resync shape; this is a one-line guard with a stated reason.
- **A replay consumption assertion as a teardown tripwire** — `.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md:35` — `ReplayHandle.assertConsumed()` checks that every recorded script was bound and every cursor drained at scaffold close, turning "silent underrun / shifted binding" into a crisp diagnostic. This is the pattern that makes a recorded-fixture harness safe: the fixture is *owed* a consumption.
- **A keyless lane that boots the *real* composition, with the adapter row disabled rather than faked** — `.agents/notes/implemented/testing/2026-07-24-web-gui-browser-e2e-lane.md:21` — the mechanism: disable the `llm-deepseek` row in the real config tree and install the replay adapter into the *empty* adapter registry (never catch-all, or `resolveModelInfo` becomes unroutable and `compaction-basic` warns every step); a scenario with no fixture leaves the registry empty so a stray stream fails loud with `NO_ADAPTER`. "Honest keylessness" beats a placeholder API key — the placeholders satisfied a fail-loud key check with a lie.
- **Bind port `0` so the OS allocates atomically** — `.agents/notes/implemented/testing/2026-08-24-session-log-snapshot-corpus.md:27` — the mechanism: each scenario-owned HTTP fixture binds loopback port 0, lets the OS allocate and bind atomically, then maps the recorded URL to that listener. Pre-probing a port is a TOCTOU race; a fixed numeric port makes concurrent snapshot jobs race on one host.
- **Performance budgets as reviewed source constants, calibrated against positive *and* negative controls** — `.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md:40` — the mechanism: `ciTimeBudget()` = reference expectation × 2× CI time scale × 1.25× variance headroom, with a pre-stack reference implementation as the positive control and a repeated-snapshot regression as the negative one (which exhausts the heap), and no environment-variable override. "A business-implementation change must not relax a budget without new positive and negative control data." August has a cost/usage surface but no calibrated perf gate; this is the whole recipe in one paragraph.
- **Measure the user-visible endpoint, not only the components, and separate first-open from reopen** — `.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md:30` — the mechanism: four phase budgets (`openMs`/`readMs`/`sessionRestoreMs`/`projectionMs`) for attribution plus separate end-to-end budgets for first history and Agent resume, with the phase *sum* marked "diagnostic only"; and two lifecycle access kinds (first open with migration vs post-upgrade reopen in a fresh process) because migration is a one-time cost that cannot protect later opens.
- **A constrained-heap run as an *independent* transient-allocation limit** — `.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md:23` — the mechanism: normal-heap mode runs five samples and enforces the median; a second child runs the same path under a fixed 128 MB old-space limit and checks only that it *completes*, so the extra GC under pressure never pollutes the timing baseline. Combined with explicit GC before/after and reachable long-lived objects, this separates "retained memory" from "transient spike".
- **Wait on the state you read, anchored at the hand-over — not on a wall-clock window** — `.agents/notes/implemented/testing/2026-09-27-observation-waits-on-observed-state.md:17` — the mechanism: `observingChild` stays in flight until the test has read the record, and the bounded wait starts at the mocked launcher's hand-over rather than at test start, with the bound set *below* the case budget so a missing record fails as "the assertion that names it" rather than as a runner timeout.
- **Put the whole readiness timeline in the failure message** — `.agents/notes/implemented/testing/2026-09-27-observation-waits-on-observed-state.md:19` — the mechanism: every decoded chunk with its marker verdict, every poll, every write, each send's settle reason and elapsed time, the replayed prompt evidence and the host/shell/PSReadLine/console-host versions, printed by `onTestFailed` when the runner budget expires first. A count-only assertion ("no send fell back to the silence tier") could not say *which* send failed.
- **Prefer a keyboard-driven interaction over a geometry-bound pointer click whose result feeds a later layout assertion** — `.agents/notes/implemented/testing/2026-09-27-spreadsheet-selection-by-keyboard-before-reflow.md:15` — the mechanism: a pointer press resolves its target from `getBoundingClientRect()` *inside* a `useState` updater, and React re-runs updaters when the hook queue holds a lower-priority update ahead of them — so one click executed four times across a sidebar reflow and resolved to a different cell. Keyboard selection computes from committed state and is idempotent under re-execution.
- **Native literal scan for detection, JavaScript for decisions; memo per *text*, not per query** — `.agents/notes/implemented/testing/2026-10-11-user-text-credential-matching.md:17` — the mechanism: all starting literals in one literal-only alternation scanned with `test` (no quantifiers, so no backtracking), a hit table keyed by the last two code units, per-instance `Int32Array` run/digit/`END` memo cleared when a query names another text, and pruning keyed on the *formats* only so text with any character distribution pays the same linear cost. Directly relevant to August's per-chunk scrubbing of streamed text.
- **Use the benchmark itself as a rejection oracle against the naive implementation** — `.agents/notes/implemented/testing/2026-10-11-user-text-credential-matching.md:51` — "the same benchmark fails when pointed at the regular-expression implementation or at an implementation that rebuilds its memo per query." A benchmark that only proves the fast path passes is half a gate; the same harness pointed at the old code must fail.
- **A truthfulness rule for capability advertisement** — `.agents/notes/implemented/simplification/2026-07-23-acp-automation-only-protocol.md:21` — advertise image capability only when a durable store exists *and* the configured exact route resolves with explicit image input; "Unknown capability is false at initialization; prompt admission rechecks the live route." Protocol vocabulary ("the SDK has an image block") is not evidence the deployment can do it.
- **Emit only committed semantic facts on the wire** — `.agents/notes/implemented/simplification/2026-07-23-acp-automation-only-protocol.md:23` — raw chunks, todos, plans, titles, retry markers, terminal metadata and diffs stay off the transport; a per-session promise chain preserves reasoning/assistant/tool/configuration/usage ordering while assistant images are asynchronously re-read and integrity-verified. August's SSE surfaces would benefit from the same "committed vs provisional" split.
- **One identity per agent/session pair, with the config label kept as metadata** — `.agents/notes/implemented/simplification/2026-06-20-unify-agent-and-session-id.md:19` — the mechanism plus the operational rule: a config-driven start mints `${label}-session-${uuid}`, and the "resume-or-create" form lets a config-created agent and the UI share one opaque identity across loop reloads instead of guessing from a prefix. Every translation map between two ids disappears.
- **No second delivery owner beside the inbox** — `.agents/notes/implemented/simplification/2026-09-26-team-direct-inbox.md:13` — Team sends return the accepted inbox `MessageId` or throw; acceptance "neither confirms model processing nor adds a synchronous flush guarantee"; no unaccepted intent is retained and no retry happens after restart. August's bot-to-bot messaging has the same shape of risk (two acceptance states).
- **Subagent result delivery must not depend on model compliance** — `.agents/notes/implemented/simplification/2026-09-17-unified-subagent-activations.md:21` — the parent completion notice includes final text *regardless* of whether the child called `send_message`, because "tool availability cannot establish that the child sent its answer"; an answer already sent through the tool may appear twice, and that duplication is accepted rather than requiring a second delivery ledger. One activation entry point (`startActivation()`) owns admission, cancellation, ownership and release across local, ACP, SDK, Codex and Claude Code providers (`:13`).
- **Do not open a turn just to obtain a durability checkpoint** — `.agents/notes/implemented/simplification/2026-07-28-remove-synthetic-log-only-turns.md:17` — log-only events are appended between turns and flushed explicitly via `ctx.sessions.flush(session)`; the synthetic-turn rule existed only because persistence once treated the last `turn/end` as the committed boundary. August's `turn_end` reason vocabulary and outcome ledger depend on turn counts meaning *model-loop executions*.
- **One tool-invocation form per agent, and reject the mixed configuration loudly** — `.agents/notes/implemented/simplification/2026-10-05-native-or-ptc-presentation.md:13` — the registry rejects `both`; silently mapping it to another mode is rejected because either mapping changes how existing programs or direct calls execute. August has a very similar native-vs-PTC (`run_code`) fork in `app/services/workbench/code_runner.py`.
- **Reject removed configuration keys at load, including empty values** — `.agents/notes/implemented/simplification/2026-10-09-preset-owned-subagent-composition.md:15` — "deleting Schemastery fields alone does not reject unknown configuration," so `dsh-tool-subagent` rejects `persona` and `toolFilter` explicitly; the same note is careful to *not* claim a provider cache-hit win for the change (`(:19)`) — a useful model for August's per-model tool-surface work, where cache-prefix stability is the actual currency.
- **A preflight that turns a missing secret into a loud failure, so a self-skipping suite can safely be a gate** — `.agents/notes/implemented/testing/2026-06-19-real-api-e2e-ci.md:44` — plus step-scoped secret env (`:50`) so checkout/install never see the key, and a Dependabot gate keyed on the PR *author* rather than `github.actor` (`:35`). August's e2e smoke has the same "skip when no key" shape that silently disables the net.
- **Test the installed artifact, and prove you tested the installed artifact** — `.agents/notes/implemented/testing/2026-08-23-installed-python-wheel-black-box-ci.md:17` — the identity check (venv, no repo-relative cwd, no source/editable import, equal distribution versions, exactly pinned runtime dependency, executable inside the installed package) runs *before the first agent request*, "so a behavior pass cannot conceal that the wrong code ran."
- **A two-turn live-provider test** — `.agents/notes/implemented/testing/2026-08-23-installed-python-wheel-black-box-ci.md:27` — turn 1 writes an exact sentinel file through the platform shell, turn 2 reads it back; the test then verifies the file content, final responses, completed turn reasons, model-requested tool calls and the Zstandard-framed session log. One turn proves nothing about persistence; two turns do.
- **Electron's `close` event is not HTTP completion** — `.agents/notes/implemented/testing/2026-09-10-desktop-local-updater-qualification.md:43` — Electron 44 emits a writable `close` before response headers, so an inactivity deadline must be released by response completion, abort or error and refreshed by received bytes. A transport-level detail that silently breaks every timeout if assumed.
- **Whitelist fields in an update journal instead of redacting secrets** — `.agents/notes/implemented/testing/2026-09-14-desktop-installed-update-journal.md:13` — "unknown authentication values and private paths cannot be exhaustively enumerated," so raw errors, URLs, request headers and chat content are omitted and known error tokens become fixed classifications; storage failures propagate rather than claiming complete evidence.
- **Corpus shape from measured quantiles, not from a uniform synthetic** — `.agents/notes/implemented/testing/2026-09-28-session-corpus-performance.md:17` — rank `r` takes the first anchor at or above quantile `(r+1)/n`, so every synthetic quantile is at least the measured one, and all three dimensions share the rank ("a long Session is long in every dimension").
- **Re-run the benchmarks under a real memory cap** — `.agents/notes/implemented/testing/2026-10-07-memory-limited-benchmarks.md:13` — a cgroup v2 with `memory.max` 4/8 GiB and swap disabled, containing Vitest, every worker, the scaffold Host and Chromium, so page-cache eviction from Session logs shows up in the timings; `--max-old-space-size` cannot model it because the workers' resident memory is mostly native.
- **Turn a benchmark number into user impact** — `.agents/notes/implemented/testing/2026-10-07-scaled-benchmark-report.md:13` — a self-contained HTML report scales each measured median onto reviewed machine profiles using a *measured* storage/CPU split (`io = max(0, 1 − cpuMs/ms)`) and shows peak RSS as a share of 4 GB and 8 GB, with every default's source visible and adjustable — and it labels the output "estimates rather than measurements."
- **Bind loopback ports with `0` and make the fixture own the mapping** — `.agents/notes/implemented/testing/2026-08-24-session-log-snapshot-corpus.md:27` (also `.agents/notes/implemented/testing/2026-09-06-frontend-performance-budgets.md:15`) — the recorded URL/authority stays stable while the listener port is OS-assigned per sample.
- **Make the translation-pairing check mechanical** — `.agents/notes/implemented/testing/2026-06-19-real-api-e2e-ci.i18n.yaml:1` — per-heading `en:`/`zh:` hashes plus the exact re-record command. The mechanism is cheap and catches the failure mode (one language drifting) that a human reviewer never notices.
- **Do not require active plugins on `Loader.create()` alone** — `.agents/notes/implemented/simplification/2026-09-09-nontransactional-loader.md:33` — callers that need an activated plugin must *audit after settlement*; a plugin activation failure may leave new options and a failed fiber in place, and that is an accepted, documented consequence.
