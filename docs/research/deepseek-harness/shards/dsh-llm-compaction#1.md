# deepseek-harness / dsh-llm-compaction#1

## Shard shape

This shard is the whole `packages/compaction/` capability family of the DeepSeek Harness — 68 files across five packages that together implement *conversation compaction* (condensing older history into a summary when the context window fills). It is a layered design: `compaction/` is the **seam** (an abstract `CompactionEngine` service on `ctx.compaction`, the `compaction/*` session-event vocabulary, the tool-pairing boundary helpers, and the `compact-checkpoint` message marker); `compaction-basic/` is the **shipped backend** (pressure policy resolved per routed model, the LLM summarizer, and the bracket-first region transaction); `compaction-tool-result-pruner/` is an optional **model-free** first pass that trims oversized tool output; `compaction-image-offload/` is an optional executor that turns a provider's image-budget rejection into a durable, replayable omission of specific image occurrences; `command-compact/` is the human `/compact` surface over the seam. The pieces fit through a durable session **surface** (an append-only log plus a replaceable node list): compaction never deletes history, it appends a `user/message` with `surfaceOp: {op:'replace'}` that shadows a span, so replay reproduces the condensed conversation exactly. Triggering is driven by `ctx.tokenMeter` (one measurement service prices pressure, retention, range selection and the shrink check), `agent/pre-step` (proactive pressure) and `agent/request-error` (provider-confirmed context overflow → compact → retry).

### packages/compaction/compaction/src/index.ts
- Purpose: The abstract `CompactionEngine` service, `ctx.compaction` merge, `CompactionTrigger`, `ManualCompactionError` + its closed code set, and the `compaction/summary-error` waterfall event.
- Key abstractions: `CompactionEngine` (abstract), `CompactionAgentContext` / `ManualCompactAgentContext` (minimal agent surfaces that avoid depending on the agent package), `ManualCompactionErrorCode` = `busy | cancelled | changed | summary | commit | persistence`.
- Data flow: A backend implements `compactIfNeeded(agent, trigger, signal)`, `compactNow(agent, signal, sourceCommandId?)` and `compactRegion(start, end, agent, signal?)`; the seam owns no algorithm.
- Non-obvious design decisions: The seam depends on `dsh-session` and `dsh-llm` vocabulary deliberately ("Session and LLM vocabulary are part of the contract"), a documented deviation from the Cordis-only rule. The `compaction/summary-error` waterfall is **synchronous** and a listener may return `true` only *after* recording a durable input change — recovery must make durable progress, not just wish to retry.
- Edge cases / failure handling: `start`/`end` name an inclusive span by **surface position**, not numeric seq order — "replacements can make visible seqs non-monotonic"; both edges must be tool-pairing balanced. `compactNow` must synchronously start an idle task before any async work.
- Surprising: `ManualCompactAgentContext.runMaintenance` is declared here as a *required* capability — the seam needs the agent to guarantee "withholding later waking input until it settles" without importing the agent package.

### packages/compaction/compaction/src/types.ts
- Purpose: The `compaction/*` session-event vocabulary (declaration-merged into `SessionEventMap`) and the `CompactionResult` shape.
- Key abstractions: `compaction/start`, `compaction/summary`, `compaction/end`, `compaction/prune` — all **log-only** (no `surfaceOp`).
- Data flow: `compaction/summary` states the shadowed range/seqs/price; the *immediately following* `user/message` with `surfaceOp:'replace'` performs the actual surface replacement. "That adjacency is contractual."
- Non-obvious design decisions: The `compaction/prune` event defines the **shadow-price protocol**: "a surface `replace` event is priced by the metering event immediately before it ... so a pure consumer can subtract it without retaining per-node prices. The replacement MUST be appended synchronously right after this event." The `compaction/summary` payload carries `provider`, `model`, `maxTokens`, `usage` and a `rawOutput`/`llmStreamCall` discriminated union so the auxiliary call is reconstructable from log + code.
- Edge cases / failure handling: `compaction/end` carries an optional `error` string; a *failed* close deliberately leaves the unmatched start detectable.
- Surprising: `CompactionResult.shadowedRange` is documented as a surface-POSITION span — after a prior replace lands a fresh high-seq summary node at an older range's position, `start` can be **greater** than `end`; `shadowedSeqs` is the authoritative set.

### packages/compaction/compaction/src/tool-pairing.ts
- Purpose: Per-session cache of tool-call/result balance per surface *cut*, exposed as `toolPairingBalancedBefore(session, seq)` and `toolPairingBalancedAfter(session, seq)`.
- Key abstractions: `BalanceCache` keyed by a `WeakMap<Session, BalanceCache>`; `eventDelta` (+tool-call count, −1 per tool/result); `cutBalanced[i]` = "cut before surface node i is balanced".
- Data flow: `balanceCache` folds the unseen surface tail into the cached state, incrementing the in-progress tool-call count; a cut is balanced iff the running count is 0.
- Non-obvious design decisions: Balance is derived from **content in current surface order**, not from step markers, because "Compaction changes surface positions, so safe cuts are derived from tool-call/result content in current surface order rather than step markers." The cache is invalidated by `surface.replaceGeneration` and defensively rebuilt if the entry count regresses within one generation.
- Edge cases / failure handling: A `tool/result` with no preceding open call, or a surface seq with no matching log event, throws "corrupt surface" rather than answering — the fold validates the whole unseen tail *before* mutating the live cache, so a corrupt append cannot leave a partially advanced state.
- Surprising: Repeated queries read **zero** events (the balance array is precomputed per cut); the tests assert the exact event-read count to pin that.

### packages/compaction/compaction/tests/tool-pairing.spec.ts
- Purpose: Exhaustive tests of the balance cache — classification of cuts, cache refresh behaviour, event-read counts, and corrupt-surface rejection.
- Key abstractions: `before()/after()` helpers that resolve a seq *through the current surface* (so a stale seq throws).
- Data flow: builds sessions with tool steps, then asserts balance at each cut; a fake session with a counting `eventAt` pins the cache's read behaviour.
- Non-obvious design decisions: The cache-refresh test asserts exact `eventReads` counts (3 → 3 → 3 → 4 → 6 → 7), proving "does no event reads for unchanged or log-only growth, folds only appended nodes, and rebuilds on replace". A `turn/end` log-only append must not cause a single event read.

- Surprising: "a neutral node inside an open tool pair is unbalanced" — an idle `user/message` injected *between* a tool call and its result is NOT a safe cut, because the open call still crosses it.

### packages/compaction/compaction-basic/README.md
- Purpose: The shipped backend's full reference — the four design commitments, the tuning table, the trigger/overflow mechanics, the region transaction, and an explicit Model-Experience section (what the model sees / token effect / KV-cache effect).
- Key abstractions: `BasicCompactionEngine`, the `thresholdTokens`/`retainTokens` budget, the `modelPolicies` per-route override table, the `compaction/summary-error` waterfall.
- Data flow: `agent/pre-step` → pressure check → prune (optional) → select span → summarize → replace; `agent/request-error` → overflow → force one maximal balanced head reduction → retry.
- Non-obvious design decisions: "**Summarization reuses the provider's warm prefix**" — replaying the system prompt, the last routed request's tools and the shadowed-region messages byte-for-byte makes the auxiliary call a genuine prefix of the conversation. - Edge cases / failure handling: misconfiguration fails fast at load; the automatic listener *warns once per routed target* and skips proactive compaction until fixed, while provider-confirmed overflow recovery stays available; a summarization failure leaves the latest durable surface and the turn continues with over-budget history.
- Surprising: The Model-Experience section states the KV-cache effect precisely: "Each checkpoint invalidates reuse from the first replaced history token; the unchanged request prefix before that range remains reusable." Routing the summarizer to a *different* provider/model forfeits this reuse.

### packages/compaction/compaction-basic/src/index.ts
- Purpose: `BasicCompactionEngine` — the plugin entry: the automatic listeners, the trigger dispatch, the per-routed-model policy resolution, and the manual `compactNow` path.
- Key abstractions: `BasicCompactionEngine extends CompactionEngine`; `static inject = ['llm','tokenMeter','sessions']`; the `summarize()` protected hook; `routedTarget()` / `conversationTarget()` / `reservedCompletionTokens()` helpers.
- Data flow: `agent/pre-step` → `compactIfNeeded(agent,'pressure')`; `agent/request-error` (code `CONTEXT_WINDOW_EXCEEDED_CODE`) → `compactIfNeeded(agent,'context-overflow')` → `{kind:'retry'}`.
- Non-obvious design decisions: the summarizer's target is the **durable routed request** (`session.requestHeader()?.config`), not the agent options — "Model discovery (`listModels()`) is never consulted for policy; only the durable route's capacity matters." The pressure budget subtracts the *routed output reservation* (`agent.session.requestHeader()?.config.maxTokens`, else the adapter default, else 0). The overflow path bypasses the threshold and retention policy entirely to "force one useful balanced reduction".
- Edge cases / failure handling: A `TargetPressureConfigError` is warned **once per routed target** (`warnedPressureConfigTargets` Set) and the turn continues. On overflow, a retry is authorised **only if** `session.surface.replaceGeneration` advanced — a backend that reports success without replacing the surface gets no retry. A model-free prune that landed before a later summary failure is accepted as sufficient retry proof; cancellation always wins.
- Surprising: the overflow retry counter is cleared by a successful `assistant/message` event, not by a turn boundary — "A successful response starts a fresh overflow-recovery sequence even when tool calls continue the same turn into another request."

### packages/compaction/compaction-basic/src/region.ts
- Purpose: The shared **bracket-first region transaction** and the retention/range selection — the heart of the backend.
- Key abstractions: `selectCompactableRange(session, measurement, retainTokens)`; `compactSurfaceRegion(deps, session, start, end, agent, options, signal)`; the `StabilityCheck` pair (`assertWholeSurfaceUnchanged` for automatic, `assertSelectedSpanStable` for manual).
- Data flow: validate span → check durable lock → append `compaction/start` → prepare (price + build replay input) → summarize (with the `compaction/summary-error` recovery loop) → revalidate stability → append `compaction/summary` + the replacement `user/message` → append `compaction/end` → optional flush.
- Non-obvious design decisions: **`compaction/start` is appended synchronously before summarization yields, so the durable marker IS the lock.** Exactly one `compaction/end` attempt is made; a failed close deliberately leaves the unmatched start as the busy signal. The shrink check compares the framed summary's *route* price against the span's *route* price — "the real question — does the replacement lower the next request's pressure." Logged shadow prices deliberately stay on the route-independent heuristic so the O(1) projection fold agrees with its own appends, while retention/range/shrink read the route-priced `tokens`.
- Edge cases / failure handling: A `system/message` at surface node 0 is never shadowed. The cut is rounded head-ward until it is tool-pairing balanced. A stale unmatched `compaction/start` older than the newest `session/end-seed` is treated as evidence from a prior lifecycle and does **not** block. The manual path uses `turn: null`, accepts append-only context outside its span, and flushes every closed attempt.
- Surprising: `inspectCompactionEntryState` scans the log tail backwards for three independent facts (open turn, unmatched compaction start, latest end-seed) and stops only when all three are known — a purpose-built three-way tail scan rather than a general "current state" query.

### packages/compaction/compaction-basic/src/summarizer.ts
- Purpose: The default one-shot `ctx.llm.stream()` summarizer, the fixed compaction instruction, and the durable checkpoint framing.
- Key abstractions: `COMPACTION_INSTRUCTION` (the eight-section Markdown template); `CHECKPOINT_PREAMBLE`; `SummarizationInput {tools?, messages}`; `SummaryResult` with the `llmStreamCall: true | undefined` discriminator.
- Data flow: replay `input.messages` + `input.tools` + `agent.session.toolHistory()` → append the instruction as the **final user message** → stream → `BlockAssembler` → text-only projection → `frameSummary()`.
- Non-obvious design decisions: "Keeping the conversation's own system prompt, tools, and message prefix in front of it makes the auxiliary call a genuine prefix of the last routed request, so the provider's KV cache is reused instead of invalidated." The instruction is delivered as a *user* message, not a summarizer system prompt, for the same reason. The instruction explicitly tells a prior checkpoint to be *merged*, not copied forward.
- Edge cases / failure handling: `finishError` maps terminal finishes to fail-closed errors: `error`/`aborted` → `LlmError`, `max-tokens` → a `MAX_TOKENS` error ("incomplete checkpoint"). Reasoning and tool-call blocks are excluded from the checkpoint but kept in `rawOutput`; **image output fails with `UNSUPPORTED_CONTENT` rather than silently disappearing**; empty text output fails.
- Surprising: the summarizer target resolution order is configured pair → **latest logged request target** → `AgentOptions` pair, and the error message names all three ways to fix it. The instruction also carries `GenerateOptions.purpose = 'compaction'`, which lets a provider or a budget layer tell auxiliary calls apart.

### packages/compaction/compaction-basic/src/config.ts
- Purpose: Load-time validation of the backend config, per-routed-model policy merging, and the capacity→budget scaling.
- Key abstractions: `resolveConfig(config)`; `resolveTargetPolicy(config, target)`; `resolveCompactSpec(policy, contextWindow, reservedCompletionTokens)`; `TargetPressureConfigError`.
- Data flow: config → validated defaults + `modelPolicies` table → per-target merged policy → concrete `thresholdTokens`/`retainTokens`.
- Non-obvious design decisions: The trigger is `floor(min(W × thresholdRatio, W − O − B))` — the **routed output reservation is subtracted from the window** before the ratio is applied, so a model with a big `maxTokens` compacts earlier. Unknown config keys are rejected ("Reject stale or misspelled keys before defaults can hide them"). `summarizationProvider`/`summarizationModel` must be set **as a pair** — both empty (inherit) or both non-empty.
- Edge cases / failure handling: duplicate per-model policies fail at load; `retainRatio`/`retainTokens` are mutually exclusive and both must be below the resolved threshold; a reserve that leaves no message budget, or a headroom that leaves no pressure budget, throws a target-specific `TargetPressureConfigError` whose message names the exact remedy.
- Surprising: `maxTokens` defaults to the resolved `headroomTokens` (65536) but a *zero* headroom requires an explicit positive `maxTokens` — the headroom serves double duty as the summary output cap, and a zero headroom would silently mean a zero-length summary.

## Ideas worth stealing

- **Reuse the provider's KV cache by making the auxiliary summarization call a genuine prefix of the last request** — `packages/compaction/compaction-basic/src/region.ts:544` and `packages/compaction/compaction-basic/src/summarizer.ts:145` — the summary call replays the conversation's own system head, its active tool schemas and the shadowed messages byte-for-byte, and appends the compaction instruction as the **final user message** rather than as a summarizer system prompt. August currently spends a whole extra request per compaction with no prefix reuse; replaying the tail of the live request and appending one instruction would let the provider serve the whole summary from the warm prefix. The test that pins the property is `packages/compaction/compaction-basic/tests/compaction-basic.spec.ts:1463`.

- **A durable log bracket as a lock, where a crashed close deliberately leaves a detectable orphan** — `packages/compaction/compaction-basic/src/region.ts:210` (append `compaction/start` synchronously *before* the summarizer yields) and `packages/compaction/compaction-basic/src/region.ts:245` (exactly one `compaction/end` attempt) — a crash mid-compaction leaves an unmatched start marker instead of a false "done". The staleness rule at `packages/compaction/compaction-basic/src/region.ts:313` (an unmatched start older than the newest `session/end-seed` is evidence from a prior process lifecycle and does **not** block) is the part August would need: without it, one crash permanently bricks the session. August's `turn_end`/`turn_outcomes` ledger is the analogous durable signal.

- **Two prices: route price for decisions, heuristic price for the log** — `packages/compaction/compaction-basic/src/region.ts:376` — pressure, retention, range selection and the shrink comparison all read the *route-priced* token count (which knows about image visual tokens), while the *logged* shadow price stays on the route-independent heuristic, because "the O(1) projection fold stays in agreement with its own appends". August currently has one estimator; a compaction/relief decision that wants to compare "will this help on this route" against a log that must stay replay-stable needs exactly this split. The two-price discipline is proven in `packages/compaction/compaction-basic/tests/compaction-basic.spec.ts:2249`.

- **Refuse a compaction that does not shrink what it replaced** — `packages/compaction/compaction-basic/src/region.ts:418` — the framed summary's price is compared against the replaced span's route price, and a non-shrinking summary is a hard error rather than a no-op. The reasoning in the comment is the transferable part: the checkpoint is text-only, so its fixed-heuristic price *is* its route price, which makes the comparison ask the real question — "does the replacement lower the next request's pressure?".

- **The shadow-price protocol: a metering event immediately before every replacement, so a pure consumer can subtract the shadowed cost without per-node state** — `packages/compaction/compaction/src/types.ts:73` (the event contract) and `packages/compaction/compaction-tool-result-pruner/src/index.ts:160` (the emitter) — the protocol states the *exact* replaced range and its heuristic token price, and the contract is that the replacement MUST be appended synchronously right after. August's own "prune old tool outputs" path would benefit: today a consumer that wants to know "how many tokens did the archive actually free" has to recompute per-node prices; with this protocol it subtracts one number.

- **Tool-pairing balance computed over the current surface, not the raw log, with a per-generation cache** — `packages/compaction/compaction/src/tool-pairing.ts:29` (`eventDelta`) and `packages/compaction/compaction/src/tool-pairing.ts:112` (the two exported helpers) — because a compaction replaces a span, visible seqs stop being monotonic, so "safe cuts are derived from tool-call/result content in current surface order rather than step markers". The `WeakMap<Session, BalanceCache>` keyed on `replaceGeneration` means repeated checks read zero events, and a corrupt surface (a `tool/result` with no open call) *throws* rather than answering. August's compaction keeps a head verbatim and folds the rest; this is exactly the boundary check that prevents a cut from splitting a `tool_use_id` from its result.

- **A retry is authorised only after a durable state change, not after the recovery function returns** — `packages/compaction/compaction-basic/src/index.ts:229` — the overflow path compares `session.surface.replaceGeneration` before and after and returns `{kind:'retry'}` only if it advanced. This is the guard against a recovery that "succeeded" without changing anything. August's `_stuckRequestEscape` ladder and its `_runawayBudget` backstop both need a comparable "did the world actually change?" predicate, and the code here shows the cheap version of it (a monotonically increasing generation counter on the surface).

- **A model-free prune first, re-measure, and skip the LLM call entirely if the pressure is already relieved** — `packages/compaction/compaction-basic/src/index.ts:327` — the pruner runs before a summary range is chosen (lines 323-326), the session is re-measured through the same meter, and if the re-measured total is under the threshold the compaction returns `null` having made zero model calls. August's budget ladder spends a whole model round on compaction; this ordering means the cheapest possible relief is tried first and the expensive path is skipped when it suffices.

- **The trigger budget subtracts the routed output reservation** — `packages/compaction/compaction-basic/src/config.ts:191` — `thresholdTokens = floor(min(W × thresholdRatio, W − O − B))` where `O` is the tokens the provider will charge for the answer, taken from the durable request envelope's `maxTokens` and falling back to the adapter default. A naive "80% of the window" rule over-packs the prompt by the size of the reply; this one cannot.

- **Warn once per routed target for a bad capacity configuration, and keep the overflow path alive** — `packages/compaction/compaction-basic/src/index.ts:167` — the `warnedPressureConfigTargets` Set means a misconfigured model produces one actionable warning, not one per step, and the provider-confirmed overflow recovery still runs even while proactive compaction is skipped. The error message names the remedy ("configure contextWindow on that adapter model") rather than just the fault.

- **Durable image offload as a *projection* plus a decision event, so the original message is never mutated** — `packages/compaction/compaction-image-offload/src/projection.ts:40` — the decision names `(seq, depth-first image index)` pairs; the derived message changes; the logged message keeps its content forever; a *second* offload of the same occurrence is a hard error. The "durable surface repair, not a provider retry" framing at `packages/compaction/compaction-image-offload/src/index.ts:29` (it spends no retry budget and logs no `llm/retry` event) is the part worth stealing: a model that is over its image budget should not burn the provider's retry budget on a repair that will never succeed.

- **A closed failure taxonomy mapped to stable human sentences, so the UI never parses an exception** — `packages/compaction/compaction/src/index.ts:35` (`busy | cancelled | changed | summary | commit | persistence`) and `packages/compaction/command-compact/src/index.ts:24` (the mapping) — each code has one fixed sentence that says what to do next ("Inspect the current session state before retrying"), and anything outside the set is rethrown rather than silently converted. August's `_stuckRequestEscape` and `turn_outcomes` ledger would benefit from the same closed set: a stable code set is what makes a "stop reason" badge possible.

- **One fixed summary schema, delivered as a template the model must fill, with a "do not mention the compaction" rule and a merge rule for prior checkpoints** — `packages/compaction/compaction-basic/src/summarizer.ts:32` — eight named sections in a fixed order, "(none)" for empty sections, exact identifiers/paths/error strings preserved verbatim, and an explicit rule that a prior `<compacted-summary>` must be *merged*, not copied forward. The "never drop a section" rule is what makes the downstream checkpoint safe to parse; August's `<<compressed_summary` note has no such fixed schema.

- **The checkpoint preamble that tells the model not to acknowledge the checkpoint** — `packages/compaction/compaction-basic/src/summarizer.ts:70` — "Treat the captured context as established background and build on it without restating it. Continue the task directly from the messages that follow, without acknowledging this checkpoint." August's own compaction note currently ends with a footer admitting that decisions were not analysed; a preamble that suppresses the model's restatement of the summary is a cheap way to recover the tokens a verbose re-read would cost.

- **Code-point (not UTF-16 unit) slicing for tool-output trimming, with a config invariant that the emitted size is provably smaller** — `packages/compaction/compaction-tool-result-pruner/src/config.ts:27` and `packages/compaction/compaction-tool-result-pruner/src/config.ts:58` — `headChars + marker + tailChars ≤ thresholdChars` is validated at load, so a valid config can never grow a result or need a second pass. August prunes tool output too; the surrogate-pair hazard on Windows-emoji output and the "provably converges in one pass" invariant are both transferable.

- **Drain in-flight handlers before unregistering, so an aborted command's durability work still completes** — `packages/compaction/command-compact/src/index.ts:97` — the lifecycle effect yields a drain *before* it registers the command, because "composite teardown is LIFO, so no new invocation can enter while already-started handler promises quiesce". August's `/compact`-equivalent and its Tauri update waiter share this exact hazard (the AGENTS.md note about the waiter outliving the pid that scheduled it is the same class of bug).

- **Measure once per decision, and assert it** — `packages/compaction/compaction-basic/tests/compaction-basic.spec.ts:852` — one `ctx.tokenMeter.measure(session)` call feeds pressure, retention, range selection and the shrink baseline; the test asserts `measure` was called exactly once. August's own AGENTS.md notes a class of bug where "the loop's ONE error string" is read by four consumers and can disagree; a single-measurement-per-decision rule with a test that counts the calls is the cheap defence.

## Uncertainties

- **The `ctx.tokenMeter` API is used but not defined in this shard.** `measure(session)` returns `{nodes[], totalTokens, baseline, surfaceDeltaTokens, ...}` and each node carries both `tokens` (route-priced) and `heuristicTokens`. - **`session.surface` semantics.** I relied on the shard's own usage: `nodes` is the ordered list of current surface seqs, `replaceGeneration` increments on a replacement, `contentGeneration` increments on a content projection. The definition lives in `packages/core/session/`, a different shard.

- **The `agent/request-error` and `agent/pre-step` event contracts** are declared in `packages/core/agent/` (and the agent loop in `packages/core/agent-loop/`), not in this shard. I read the *listeners* this shard installs, not the emitters.
