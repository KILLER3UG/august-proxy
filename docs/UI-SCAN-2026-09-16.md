## 2. Verified functional/rendering bugs

**B1 — Bots-rail rows collapse to height 0 and overlap the Projects/Tasks sections.**
DOM geometry on `/board`: `.august-bot-row` measures `height:0` while its 28–50 px children
overflow visibly → "Assistant · 11" and "wfwfw / 5d ago" collide with "Projects 11".
Cause: `sessionRow` in `src/lib/motion.ts:34` animates `height:0 → 'auto'` inside
`AnimatePresence mode="popLayout"` (`src/components/sidebar/BotsRail.tsx:528`); with
popLayout + layout, the auto-height measurement settles at 0. Fix: drop `mode="popLayout"`
for this list, or animate `opacity/x` only (height collapse is only needed on exit).
Evidence: `shots/v2-board.png`, `shots/crop-sidebar-board.png`.

**B2 — Titlebar never leaves chat context.**
`ChatTitlebar.tsx:109` renders `session?.title ?? "New chat"` on *every* route; DOM confirms
header = "New chat" while viewing Board, Runs, History, Automations, Live, Settings. The app
window title (Tauri) inherits the same wrong label. Fix: route-aware header ("Board",
"Runs", "Settings → Appearance", session title only on `/c/:id`).

**B3 — Opening an existing session can render the empty state; messages appear only after reload.**
`/c/wb_…7788` (API reports `messageCount:11` → `/api/sessions/:id/messages` 200 + 11 rows)
rendered zero `.chat-message-text` nodes and the "What should we work on?" hero. After a
navigation reload the same session hydrated 2 messages correctly. Also: after sending a turn
in the bot chat, the completed transcript visually reverted to the hero until reload.
The reconnect-hydration guard (`ChatThread.tsx:830-870`) plus persist/restore race is the
likely area — worth a targeted repro; this is the single most user-trusting-breaking bug found.

**B4 — Workbench drawer overlays the chat column instead of resizing it.**
Geometry: chat column right edge = 1418 (full viewport) while drawer content occupies the same
pixels (`elementFromPoint` at message right edge hits `drawer-section-text`). Long lines get
hidden behind the panel mid-word with no wrap/ellipsis. Fix: flex the drawer as a sibling with
chat reflow (or at minimum `max-width` the thread to the free space). Evidence `shots/w-after.png`.

**B5 — Settings rail bottom item clipped.**
"Review Inbox · 1" renders cut mid-label at the rail's bottom edge on every settings screen;
no bottom padding/fade. Evidence: all `s-*.png`.

**B6 — History plural bug.** `HistoryPage.tsx:114` — `{messageCount ?? 0} msgs` → "1 msgs".

**B7 — Indexing settings is an unmigrated placeholder.** Live copy: "This section hasn't been
migrated to the new visual style yet." Same pattern to grep for across the registry before
shipping. Evidence `shots/s4-indexing.png`.

**B8 — ErrorBoundary crash screen is raw.** Caught during lazy-chunk refetch: black void,
bare sentence, unstyled Details/Reload buttons — the app's worst moment looks the roughest.

## 3. UI/look improvement suggestions (ranked)

### 3.1 Give the product a real brand presence — the token system exists, the UI hides it
`styles.css` defines a considered palette (`--dt-primary #6f9bff` dark / `#2f6df6` light,
success/warning/info/destructive tiers, code surfaces) yet **every visible screen is near-pure
monochrome**; the only color on the boot screen is a tiny green context dot. Result: "generic
dark ChatGPT clone". Concrete moves:
- Primary actions (Send, Launch, + New, Apply) → filled `--primary` with `--primary-foreground`;
  today Send is a gray circle (lowest-emphasis element in the composer) and "Launch agents"
  (muted indigo) vs "+ Add" (saturated blue) are two different primaries on one page.
- Introduce a **status color language** on Runs/Board/Workbench: working=info-blue,
  awaiting-approval=warning-amber, completed=success-green, failed=destructive. The Runs
  filter pills, stat tiles and board lanes are all colorblind-neutral today.
- Raise the "AUGUST" wordmark and `?` from their ~2:1 opacity ghost to real chrome, or drop
  the wordmark entirely and let the sidebar brand carry identity.

### 3.2 Contrast tiers are systematically too low
Sidebar counts at `text-sidebar-foreground/25`, section labels `/40`, previews `/30` against
`#141414` fail WCAG AA for their size class; in light mode "47.8 t/s" (~2.8:1) and the send
glyph (~2.6:1) fail AA/3:1. Define and enforce three sanctioned tiers (e.g. /70 secondary,
/55 tertiary, /40 only for ≥14px decorative) as utilities and sweep `text-*/25|30|35` call
sites. Same for card borders (`#262626` on `#0F0F0F` is invisible — empty-state cards read as
smudges; add a hairline `+` 1 step of elevation instead).

### 3.3 Composer polish (highest-frequency component in the app)
- The `+` attach icon sits orphaned on its own line between input and toolbar → merge into the
  toolbar row's left cluster.
- "Model" pill is bold while "Full access"/"Medium" are regular — same control type, one
  visual weight.
- The context ring (tiny circle + green dot) is cryptic → show `9%` numerals or a tooltip.
- Model pill truncates mid-token (`…north-mini-cod…`) with no tooltip; model picker cascade has
  **no search field**, ~80 px rows, provider dim/undim contrast unclear (disabled vs hover?),
  and the flyout column misaligns top/bottom with its parent. Add search + 28-32 px rows +
  shared header, show last-used/default first.

### 3.4 Empty/loading state discipline
- Never show skeleton + hard zeros together (Runs page today).
- Skeletons should mimic real card anatomy (stat tiles + rows) to kill layout shift.
- Hero screens are top-anchored leaving ~50% dead void (chat hero, Automations, Board);
  vertically center the hero+composer block, and give empty boards/lists one CTA + one line of
  guidance instead of a faint "Drop cards here".
- Runs/Bot profile "sad-face" generated avatar reads as an error; use neutral avatar + an
  explicit status line.

### 3.5 Sidebar information architecture
- "Assistant" appears twice (workspace header and bot-group label) → rename group to the bot's
  display name or "Direct messages".
- Two search fields stacked (sessions + bots) — one search with type filter.
- Destructive "delete all tasks" trash sits always-visible beside benign "+"; move into a
  `⋯` menu (same rule as Model-settings' icon-only trash buttons — add labels/confirm).
- Section headers' trailing icon clusters don't share a right rail; fix widths or hide counts
  into the same 16px action column.

### 3.6 Command palette
`ALL-CAPS` labels hurt scanning; per-row shortcuts are missing (footer legend only); "CHAT"
group is overloaded with export/mode/memory commands; dead-center placement. → Sentence case,
right-aligned key hints per row, tighter groups (Chat / Modes / Panels / App), anchor ~25% from
top, selected-row fill needs +2 steps of contrast.

### 3.7 Live voice page
Flat gray orb = "placeholder", not a visualizer; wire it to input level (ring pulse or bars),
add explicit states idle→connecting→listening→speaking→muted, mute needs a visible muted form,
"End" scissors → phone-hangup glyph, disable Mute/PtT while idle, and give speech a transcript
column (the left strip says "No tool activity yet." — nowhere for spoken text to appear).

### 3.8 Update lifecycle (opening-to-updating flow)
The chat-anim "what's new" conversation and the modal update flow (Downloading % → ready →
Restart to update, with "Later") are a genuinely good pattern — keep. Look fixes: in
browser/web mode `/settings/app-updates` shows "Version **web**" + a dead-end sentence; render
a disabled-but-explanatory card instead. During download the progress lives only inside the
modal — mirror it as a slim bar/`↓` badge on the titlebar so users can keep working.
"Restart to update" is the only destructive-adjacent moment; give it the primary treatment and
show installed→target version inline (v0.18.11 → v0.18.12).

### 3.9 Light theme consistency
Light mode re-themes correctly (no dark islands) but: composer card uses shadow while every
sibling uses 1px borders (pick one elevation strategy), unselected theme cards and presets lack
a visible selected state, the floating "dark" chip duplicates the segmented selection, and
Apply/Discard/Clear stay enabled while "In sync" (gate them on draft state).

### 3.10 Small but free
- Tooltips on every truncated id/model (`…step-3.7-flash:free`).
- `rober` monospace in hero subtitle but sans in header/composer — one treatment.
- Monospace for Base URL / endpoint fields (already used elsewhere in settings).
- History rows: real last-message preview already exists in code — fix the seeded "Conversation
  started." data or hide subtitle when it equals the seed.
- Model-settings: mask API key as fixed-length `••••last4` (current dot-run leaks length); no
  "remove key" affordance; two identical refresh icons with different scopes; green dot status
  without legend/error state.
