# deepseek-harness / dsh-platform#3

## Shard shape

This shard is the harness's **shared-mechanical-primitive layer plus one durable registry**. It contains two package groups: `packages/util/*` (19 leaf packages, ~1/3 of the tree's utility surface) and `packages/workspace/workspace` (a single service package). The `util/` packages are all *libraries, not plugins* — they take no `ctx`, register no service, emit no events, and hold no cross-call state; each one owns exactly one mechanical question and leaves business semantics to the consuming capability. The four that matter most to a harness are: `values` (lossless-JSON validation plus `PartialArguments`, the lazy streaming reader for model tool-call arguments), `output-retention` (bounded model-facing tool output with exact omission metadata), `timeout` (deadline arithmetic, signal fusion, and timeout-versus-cancel classification), and `http-proxy` (one resolved outbound-proxy policy installed as undici's global dispatcher). Around those sit path/identity/collection primitives: `atomic-write` (atomic replacement + a cross-process writer lock with dead-holder takeover), `workspace-path` (the `dsh-resource://file/…` address grammar and browser-safe path display helpers), `home-paths` and `launch-environment` (where user data lives and which layer supplied an env value), `native-command` (shell-free host command execution and desktop path opening), plus `brand`, `chunked-list`, `code-language`, `crypto`, `deque`, `lazy-require`, `package-manifest`, `plugin-market-index`, and `time`. `packages/workspace/workspace` is the one *stateful* member: a Cordis service (`ctx.workspaceRegistry`) that keeps an ordered durable list of project directories and the sessions that ran in each, with header-validated membership, a two-write pending-mutation marker for crash recovery, and an archive/pin surface that dispatches two Host events to ask what is still running before it hides a session. The two groups connect only through `workspace-path`'s path vocabulary and `brand`'s nominal `WorkspaceId`.

### packages/util/atomic-write/README.md
- Purpose: the package page for atomic file replacement and the cross-process writer lock.
- Key abstractions: `writeFileAtomic(filename, content, { mode, dirMode? })` and `withFileLock(filename, operation, { waitMs?, signal? })`.
- Data flow: content → random-suffix `wx` sibling → `rename` over the target; a writer lock serialises read-render-commit cycles.
- Non-obvious design decisions: `mode` is **required** "so the permission decision stays visible at every call site" (packages/util/atomic-write/README.md:89); the temp inode carries the mode through the rename, so narrowing a wider-permission file has no chmod race. Readers never take the lock because the rename commit is atomic. A contender deletes a lock only when the recorded PID is provably gone — "age cannot distinguish a crashed owner from a paused live writer, but a missing process can" (packages/util/atomic-write/README.md:91).
- Edge cases / failure handling: Windows `EACCES`/`EBUSY`/`EPERM` on rename retried with bounded backoff; the lock's parent directory must already exist; an empty/incomplete lock record or a reused PID is waited for, never taken over.
- Surprising: a Windows non-interactive session has no `explorer.exe` fallback implemented, and the whole package is "atomic, not durable" — no `fsync` of file or parent directory (packages/util/atomic-write/README.md:124).

### packages/util/atomic-write/src/index.ts
- Purpose: zero-dependency atomic file replacement and cross-process writer coordination.
- Key abstractions: `writeFileAtomic`, `withFileLock`, `WriteFileAtomicOptions { mode, dirMode? }`, `FileLockOptions { signal?, waitMs? }`.
- Data flow: `mkdir` parents → write `<filename>.<12 hex>.tmp` with flag `wx` and the caller's `mode` → `rename` over the target; on failure the temp is `rm`'d and the error rethrown. The lock is a `<file>.lock` sibling created with `wx` holding `<pid>\n`; the operation runs inside a `try/finally` that removes it.
- Non-obvious design decisions: the `wx` open "refuses to follow a symlink planted at the temp path" (packages/util/atomic-write/src/index.ts:67-68), and the rename "replaces a symlinked target itself instead of writing through to its referent" (packages/util/atomic-write/src/index.ts:70-71). `DEFAULT_LOCK_WAIT_MS = 2_000` is documented as "the floor for an operation that does file work alone" (packages/util/atomic-write/src/index.ts:193-197) — a holder whose cycle includes a network round trip must state a longer `waitMs`, otherwise it fails every other writer of that file. Takeover is guarded by a **claim file** named after the hash of the lock record, so contenders that read the same record serialise on one claim and a takeover can never remove a lock another contender acquired afterwards.
- Edge cases / failure handling: `holderExited` requires a strict `^\d+\n$` record, rejects PID 0 and out-of-int32 PIDs, and refuses to take over its own PID; `EPERM` from `process.kill` means the holder exists under another user, so it is waited for. `isLockContention` treats `EPERM` as contention only when a fresh `lstat` confirms the lock path exists, and Windows retries one *unconfirmed* `EPERM` because the holder can release between the exclusive create and the probe. A repeated unconfirmed `EPERM` is rethrown. The lock wait is abortable (`await wait(delay, undefined, { signal })`).
- Surprising: the takeover claim is removed in a `finally` whose failure is swallowed, on the reasoning that "a claim left behind names a record that is no longer the lock, so it blocks no later takeover" (packages/util/atomic-write/src/index.ts:174).

### packages/util/atomic-write/tests/atomic-write.spec.ts
- Purpose: the spec for atomic replacement and writer locking.
- Key abstractions: mocks `node:fs/promises` to inject rename/rm/writeFile failures; `probeExited` stubs `process.kill` to make a PID look absent.

- Surprising: the "keeps its own lock when the runtime cannot probe itself" case exists because "the browser Worker's process shim reports its own PID as absent" (packages/util/atomic-write/tests/atomic-write.spec.ts:371).

### packages/util/chunked-list/README.md
- Purpose: persistent append-only lists with bounded copying.
- Key abstractions: `ChunkedList<T> { values, previous? }`, `appendChunkedList`, `iterateChunkedList`, `chunkedListSchema(valueSchema)`.
- Data flow: append copies at most one 64-value chunk and shares older nodes; iteration walks the `previous` chain.
- Non-obvious design decisions: the newest chunk holds up to 64 values, so "the capacity controls storage layout, not total list length" (packages/util/chunked-list/README.md:48) and appends are O(1) amortised while iteration is O(N) with O(N/64) scratch. The empty list is `undefined`, not an empty object.
- Edge cases / failure handling: the Zod checkpoint schema is recursive and `.strict()`, rejecting empty or oversized chunks, invalid values, and unknown fields; `.optional()` is needed when the containing field also permits an empty list.
- Surprising: values are retained *by reference*, so callers must treat them as immutable (packages/util/chunked-list/README.md:28) — the list is persistent, not deep.

### packages/util/chunked-list/src/index.ts
- Purpose: persistent append-only list with bounded copy cost and JSON checkpoint validation.
- Key abstractions: `ChunkedList<T>` (values + `previous` link), `appendChunkedList`, `iterateChunkedList`, `chunkedListSchema`.
- Data flow: `appendChunkedList` returns a new head whose `previous` points at the old head when a chunk is full, otherwise a new array copying the old chunk's values.
- Non-obvious design decisions: `CHUNK_CAPACITY = 64` is a single constant that "governs append rollover and recursive Zod validation" (packages/util/chunked-list/README.md:48) — the runtime layout and the persisted format are deliberately the same number. `iterateChunkedList` collects the chunk chain into an array and reverses it, spending O(N/64) scratch so that iteration is in insertion order.
- Edge cases / failure handling: the schema is `z.lazy()`-recursive and `.strict()`; it rejects an empty chunk, a chunk longer than 64, a bad value, and any unknown member.
- Surprising: an empty list is `undefined` rather than an empty head, so `appendChunkedList(undefined, v)` and `iterateChunkedList(undefined)` are the two ends of the type.

### packages/util/chunked-list/tests/chunked-list.spec.ts

### packages/util/code-language/README.md
- Purpose: the repository's single file-extension → syntax-highlighting language table.
- Key abstractions: `languageForPath(path)`, `readLangHintForPath(path)`, `CODE_HIGHLIGHT_EXTENSIONS`.

### packages/util/code-language/src/index.ts
- Purpose: the one extension→language table shared by the Client code surfaces and the Host read card.

### packages/util/crypto/src/index.ts
- Purpose: RFC 9562 v4 UUID minting and chunked base64 encoding that work in every shipped context.
- Key abstractions: `Uuid` (template-literal type), `randomUUID`, `bytesToBase64`.

### packages/util/deque/README.md
- Purpose: amortised constant-time queue operations with bounded vacant storage.
- Key abstractions: `Deque<T>` with `pushBack`, `pushFront`, `popFront`, `size`, `clear`.
- Data flow: entries live in a circular array with a `head` cursor and a `count`.

### packages/util/deque/src/index.ts
- Purpose: zero-dependency circular deque.
- Key abstractions: `Deque<T>` over a `T | undefined` buffer with `head`/`count`.
- Data flow: `pushBack` writes at `head+count` modulo the buffer length; `pushFront` decrements `head`; `popFront` reads, clears the slot, advances `head`, and compacts.
- Non-obvious design decisions: `MIN_CAPACITY = 16` is the floor; `compact()` halves the buffer once the live count reaches a quarter of capacity, and `clear()` allocates a *fresh* buffer so the old storage (and everything it referenced) is released.
- Edge cases / failure handling: `popFront` on an empty deque returns `undefined`, which is why `size` is the emptiness predicate.
- Surprising: `popFront` clears the slot before advancing, so a popped object is collectible immediately even though the buffer itself is retained — the test asserts the removed reference is absent from the backing storage.

### packages/util/http-proxy/src/install.ts
- Purpose: the transport half — owns undici's global dispatcher and the process-wide record of the active policy.
- Key abstractions: `ProxyRoute` (proxied arm carries the dispatcher; direct arm is a shared singleton), `proxyRouteFor`, `applyPolicyEnv`, `writeProxyEnv`, `createPolicyDispatcher`, `installGlobalProxy`, `proxyEnvironmentForChild`, `installProxyFromEnvironment`, `clearedProxyEnv`.
- Data flow: resolve → report diagnostics → install a dispatcher whose per-origin `factory` consults `proxyForUrl` → publish the policy into `process.env` for children → dispose restores the previous dispatcher, policy, and environment.
- Non-obvious design decisions: `ProxyRoute`'s proxied arm carries the *dispatcher already routing*, "so a caller that branches on the answer needs the transport that answer assumed, or an install or disposal landing between the two would send the request somewhere the branch did not clear" (packages/util/http-proxy/src/install.ts:42-45). `writeProxyEnv` snapshots **every** name before writing any, because "Windows folds environment names case-insensitively, so reading the uppercase spelling after writing the lowercase one would read back the value just written and restore the policy instead of the user's environment" (packages/util/http-proxy/src/install.ts:114-116). `inheritedProxyEnv` is owned by the *outermost* install so a nested one does not record the outer policy's published values as if the user had written them.

Disposal *closes* the dispatcher rather than destroying it, so a request already in flight still finishes.
- Surprising: worker threads are deliberately not served — "both this repository ships — the workflow engine and the PTC runtime — evaluate model-authored scripts, which must not receive a proxy URL that may carry credentials" (packages/util/http-proxy/src/install.ts:166-169).

### packages/util/http-proxy/src/policy.ts
- Purpose: the pure, transport-free half — turn the launch environment into one policy and answer which proxy a URL goes through.
- Key abstractions: `EnvLookup` (structural, so the launcher's snapshot satisfies it unchanged), `ProxyPolicy`, `ProxyResolution`, `ProxyDiagnostic`, `ProxyCandidate`, `LOOPBACK_NO_PROXY`, `POLICY_ENV_NAMES`, `PROXY_ENV_NAMES`, `DIRECT_POLICY`.
- Data flow: `readEnv` (lowercase first, blank treated as unset) → `acceptProxyUrl` (parse, then reject SOCKS/unsupported schemes into a diagnostic) → `resolveScheme` (own slot, then `ALL_PROXY`, then the HTTP proxy for HTTPS) → `withLoopback` merges the bypass list → `proxyForUrl` decides per URL.
- Non-obvious design decisions: **a rejected slot is distinct from an absent one** — "the user named a proxy for that scheme, so falling back to another scheme's proxy would route the request somewhere they never asked for while the diagnostic said it stayed direct" (packages/util/http-proxy/src/policy.ts:121-124); `resolveScheme` therefore returns `undefined` for a rejected slot instead of falling through. - Surprising: `bypassesProxy` treats a bare IPv6 literal and a bracketed one as the same, and an entry names a host *together with every subdomain under it*.

The default intent prefers the default browser for `.html/.htm/.xhtml/.svg` where the platform can name one, but the *text-editor* intent never consults the browser. WSL is detected from `WSL_DISTRO_NAME`, `WSL_INTEROP`, or a kernel release containing "microsoft".
- Edge cases / failure handling: Explorer's exit code 1 is accepted as a delegated handoff while cancellation wins over it (`signal.throwIfAborted()` before the exit-code check); a `wslpath` translation that is empty throws "wslpath returned no Windows path"; an unsupported platform throws "native path opener is unsupported on …".
- Surprising: `canOpenNativePath` exists so a surface can show a path as *text* instead of offering a button that would spawn `xdg-open` into nothing on a headless Linux host (packages/util/native-command/src/path-opener.ts:209-212).

### packages/util/output-retention/README.md
- Purpose: cap how much context a tool returns to the model while reporting exactly what was dropped.

### packages/util/output-retention/src/index.ts
- Purpose: bounded model-facing output with exact omission metadata.
- Key abstractions: `ItemRetainer<T>`, `TextRetainer`, `Omitted`, `RetainedItems<T>`, `RetainedText`, `ItemRetentionStrategy`, `TextRetentionStrategy`, `RetentionNotice`, `describeOmitted`, `formatRetentionNotice`, `truncateWithoutSplittingSurrogatePair`.
- Data flow: `push()` per unit/chunk returns `{ kept, truncated }`; `finish()` returns the retained content plus `omitted`.
- Non-obvious design decisions: `omitted` is reported against the bytes **actually returned**, not the pre-trim budget: "a boundary trim drops partial-codepoint bytes too, so an exact count derived from the budget alone would overstate the retained text (and any 'Omitted N bytes' notice built from it would be a lie)" (packages/util/output-retention/src/index.ts:372-375). When nothing was omitted, the head and tail slices are **adjacent** parts of one stream, so they are decoded as one contiguous buffer — otherwise a codepoint spanning the artificial split would be corrupted even though no content was dropped (packages/util/output-retention/src/index.ts:357-363). `describeOmitted` prints no count for `unknown`, because the caller did not provide one.
- Edge cases / failure handling: byte budgets are validated as non-negative integers; a chunk straddling the cap is `kept: false`; the suffix accumulator drops whole leading chunks as they slide out and trims a chunk larger than the window so the retained memory stays bounded by `suffixCap`; UTF-8 boundary trimming removes a trailing partial sequence and a leading continuation run, and a stray continuation run with no lead byte is left alone for the non-fatal decoder to replace. `truncateWithoutSplittingSurrogatePair` drops the unpaired half when a cap lands inside a surrogate pair, because "an unpaired surrogate is not well-formed text — a strict JSON reader rejects a durable Session log that carries one" (packages/util/output-retention/src/index.ts:449-450).
- Surprising: `finish()` counts the trimmed boundary bytes as *omitted*, so the number the model sees always equals what is genuinely missing from the returned text.

- Purpose: shared timeout arithmetic, deadline fusion, and timeout-versus-cancel classification.
- Key abstractions: `clampTimeout(requested, def, max, name?)`, `deadline(upstream, timeoutMs, code)`, `idleWatchdog(upstream, timeoutMs, code)`, `timeoutOf(x, code?)`, `TimeoutReason`, `MAX_TIMER_DELAY_MS`, `Deadline`, `IdleWatchdog`.

### packages/util/timeout/src/index.ts
- Purpose: the shared timing and classification library.
- Key abstractions: `TimeoutReason`, `MAX_TIMER_DELAY_MS = 2_147_483_647`, `clampTimeout`, `Deadline`, `IdleWatchdog`, `deadline`, `idleWatchdog`, `timeoutOf`.
- Data flow: `deadline` arms one timer and fuses it with the upstream signal through `AbortSignal.any`; `idleWatchdog` arms a timer only while a `next()` demand is outstanding and races that demand against an expiry promise.
- Non-obvious design decisions: `AbortSignal.any` "adopts the reason of whichever source aborts FIRST, so a race resolves to a single cause" (packages/util/timeout/src/index.ts:115-117) — the *first* cause wins, which is why the timeout reason is only readable when the timeout won. The idle watchdog "owns the outstanding demand": a transport can leave a read it aborted pending forever, so "waiting for the iterator to observe the signal would leave the caller waiting past its own deadline" (packages/util/timeout/src/index.ts:145-148). `timeoutOf` pins `AbortSignal.reason` to `unknown` "so no `any` leaks" (packages/util/timeout/src/index.ts:208-209).
- Edge cases / failure handling: a delay above `MAX_TIMER_DELAY_MS` is rejected, because Node would silently clamp it to 1 ms; a negative or non-finite delay is rejected; `idleWatchdog` rejects a concurrent `next()` ("already outstanding") and any call after disposal; a `timeoutMs` of zero or less arms no timer and forwards only the upstream signal.
- Surprising: `deadline` returns an object with `[Symbol.dispose]()`, so `using d = deadline(...)` clears the timer at scope exit — the timer is a resource with a lexical lifetime.

- Key abstractions: `workspaceRecord` (Zod), `workspaceDomainState` (Zod), `workspaceDomainSpec = defineDomain({ name: 'workspace', version: 2, global, tables })`, `workspacePendingMutation` (a discriminated union on `operation`).
- Data flow: the registry opens the spec; the domain's global holds the registry state and the `workspaces` table holds the records.
- Non-obvious design decisions: the archive set is layered *over* workspace accounting and "never participates in the one-owner accounting invariant" (packages/workspace/workspace/src/spec.ts:52-54) — an archived session keeps its `sessionIds` slot so unarchiving restores its position. Both session sets are `.default([])` so media written before the fields existed parses unchanged. The `pendingMutation` marker is a **discriminated union** on `operation`, so a create marker and a delete marker are different shapes and cannot be confused.
- Edge cases / failure handling: `workspaceId` and `sessionId` are Zod transforms that brand the string — "branding has no runtime representation" (packages/workspace/workspace/src/spec.ts:14-15).
- Surprising: the domain version is 2, and the Zod schema is "the direct source of a future RPC wire projection" (packages/workspace/workspace/src/spec.ts:3-4) — the durable format doubles as the wire format.

### packages/workspace/workspace/src/types.ts
- Purpose: the public type vocabulary — the `WorkspaceId` brand and the `Workspace` consumer interface.
- Key abstractions: `WorkspaceId = Branded<'WorkspaceId'>`, `Workspace`, `SessionActivityKindMap` (empty by design), `SessionActivityKind`, `SessionActivityItem`, `SessionActivity`.
- Data flow: none — this file carries no runtime code.
- Non-obvious design decisions: `WorkspaceId` is "a generated uuid, never the path: path normalization rewrites paths, and a reference anchor must stay stable" (packages/workspace/workspace/src/types.ts:13-15). `SessionActivityKindMap` is declared **empty** on purpose: each provider merges its own key, "so a consumer that renders the families sees exactly the keys its program compiled and falls through to a generic description for any other" (packages/workspace/workspace/src/types.ts:36-38).
- Edge cases / failure handling: the `sessionIds` doc states the exact filtering rules — missing headers, invalid cwd values, and canonical cwd mismatches are never returned; a fully qualified cwd whose realpath or directory stat fails with ENOENT preserves an existing candidate, "including a dangling symlink; other filesystem failures do not".
- Surprising: the module augments `@deepseek-ai/dsh-typert-protocol` with a `workspace` resource and a `'workspace/not-found'` remote-error detail, so the workspace identity is a first-class wire resource.

### packages/workspace/workspace/tests/workspace.spec.ts
- Purpose: the registry's whole contract — lifecycle, bootstrap, ordering, membership, archive/pin, and first-use preparation.
- Key abstractions: a `harness()` that boots the *real* storage/domain/registry composition over an in-memory backend with a header-only persistence peer; `selectiveFailureBackend` that injects a failure at the Nth `putRecord`/`deleteRecord`/`setGlobal`.
- Data flow: each case boots a composition, mutates it, and asserts the durable state, the `domain/changed` events, and the registry's projection.
- Non-obvious design decisions: the peer `sessionPersistence` throws on `open` and `stat` — "event bodies must not be opened" and "per-session stat must not be needed" (packages/workspace/workspace/tests/workspace.spec.ts:57-58) — so header-only reads are enforced by the harness, not merely asserted in prose. The failure backend injects a failure at a *chosen write index*, so a rollback path can be reached without racing.
- Edge cases / failure handling: the registry stays pending without `sessionPersistence` and never opens the domain; bootstrap groups by canonical cwd, ignores a symlink alias, a file, a missing dir, and a cwd-less session; equal timestamps break by session id then path; a failed bootstrap record write is reused on retry; a failed final marker write keeps the durable order; headerless partial records are ordered by prior order then stable id; concurrent same-path creates serialise into one entity; the `title` parameter is not retitled on reuse; a relative path is rejected rather than adopted from the Host cwd; every create rollback path is exercised, including the `AggregateError` case where both the write and its rollback fail; delete rollback, double failure, and marker-cleanup failure each have a case; order drift, duplicate paths, duplicate session accounts, orphans, and repeated ids all fail loud; a pending marker for a create *and* for a delete are both recovered, and a pending delete whose id is still in the order fails loud; membership survives directory removal, a vanished symlink target, a removal between `realpath` and `stat`, and `EACCES`/`ELOOP`/`ENOTDIR` (which *do* prune); the missing-path exemption is cleared when a later header index resolves elsewhere; the archive surface is tested for idempotence, refusal of an active session with the reported families, the `stopActivity` ordering (`write` before `stop`), a failing provider being logged rather than undoing the archive, and a persistence fault propagating instead of becoming "unknown session"; the pin set is tested for prepend order, the mutual exclusion with archive, and the same-durable-write pin drop; unarchive and unpin run no existence probe.
- Surprising: the first-use preparation section asserts the *title* is taken from the requested directory rather than the canonical one, "so the caller can still recognize a Workspace it has not renamed" (packages/workspace/workspace/tests/workspace.spec.ts:1500-1502), and that a Session arriving *during* directory preparation makes the initialization ineligible — the check is repeated after the `await`.

## Ideas worth stealing

- **A "settle" step that reconciles a streamed prefix with the authoritative final text without joining the fragments** - `packages/util/values/src/partial-json.ts:160` - August's tool-call arguments arrive as deltas and are later re-sent as one complete body. `settle(text)` compares the recorded fragments against the final text *directly* (no concatenation, so a 100 KB argument is not copied), seals the *same* view with its caches intact when they match, and produces a fresh sealed view when a delta is missing or conflicting. Copy this shape for the "streamed tool call vs. final tool call" reconciliation so a re-sent argument can never be parsed twice or drift from what the model asked for.
- **Publish only what actually changed, and only when the published value changed** - `packages/util/values/src/partial-json.ts:177` - `refresh()` compares each remembered answer against its last published value and returns a single boolean, and `stringLength(key, { step })` reports a change only when the *rounded-up step* moves. A streaming chat card in August can therefore re-render on a 64-character boundary instead of on every delta, and the "did anything the user sees actually change?" question is answered by one boolean instead of a diff.
- **Report omission against what was actually returned, not against the budget** - `packages/util/output-retention/src/index.ts:376` - The retainer trims a partial UTF-8 codepoint at each cut and then counts the trimmed bytes as *omitted*, because "any 'Omitted N bytes' notice built from it would be a lie" (packages/workspace/workspace/src/index.ts:372-375). August's tool-output caps should report the same way: the number in the model's context must equal the number of bytes genuinely missing, or the model will trust a wrong count when it decides whether to re-read.
- **A rejected slot is distinct from an absent one** - `packages/util/http-proxy/src/policy.ts:121` - When the user named a proxy for `https:` and that value is unusable, the scheme stays direct instead of borrowing the `http:` proxy — "falling back to another scheme's proxy would route the request somewhere they never asked for while the diagnostic said it stayed direct". August has the same shape everywhere a per-capability value is refused (a model with no tools, a provider with no key, a tool with no permission): once a user has named a value for a slot, silently substituting a different one is worse than refusing, and the diagnostic must agree with the route.
- **The deadline owns the outstanding demand, not the iterator** - `packages/util/timeout/src/index.ts:145` - A transport can leave a read it aborted pending forever, so waiting for the iterator to observe the signal would leave the caller waiting past its own deadline; the watchdog therefore races the demand against its own expiry. August's stream-reading tool calls (web fetch, MCP, provider streams) need the same property: a hung read must fail at the deadline instead of pinning the turn.
- **Scope the timeout classification to your own code, so nesting composes** - `packages/util/timeout/src/index.ts:206` - `timeoutOf(signal, 'BASH_TIMEOUT')` returns a timeout only when *that* capability's timer fired; a foreign timeout follows the ordinary cancellation path. In August, where one turn nests a provider read, a tool call, and a subagent, this is what keeps "the provider timed out" from being reported as "the tool timed out" three layers up.
- **Two-write mutation with an explicit recoverable marker, and fail loud on anything else** - `packages/workspace/workspace/src/index.ts:636` - `recoverPendingMutation()` completes the one mutation explicitly named by durable state; "this path never guesses which operation created a row from its shape alone", and unexplained order/table divergence still reaches `validateStoredState` and fails loud. August's durable stores (session transcripts, turn outcomes, workspace records) need exactly this: a marker written before the two-write window, and a loud failure rather than a heuristic repair when the marker is absent.
- **Decide membership at the write chain slot, and let a no-op write nothing** - `packages/workspace/workspace/src/entity.ts:203` - The update function sees the value current at its chain slot, so idempotence is race-free against queued writes, and a function that returns the record verbatim aborts the slot through a sentinel so "a no-op neither rewrites the medium nor emits a change event". August's turn/turn-outcome persistence gets the same property: a repeated archive or a duplicate attach must not rewrite the log or emit a spurious event.
- **Write the durable state that gates the side effect *before* asking for the side effect** - `packages/workspace/workspace/src/index.ts:385` - With `stopActivity`, the archive write lands first and only then are the stop providers asked to stop the work, "so the durable archive set is what a provider's `agent/pre-step` gate reads, and every wake the stops induce is already blocked". August's stop/cancel path needs this ordering: the durable "this turn is stopped" fact must be committed before the cancellation is issued, or the cancellation itself can wake the thing it just stopped.
- **A `Map` for a table keyed by untrusted strings** - `packages/util/code-language/src/index.ts:100` - "A `Map`, not an object: a filename whose extension is an `Object.prototype` key (`foo.constructor`, `foo.__proto__`) must miss instead of resolving the inherited member, which would otherwise reach callers as a non-string language value." Every August table keyed by a model-supplied string (tool names, provider ids, file extensions, session labels) should be a `Map`, and the same rule appears in `plugin-market-index`'s `own()` helper, which uses `Object.defineProperty` so `__proto__` stays an ordinary key.
- **One matcher, not two** - `packages/util/http-proxy/src/policy.ts:338` - `proxyForUrl` is the single answer both the installed dispatcher and the browser-worker fetch consult, "so a URL can never be pinned to a resolved address by one and tunnelled by the other". The package's own spec says out loud that the parity test can only catch a *reintroduced* second matcher. August should have one place that answers "which credential/endpoint/transport does this request use" and one implementation of the answer, with the parity spec written to fail if a second copy appears.
- **Never hand a child process a value you refused** - `packages/util/http-proxy/src/install.ts:262` - The child's environment carries the *user's* value for every scheme they named (so a SOCKS proxy `curl` uses is not replaced) and the resolved value for the ones they did not, and the `NODE_USE_ENV_PROXY` flag is withheld when any value the child would receive is one the parent refused — because Node parses those names under the flag and exits on a bad scheme. August's subprocess and worker spawns need the same rule: a credential the parent refused must not be handed down in a form that stops the child from starting.
- **A frozen, layered environment snapshot that remembers which layer won** - `packages/util/launch-environment/src/index.ts:88` - `getFrom(name, sources)` filters by the *canonical* trust order, never by the caller's list order, so omitting a layer is a refusal that no future reordering can undo. August's config resolution (env → project `.env` → user `.env`) should answer "which layer supplied this?" and should make "never read this from the project directory" a structural property rather than a convention.
