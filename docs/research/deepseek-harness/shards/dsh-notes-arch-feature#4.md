# deepseek-harness / dsh-notes-arch-feature#4

## Shard shape

This shard is the **September 2026 wave of frozen `feature`-class Agent Notes** from the deepseek-harness repo, held under `.agents/notes/archived/feature/`. It is 138 files but only **46 distinct decisions**: every decision appears as a *triplet* — an English `foo.md`, a Simplified-Chinese `foo.zh.md`, and a `foo.i18n.yaml` sidecar that pins the git blob hash of each language side. All 46 notes carry `Status: implemented` and `Archived: 2026-09-30` (one exception: `2026-09-08-web-explicit-file-delivery.md` is archived `2026-09-08`), and all are sealed: the archive is a *frozen historical snapshot*, not current authority, and `verify-archived-agent-notes` refuses any content change. Every note follows the same skeleton — `## Problem` / `## Decision` / `## Alternatives considered` / `## Consequences`, with `## Testing` / `## Verification` / `## Deferred` / `## Related` where the decision needed them. The decisions themselves cluster into five groups: **(a) the agent loop and its periphery** — background `workflow` runs on the job registry, unbounded background-job completion wakes, shared continuable-Activation capacity for subagent delegation, model-switch route-change notices, MCP resource tools and scoped server instructions, MCP SDK protocol negotiation; **(b) the desktop shell** — macOS vibrancy titlebar, Windows caption and application menus, mandatory-update client and blocking window, Desktop-installed CLI runtime, login-shell environment capture, uninstall data policy, device-local onboarding; **(c) the Web/Sidebar product surface** — the guide/document-preview/file-tree tab types and their polish, file-tree and diff review tabs, the changed-files card, composer reference previews and selection keyboard contract, persistent plan cards, session pinning/archive filter, first-use default Workspace and its language-neutral naming, developer-tool settings, focus-ring unification; **(d) delivery and file surfaces** — `present` following Session filesystem access, authenticated `/api/file` byte reads, explicit Web file snapshots, local-media display in session prose, Markdown file-preview links, bundled Office skills; **(e) small policy records** — public Web URL advertisement, feedback dialog and categories, account quota top-up, profile command shorthand, one-minute schedule floor, developer-tools default-on. The notes are unusually valuable as a corpus because they record **why a mechanism was chosen over the plausible alternative**, which is exactly the part that does not survive in code.

## Per-file notes

### .agents/notes/archived/feature/2026-09-01-workflow-run-in-background.md
- Purpose: Give the `workflow` tool a `run_in_background` route so a long multi-agent orchestration no longer holds the parent turn hostage for its whole wall-clock.
- Key abstractions: the job-registry seam (`JobSpec`, `JobHandle`, `JobOutcome`, `JobKindMap` declaration merging), a `kind: 'workflow'` job with an observation record, and a `kind`-discriminated output union (`background` | `foreground`).
- Data flow: the tool call registers a workflow job and returns `{ kind: 'background', jobId, runId }` immediately; the engine run lives inside the job starter; `run.result` chains into the job's `done` → dispose mirrors → map the stop reason → `completed` carries the same rendered return value as the foreground path in `JobOutcome.output`; `src/record.ts` subscribes once per plugin to `workflow/phase`, `workflow/log` and member-lifecycle events and routes them into the tracked run's `JobHandle` on the `log` channel, so the model's `job_output` never renders them; `updateProgress` tracks the current phase.
- Non-obvious design decisions: **the run belongs to the job, not the tool step** — the engine starts with no `exec.signal`, so a turn abort cannot kill work the model deliberately detached; `job_kill`, the job list's stop control and owner teardown are the cancellation paths and each forwards its reason into `run.cancel`. Bridging `exec.signal` in was rejected because the returning tool step's abort "would kill work the model just intentionally detached". A *synchronous* engine rejection (meta/parse failure) propagates out of the starter so nothing registers and the model sees the ordinary correctable error.
- Edge cases / failure handling: a disposal failure warns and never rejects into the registry; post-settlement appends drop inside the registry; a straggling event finds no tracked run; the durable run-start/member/run-end recording keeps its `exec.parent === undefined` gate on both paths; `job_output` before settlement returns status alone.
- Surprising: the foreground envelope gains `kind: 'foreground'` purely for symmetry, and a "start/poll API on the tool itself" (`workflow_status`) was rejected as duplicating `job_output`/`job_kill` for one producer.

### .agents/notes/archived/feature/2026-09-05-sidebar-text-preview-and-file-tree.md
- Purpose: Ship the first three right-Sidebar tab types (guide, document preview, file tree) and, by using them, demonstrate the type-authoring template end to end.
- Key abstractions: a static tab-type definition registered into `ctx.sidebarRightTabs`; the body registered in the keyed `sidebar.right.pane.tab` seat under the definition's `id`; `ctx.effect` lifetime; `useResource`; a Slot-standard exclusive store; an inject face; `SidebarRightResourceParamsMap`; `fileAddressFor` / `parseFileAddress`; `workspaceTitleOf`.
- Data flow: definition + priority band (`builtin` / `extension` / `fallback`) + `patterns` decide who claims an address; the body calls `useResource<'file'>(tab.contentId)` to get a `WorkspaceFileStat`; the Preview face reads text through `remote.workspaceFiles.read` and bytes through `readBytes`; the store bucket holds `{ version, pages, eof, loading, failure, scrollTop, wrap, revision }`; navigation narrows `navigation.params` to `{ line?: number }` and walks pages in order until the line is covered.
- Non-obvious design decisions: **bucket the store by tab id, not by file** — two tabs of one file are two reading positions; **the tree is not a resource** — "a resource has one address and one current value", so a lazily-expanded directory tree is the type's own state; the guide is the chain's *fallback*, not a chain entry, so there is always exactly one body and it cannot be outvoted by registration order; the guide hands the tab over with `openTab(kind, { replaceTab: true })` because "the guide is a doorway, not a page that stays open beside what it opened"; a type's controls live in its own body, not on the pane's tab strip.
- Edge cases / failure handling: a malformed claimed address throws as a programming error; a page that fails while walking stops the walk and shows the failure line; a line past EOF stops silently at `eof`; an owner's `signal` ends the bucket and a late-settling read writes nothing; `other` entries (symlink, socket, device) render as a greyed, non-focusable span with `aria-disabled` so a directory is reported whole without offering a click that would fail; `maxEntries` truncation ends a level with a `truncated` marker.
- Surprising: **"a changed file is announced, not applied"** — reloading under the reader loses their place and an agent-written file changes repeatedly, so the bar waits for a click; the tree never names a viewer (the registry's claim decides who draws the address); reading by page bounds every request but a jump to line 40,000 of a large file reads eight pages first.

### .agents/notes/archived/feature/2026-09-07-model-switch-notice.md
- Purpose: Tell a newly selected model that earlier assistant turns came from a *different route*, so it does not inherit a stale capability limitation (the motivating case: a text model had omitted images, and the new vision model believed the limitation described itself).
- Key abstractions: `installModelSelection`; the durable request header as the route record; the `agent/pre-step` decision point.
- Data flow: prompt assembly captures the provider/model selection → it is compared with the latest durable request header → on a mismatch an *identified user-role message* is appended to the downstream `agent/pre-step` decision that would send a model request → the message is logged through the existing `user/message` event before the request header, so it appears in model input, Chat and Trajectory.
- Non-obvious design decisions: the notice goes into **history as a user-role message, not into the system prompt** — "a transient prompt change would not be reconstructable from the session log and would not mark the exact point where ownership of assistant turns changed"; a separate package or capability was rejected because the behaviour only coordinates two things `installModelSelection` already owns.
- Edge cases / failure handling: no notice for initial selection, unchanged route, reasoning-effort-only change, rejected steps or aborted steps; an empty first decision and a decision that removes offered messages stay no-request results; an empty continuation after a tool call *does* receive the notice because the loop would still request the model from retained history; a selection changed during pre-step processing waits for the next prompt assembly; if the step fails before the header is logged the next request step repeats the notice, because the durable previous route is unchanged.
- Surprising: same-provider routes use bare model ids and cross-provider routes use `provider/model`; a failure before header persistence can retain more than one identical notice in history.

### .agents/notes/archived/feature/2026-09-07-public-web-deployments.md
- Purpose: Let a deployment **advertise** its public HTTP(S) root (behind a forwarding gateway that strips its path prefix) without that advertisement granting any trust.
- Key abstractions: the `--public-url` CLI flag; `src/public-url.ts`; the Web bundle's `publicUrl` config; `--trusted-host`; the browser-trust fence; `DSH_WEB_URL`.
- Data flow: flag → `publicUrl` → the printed and opened URL, `DSH_WEB_URL` and the web-surface orientation. It configures **no** routing, client transport or cookie scope.
- Non-obvious design decisions: advertisement is deliberately separated from trust — "the browser-visible authority must be named with repeatable `--trusted-host`, and the fence still validates `Host` and `Origin` per request, so advertisement grants neither identity nor authentication"; folding the advertised host into `trustedHosts` was rejected for exactly that reason; the advertised root is the first production input that can carry a mount prefix, so the launch flow adds the launch token without collapsing the mount.
- Edge cases / failure handling: `--public-url` refuses credentials, query and fragment; a misconfigured address can still disclose the launch token; an HTTP root carries the tokenized URL and the session cookie without TLS, and an HTTPS root encrypts only the browser-to-proxy leg; a wildcard `--host` stays refused.
- Surprising: network exposure is never inferred from the advertised root or a trusted host — "a display or authority choice cannot authorize opening every interface", so listener selection stays explicit.

### .agents/notes/archived/feature/2026-09-07-session-prose-local-media-display.md
- Purpose: Make local filesystem image references in assistant prose render, through a same-origin file route, instead of staying inert alt text.
- Key abstractions: the `MarkdownPathImages` vocabulary on `MarkdownText` (`ui-primitives`); the `localPathMediaUrl` vocabulary from `ui-chat` via `AssistantMarkdown`; the `SessionMediaReferences` contribution in `session-controller`; `connection.fetch`.
- Data flow: the settled markdown pass rewrites image destinations outside the remote-URL allowlist → an absolute POSIX path becomes `api/file?path=…` resolved against `document.baseURI` → `connection.fetch` applies the same browser authentication and trust checks as `/api` RPC.
- Non-obvious design decisions: the vocabulary applies **only after the message settles**, "so frozen streaming blocks cannot cache a vocabulary handler"; a fixed same-origin endpoint gives the *synchronous* renderer a stable URL without asynchronous capability negotiation; byte-signature validation was left to the model-facing `read_image` tool rather than duplicated in the route.
- Edge cases / failure handling: relative, protocol-relative and Windows-style paths and non-HTTP transports (Electron `file://`) stay inert; only absolute `http(s)`, `blob` and `data` results are emitted; a failed load replaces the image with authored alt text, or the original destination when alt is empty; a different source can load again.
- Surprising: the original policy (workspace roots + MIME allowlist, regular-file checks, opened-handle identity comparison) was **superseded** because it excluded temporary screenshots and remote files, and because distinguishing "exists outside workspace" from "absent" leaked existence even while refusing the bytes.

### .agents/notes/archived/feature/2026-09-08-desktop-uninstall-preserve-dsh-home.md
- Purpose: Decide exactly what a Windows uninstall deletes: the Electron user-data directory, the `%APPDATA%` product directory and the updater cache — but **never** the Harness home shared with the CLI.
- Key abstractions: the NSIS uninstaller template; the native removal helper in `window-frame.dll`; `InstallLocation` recorded on the Windows uninstall entry; `DSH_HOME` published as a Windows environment variable.
- Data flow: uninstall → the native helper removes `%APPDATA%\@deepseek-ai\dsh-desktop` → then removes ordinary *empty* parents below `%APPDATA%`, never a linked or populated scope directory.
- Non-obvious design decisions: **no user choice and no custom uninstaller page** — the remaining Electron data is only UI preferences and caches, "which does not justify a choice the user must understand, a recorded home path for the uninstaller, and a bilingual native dialog"; `--updated` / `/KEEP_APP_DATA` retain the data so electron-builder's in-place update keeps UI preferences; the native helper replaces electron-builder's `deleteAppDataOnUninstall` because the upstream `RMDir /r` "follows no ownership rules, ignores long paths and enters linked directories".
- Edge cases / failure handling: the helper refuses protected Windows folders and paths overlapping the installation or the protected home; it holds directory handles with listing access during traversal so a directory cannot be renamed or replaced underneath it; it unlinks reparse points without entering their targets; clears the read-only attribute; keeps deleting siblings after a locked file; requires a fixed local drive and leaves a linked root or ancestor in place; a failure leaves residue and does not stop or report on uninstallation.
- Surprising: the helper "cannot see a home configured only in a shell profile" — only a `DSH_HOME` published as a Windows environment variable protects the home.

### .agents/notes/archived/feature/2026-09-08-feedback-dialog-and-categories.md
- Purpose: Replace two disconnected, outcome-free feedback paths with **one** dialog reachable from the composer menu, a bare `/feedback`, and Dislike, carrying seven fixed categories, an optional description and a success toast.
- Key abstractions: the `FeedbackCategory` union and `FEEDBACK_CATEGORIES` tuple in `command-feedback`'s client-safe `./types`; the `sessionFeedback.record` Remote published through `TypertRemoteService`; `FeedbackSurface` / `FeedbackDialogController` in `ui-message-feedback`; the `conversation.input.overlay` entry; the `action` kind in `CommandUiSpec`.
- Data flow: the dialog → `FeedbackDialogController` → either the message controller (message target) or `ctx.remote.sessionFeedback` (session target) → the existing `recordFeedback` producer → a Session remark.
- Non-obvious design decisions: the category taxonomy is **restated in the client** as `Record<FeedbackCategory, true>` because the client-bundle purity gate forbids a value import from a Host package, and the compiler checks completeness; the design's "include the conversation log" checkbox is not built because the log travels with every feedback event and is not optional; the dialog is submitted through the Remote rather than the command plane because the command rejects empty text and cannot carry a category.
- Edge cases / failure handling: blank text records as absent, and an entry with neither member still records — "the log delivery that the feedback authorizes is the content"; an oversized description fails on submit with `note-too-large` and the dialog keeps its draft and shows a localized warning toast; opening or dismissing the form writes no feedback event, only Submit records one; unloading the feedback plugin removes only its menu row and leaves export usable.
- Surprising: the frozen released-v2 payload inventory still lists `feedback/record` as `text`-only — it governs artifacts migrated from older generations, while equal-version restoration applies the installed vocabulary.

### .agents/notes/archived/feature/2026-09-08-file-display-through-filesystem.md
- Purpose: Serve authenticated `/api/file` reads from the composed filesystem provider instead of a Host-local workspace-and-MIME allowlist.
- Key abstractions: `ctx.fs`; `readBytes(target, signal, maxBytes)`; `ctx.attachments.imageLimits.maxImageBytes`; `FS_TOO_LARGE` → 413; a sandbox CSP.
- Data flow: GET → `readBytes` (providers reject known oversized files *before* content I/O and enforce the limit while reading) → the whole file; HEAD → metadata only; MIME lookup supplies response metadata without sniffing file contents.
- Non-obvious design decisions: duplicating size checks in the route is rejected — "`readBytes` already owns preflight limits, growth detection, and cancellation"; Range is ignored and not advertised, and every response is a complete file, because streaming and Range would require implementing them in every provider.
- Edge cases / failure handling: `FS_TOO_LARGE` becomes 413; unknown extensions use `application/octet-stream`; a sandbox CSP prevents directly opened HTML/SVG from executing with the authenticated API origin; a failed image load shows authored alt text or the original destination when alt is empty; HEAD checks size separately because it must not read the body.
- Surprising: the chosen policy gives an authenticated client **broader access than registered workspace roots** (any regular file the composed provider can read) — the local sandbox provider constrains mutations, not reads.

### .agents/notes/archived/feature/2026-09-08-web-explicit-file-delivery.md
- Purpose: Deliver a file to the user as an **immutable snapshot** rather than a live workspace link, and add the durable `deliverables/presented` event.
- Key abstractions: `packages/fs/tool-present` (execution, immutable snapshots, delivery types, the durable event); `packages/client/ui-deliverables` (authenticated snapshot actions, browser rendering, type-only imports from the tool's `./types`); the `standard` / `ptc` / `cordis` presets mount the tool package while `minimal` keeps its two-tool training configuration; the attachment service.
- Data flow: a tool call → the attachment service saves immutable bytes → a successful **final** `tools/result` appends `deliverables/presented` to the calling Session → a later download or native-open authorizes the reference by (viewed Session, event sequence, file index).
- Non-obvious design decisions: the event stores **no Session ID**, so a forked history uses the child's own log; tool *text* is not used as the durable index because post-processing and spill can replace ordinary or nested result text — each plugin instance instead keeps its own completed snapshots by execution identity and publishes only on a successful final result; a later enclosing program failure does not undo a completed nested delivery.
- Edge cases / failure handling: blocked tool results publish none; each open gesture receives a **new** copy so application edits cannot corrupt the immutable attachment or alter later opens; successful copies survive until plugin disposal (for lazily-reading applications) while failed copies are removed immediately and disposal awaits cancelled work before cleanup; Session ZIP retains delivery events but does not collect their attachment bytes.
- Surprising: the delivery event is **required-on-read** — it is the authorization index for saved bytes, so an older reader *refuses* the session rather than silently dropping the references.

### .agents/notes/archived/feature/2026-09-09-headless-machine-readable-run-surface.md
- Purpose: Give a supervising process (one headless process per wake) three things the human-terminal contract lacks: the task over a private pipe, a machine-readable stream separating assistant text / reasoning / tool calls / results / turn boundaries / usage, and an exact session identity it can pass back.
- Key abstractions: the `dsh-headless` bundle; `--json`; `--session-id <id>`; `src/json-stream.ts`; the event vocabulary (`session`, `status`, `text`, `thinking`, `tool_call`, `tool_result`, `error`, `final`); the `sessionQuery` and `sessionPersistence` services; `cordis.patch.yml`; the shared `lib/json-stream-*.js` chunk.
- Data flow: `src/startup.ts` parses the flags; `src/index.ts` resolves the task (joined positionals → `-` → piped stdin), adopts or mints the session, and wires either the stderr reasoning projection or the new JSON projection; the JSONL projection reads the session event log and emits one JSON object per line.
- Non-obvious design decisions: the vocabulary is a **projection of the log, not the log** — dumping raw events was measured at 84 lines / 11.7 KB for one prompt against opencode's 3 lines / 962 B, with roughly a quarter of pi's bytes repeating one message across `message_end`, `turn_end` and `agent_end`; text and thinking project only from a **committed** `assistant/message`, never live attempt deltas, so a discarded attempt leaves no trace; a `tool/result` projects only when its `surfaceOp` is `append` (a compaction replacement would emit a call id with no matching `tool_call`); `usage` appears on `step_end` only when every attempt in the step reported a sample, "so a partial total is never presented as exact"; `--session-id` is **adopt-only**, because creating the requested id would let a mistyped or stale id silently open an empty history the caller believes it is resuming; the requested id must match the persisted cwd, must not be a preset / fork / subagent session, must not be a live agent's id, and is re-checked after the runner's idle wait.
- Edge cases / failure handling: a whitespace-only positional is a usage error even when stdin is piped, "so an accidental blank argument never consumes a pipe"; a lone `-` mixed with other words is a usage error; in `--json` every usage error — including commander's own grammar rejections — writes the `error` event before the process exits, and the event message omits commander's `error: ` prefix so one event type carries one message shape; every projected string and object key is bounded at 8 KiB and one serialized line at 32 KiB (an over-long event keeps scalars, drops structured fields, and at the extreme reduces to `type` + `truncated`; a payload nested 64+ levels is cut at that depth); a literal `__proto__` argument key is copied as data rather than through the inherited setter; an empty tool-argument string projects as `{}` to match the executor; `1e400` keeps its raw text rather than `JSON.stringify`'s `null`; the terminal `final` event is deliberately unbounded.
- Surprising: `--json` changes only the stdout payload and the reasoning destination — exit status, shutdown ordering, session flush and the durable log are unchanged, so a supervisor classifies a run exactly as before; a turn that fails in-turn still ends the stream with `final` and **no** `error` event.

### .agents/notes/archived/feature/2026-09-09-present-filesystem-access.md
- Purpose: Let `present` declare files that live outside the workspace (notably `/tmp`) and files held by a remote filesystem provider.
- Key abstractions: the composed `ctx.fs`; the `workspaceFiles.stat` scope; a canonical process path → Host path → same process path round trip.
- Data flow: `present` accepts an existing regular file accessible through `ctx.fs` (relative paths resolved against the Session working directory) → the declaration returns the viewed Session header → native actions use that header (its cwd, else the deployment workspace root) to form the `workspaceFiles.stat` scope → the same composed filesystem serves Sidebar previews and native validation **without activating an Agent**, including for child Sessions.
- Non-obvious design decisions: there is **no workspace containment check and no temporary-directory allowlist** (a `/tmp` allowlist would exclude other readable output locations and duplicate filesystem policy); the canonical process path must map from a Host path back to the *same* process path through that filesystem, and "a same-named local file never substitutes for an unmapped provider file"; treating every provider process path as a Host path could open an unrelated local file.
- Edge cases / failure handling: missing files, directories, final symbolic links and provider failures reject the declaration; a sandbox's private temporary files remain unavailable when the provider cannot see them; absent or different Host mappings produce 422 with a localized Sidebar-preview suggestion; native opening requires both a serving desktop and a verified Host path; metadata checks do not make a desktop application's later path lookup atomic.
- Surprising: the request still selects only saved Session/event/file coordinates — "never an arbitrary browser-supplied path".

### .agents/notes/archived/feature/2026-09-09-ptc-trajectory-code-inspection.md
- Purpose: Inspect recorded PTC (program-as-tool-call) source in Trajectory instead of a JSON-escaped generic argument tree.
- Key abstractions: `run_code` argument validation; Trajectory's identification by recorded tool name; a code inspector derived from validated arguments; the shared wrapping preference.
- Data flow: a recorded call named `run_code` → the validated arguments carry the original JSON text → the inspector shows the source (copying preserves source and argument bytes) with a separate toggle exposing the original JSON; the result view preserves recorded text and uses a tree only for complete JSON objects or arrays.
- Non-obvious design decisions: syntax highlighting requires an **unambiguous TypeScript or Python hint in that call's recorded parameter description** — using the active runtime language or inferring it from the source "can mislabel a historical program"; unsupported arguments retain the generic inspector; the inspector adds **no** Session events or host presentation fields, because the client derives UI from recorded facts.
- Edge cases / failure handling: unknown or conflicting hints leave plain text; errors retain captured output; code views sample the shared wrapping preference when opened and keep their own choice while mounted; the recorded text is not split into "printed output" and "return value" because "historical rendered text does not establish that distinction; a parser could invent a separation the producer never recorded".
- Surprising: the inspector is a pure client-side derivation from the recorded log — no host work is added to make it possible.

### .agents/notes/archived/feature/2026-09-10-composer-reference-previews.md
- Purpose: Let the user preview a referenced file or skill instruction while composing and after sending, **without changing what the next prompt sends**.
- Key abstractions: `ui-input-trigger` optional reference activation; routing of atomic references by source identity and of editable tokens through the current source lexicon; the existing right-Sidebar file resource; the per-Session skill catalog and its optional instruction-file paths.
- Data flow: the editor → source-owned activation → the existing right-Sidebar file resource in the composing Session; skill discovery retains the winning provider's optional instruction-file path (no body loads, no guessing from skill names or directory conventions); sent-message bubbles keep their logged skill-invocation evidence; the shared user-text primitive renders the references as buttons.
- Non-obvious design decisions: clicking never serializes or submits the draft; preview paths are transient discovery data and are **never added to Session messages**; turning skill tokens into file chips "would change editing, clipboard, and prompt semantics to solve a presentation task"; resolving formats inside the composer would couple the editor to provider catalog policy, so source-owned activation keeps those dependencies with the plugins that already own reference discovery.
- Edge cases / failure handling: invalid chips, selection gestures and unavailable source targets retain editor handling; virtual skills remain invocable without a file preview; catalog invalidation and plugin disposal cancel pending previews; an uncached click awaits the shared catalog fetch and retains its Session address.
- Surprising: file and skill previews share hover styles while keeping separate editing semantics — the shared hover is presentation, the activation is source-owned.

### .agents/notes/archived/feature/2026-09-10-symmetric-message-feedback-submission.md
- Purpose: Make Like and Dislike **symmetric** — both open the shared dialog and record only on Submit.
- Key abstractions: the `FeedbackDialogTarget` carrying `positive` / `negative`; `FeedbackSurface`; `MessageFeedbackController.rate`; the injected `retract` operation; the controller's serialized mutation queue.
- Data flow: the action row reads the committed item before either action → clicking the *current* rating calls `retract` → clicking an absent or opposite rating opens the dialog → Submit records the rating (plus optional category and description) and raises the acknowledgement toast.
- Non-obvious design decisions: `retract` **re-checks the committed rating inside the controller's serialized mutation queue** and becomes a no-op after a concurrent change, "so it cannot turn stale UI intent into a bare rating put"; the dialog remains optional-input (submitting with no category or description still records); the rating travels in the existing target so one draft and submission lifecycle serves both.
- Edge cases / failure handling: dismissing the dialog records nothing; clicking the active rating continues to create `feedback/message-delete` without opening the dialog; a separate confirmation to retract was rejected because retraction has no category or description to collect.
- Surprising: the "one fewer click" for Like was given up deliberately — "it keeps two submission models beside each other and prevents positive reports from carrying context".

### .agents/notes/archived/feature/2026-09-11-desktop-mandatory-update-client.md
- Purpose: Let the Desktop shell independently learn that an update is **required**, block subsequent interaction without interrupting running work, and retain a recovery path when policy queries or updater preparation fail.
- Key abstractions: the guest protocol (in the API proposal); the update coordinator (one in-flight request, a deadline, interval jitter, bounded failure backoff); the five Platform client headers plus architecture, update channel and bundled runtime version; a shell-owned modal with a **separate sandboxed preload** and a private MessageChannel; the flattened `40005` code.
- Data flow: the shell polls the guest protocol independently of business traffic → the coordinator publishes semantic phase/version/progress/classified failure to the preload → the modal renders; a confirmed block cancels ordinary dialogs and transfers presentation to the mandatory dialog; after approval the Host refuses new API requests, drains admitted ones, re-checks tasks, and only then installs.
- Non-obvious design decisions: a flattened `40005` establishes blocking **independently of optional title, detail and download-page fields**, and *no* failure class (transport, JSON, business code, HTTP) can clear a known block — only a valid fresh no-force response can; the product preload publishes **semantic** fields rather than localized strings, because the Desktop shell locale can differ from the language chosen inside the Web app and transported strings cannot react to a later language change; the Windows dialog is embedded in the main document below the caption because a second native window caused visibly unsynchronized resizing (#4566); the private MessageChannel means product scripts can hide or imitate the presentation but cannot obtain the privileged port, clear main-process policy, or approve task teardown.
- Edge cases / failure handling: disposal aborts the request, awaits settlement and prevents late publication; manual checks bypass scheduling but join in-flight work; a confirmed block alone cancels ordinary dialogs; Esc and ordinary updater prompts cannot dismiss the block, and main-process guards refuse plugin-window entry and plugin mutations while it is active; server title/detail are text, never HTML; exact HTTPS origins are checked before browser or clipboard use, and a browser request immediately exposes copy recovery because its completion cannot prove external page loading; a timed-out or superseded drain cannot authorize installation; the product window is hidden before Host teardown on intentional quit so the expected disconnect is not shown as recovery work.
- Surprising: "Host exit and successful task teardown are separate outcomes" — the process owner reports a confirmed-but-unsuccessful exit with a dedicated error type, backend cleanup can complete while installation still fails, and the shell restores the current-version Host and requires fresh confirmation **without clearing mandatory policy**.

### .agents/notes/archived/feature/2026-09-11-sidebar-document-preview-polish.md

## Ideas worth stealing

- **Never make a bound silently park work the model cannot see — prefer an observable cost over an unobservable stall.** `.agents/notes/archived/feature/2026-09-22-unbounded-completion-wakes-by-default.md:18` — the shipped cap of 3 woke an idle owner three times, then injected the fourth notice into a next-step inbox that nothing would ever drain, while the client rendered no pending indicator: the session sat with an invisible notice that looked like a hang, and the `tool-jobs` prompt's promise ("notified in-session when a job finishes — do not busy-poll") had quietly become false. The fix was to make the cap **default-off** and to state the trade outright — the chain spends model requests the user can watch and stop, an invisible stall costs a night. August's turn bounds, subagent caps and budget ladder should each be audited for the same shape: a bound that *defers* work to a place the model (or the user) never looks at is worse than no bound.

- **Project a run/event stream from the durable log at its commit points, and bound every field.** `.agents/notes/archived/feature/2026-09-09-headless-machine-readable-run-surface.md:55` (projection only from a committed `assistant/message`, never live attempt deltas) and `:58` (every string/object key ≤ 8 KiB, every serialized line ≤ 32 KiB, nested payloads cut at 64 levels, `__proto__` copied as data, `1e400` kept as raw text, the terminal `final` event deliberately unbounded). August's `turn_end`/`turn_outcomes` records and any SSE frame the harness emits for an external supervisor should be built as a *projection* of the session log, not a parallel writer — and every field should have a stated bound, because an unbounded field in a supervisor stream is a denial-of-service vector against whoever parses it.

- **A tool result that is not an append must not be projected as one.** `.agents/notes/archived/feature/2026-09-09-headless-machine-readable-run-surface.md:57` — a compaction replacement of an older `tool_result` is *history*; projecting it emits a call id with no matching `tool_call`, and the consumer's pairing logic breaks. August's `surfaceOp` / compaction paths should carry the same discriminator, and any consumer that pairs calls with results must filter on it.

- **Adopt-only session identity: refuse to create a session under an id the caller named.** `.agents/notes/archived/feature/2026-09-09-headless-machine-readable-run-surface.md:67` — creating the requested id when no log exists "would let a mistyped or stale id silently open an empty history that the supervisor believes it is continuing". The companion checks are worth copying wholesale: the requested id must match the persisted cwd, must not be a preset/fork/subagent session, must not already be live in the process, and is re-checked after the idle wait. August's session-resume and MCP-session paths should treat "the caller named this id" as a *claim about the past*, and verify it rather than honour it.

- **Tell the model when the route changed, as history — not as a system prompt.** `.agents/notes/archived/feature/2026-09-07-model-switch-notice.md:14` — `installModelSelection` compares the selection captured during prompt assembly with the latest durable request header, and on a mismatch appends an identified user-role message `[model changed: assistant turns above this point were generated by <previous>; the session continues with <next>]` to the `agent/pre-step` decision that would send a request. The stated reason for not using the system prompt is the transferable part: a transient prompt change "would not be reconstructable from the session log and would not mark the exact point where ownership of assistant turns changed". August swaps models mid-session too (per-model profiles, family fallbacks) — the fact belongs in the transcript, at the seam, or the new model will mis-attribute a previous model's limitation to itself.

- **Bound WIDE delegation with a live pool, and reject rather than wait when the pool is full.** `.agents/notes/archived/feature/2026-09-15-continuable-activation-capacity.md:26` — "Waiting for capacity can deadlock when every slot belongs to a parent waiting for a descendant. Full pools reject with an actionable diagnostic instead of retaining queued activation requests." The pool is per live parent, shared by reference through continuable parent links, and the owner is excluded (`:14`) — a cumulative child count was rejected because it does not release capacity when useful work finishes, and counting model requests was rejected because it omits waiting parents, queued inbox work, reconstruction and cleanup. August's subagent spawner should carry a *live* concurrency budget with a reject-and-diagnose path, never a cumulative counter and never a blocking wait.

- **A run belongs to the job registry, not to the tool step that started it.** `.agents/notes/archived/feature/2026-09-01-workflow-run-in-background.md:18` — the engine starts inside the job starter with **no** `exec.signal`, so the returning tool step's abort cannot kill work the model deliberately detached; `job_kill`, the job list's stop control and owner teardown are the only cancellation paths, and each forwards its reason into `run.cancel`. August's background-tool surface has the same trap: bridging turn-abort into a detached job turns "cancel this turn" into "kill my long job".

- **Snapshot the working tree with a PRIVATE git index so the user's repository gains no objects and the user's uncommitted work becomes the baseline.** `.agents/notes/archived/feature/2026-09-11-turn-changed-files-card.md:16` — `add --all` into a private index seeded from the repository's index, then `write-tree`, both writing into a Session-owned temporary object directory with the repo's object store attached read-only as an alternate; the two tree ids are diffed with `diff-tree -r -M --numstat`. Because the baseline includes the user's earlier uncommitted work, the summary contains exactly the turn's changes and a commit the model makes mid-turn cannot hide them. August's "files changed this turn" card should use this shape rather than diffing against `HEAD` (which attributes the user's work to the turn).

- **The card's lifetime equals the content's lifetime, not the log's — so the log carries only an index.** `.agents/notes/archived/feature/2026-09-11-turn-changed-files-card.md:26` — "The log deliberately carries nothing but the turn number. Summaries, snapshot trees, and captured copies live only as long as the Session in the Host process … a card whose content the Host can no longer open should not appear at all." August's session log is durable and its UI is not; anything the UI offers must either survive a restart or be explicitly scoped to the live process. The same note's per-Session temp directory replaced a shared per-repository store because the shared store "needed two configuration fields, and made a Session's snapshot fail when another Session discarded the store".

- **Compare uncovered files from whole-file copies, with a hard byte cap and a timeout that degrades to a coarse hunk.** `.agents/notes/archived/feature/2026-09-15-changed-file-diff-preview.md:18` — `maxFileBytes` caps a copy and a snapshot blob read, a larger file is listed `oversized` *without counts* and its comparison is refused, and `diffTimeoutMs` (100 ms) degrades the comparison to one hunk replacing every line, marked `coarse`. Two sides that both exceed the cap are listed `oversized` rather than dropped, "since unread content is never known to be unchanged". August's diff surfaces should degrade *visibly* rather than silently truncate.

- **Configuration that grants a capability must be withheld until an accepted value arrives, and an absent response is never consent.** `.agents/notes/archived/feature/2026-09-20-developer-tools-default-on.md:16` — "Host-backed clients publish disabled until an accepted schema-resolved value arrives. Loading, failed initial reads and an unavailable namespace do not grant interactive-preview capabilities … the client does not interpret an absent response as consent to enable scripts." The reason is the one August repeats in its own docs: "unmounting a scripted HTML iframe cannot undo scripts or requests already executed". Any August toggle that turns on script execution, network access or a tool surface must be fail-closed at the moment of uncertainty, even when the eventual value is permissive.

- **Classify an error at the route that owns the credential, and keep the durable record provider-neutral.** `.agents/notes/archived/feature/2026-09-18-account-quota-top-up.md:14` and `:16` — the account plugin's credential callback releases the token only for the configured inference origin, and it rewrites the provider-neutral `QUOTA` into `ACCOUNT_QUOTA` for both HTTP 402 and in-band SSE errors, while the API-key route keeps `QUOTA`; the durable terminal-error record keeps the request-time code so the transcript, history paging and session log "do not depend on current credentials". The rule behind it — "current endpoint, key, and login state may differ from the facts of a historical failed request" — is exactly August's problem when a provider key is rotated and old sessions are reopened.

- **Classify tool-call surface by *configuration*, not by connection health.** `.agents/notes/archived/feature/2026-09-13-mcp-resources-in-profiles.md:18` — "Connection health does not determine this visibility. An active client remains configured through failed requests and reconnect attempts; its shared resource tools and server-name guidance stay available, and calls report connection failures." The rejected alternative is instructive: filtering by *negotiated capability* would make visibility require a successful capability exchange, so the tool set would flicker. August's MCP and provider surfaces should keep their schemas stable across a reconnect and let the call fail instead.

- **A redundant permission request that asks for nothing new must not be fatal.** `.agents/notes/archived/feature/2026-09-16-sandbox-same-mode.md:14` — `approveEscalation` returns the effective mode immediately when the requested mode matches it; wider modes still require approval and narrower or unsupported targets still fail. The stated reason: rejecting every non-widening request "prevents authorized work without preventing any permission increase". August's `sandbox_permissions` re-assertion path is the same case, and the ACP `fs-same-mode` snapshot is a good shape for a regression: verify an unrestricted write with **no approval events**.

- **A path is addressed by machines; a label is addressed by people — never let one string be both.** `.agents/notes/archived/feature/2026-09-23-language-neutral-default-workspace-naming.md:16` — the directory name and stored title are one fixed, language-neutral constant (`default-workspace`), published from a pure import-free subpath "so client bundles inline it rather than requesting a module-table row the package does not publish"; only the on-screen label is localized, and the rename dialog decides "did this change?" by comparing the **stored** title, not the displayed one. August's workspace/root naming is addressed by shell commands, tool arguments, `@path` references, session logs and backups — it must not depend on the UI language that happened to be active at install.

- **Apply a vocabulary only after the message settles, or a frozen streaming block will cache it.** `.agents/notes/archived/feature/2026-09-07-session-prose-local-media-display.md:16` — "Like `fileMentions`, it applies only after a message settles so frozen streaming blocks cannot cache a vocabulary handler." August's markdown renderer has the same hazard with any post-settle transformation (file links, media, code fences): a handler installed during streaming gets captured by the frozen block and applied forever.

- **Per-tab state, not per-file state, when two views of one thing can be open at once.** `.agents/notes/archived/feature/2026-09-05-sidebar-text-preview-and-file-tree.md:40` — "Bucketing by tab, not by file, is deliberate — two tabs of one file scroll independently"; and `:44` — "A changed file is announced, not applied", because reloading under the reader loses their place and an agent-written file changes repeatedly. August's own "two tabs of one file" case (a file preview and a diff review of the same file) should keep two independent view states, and any live-refresh of a file the user is reading should be an announcement rather than an in-place replacement.

- **Announce a change, do not apply it, when the file is changing under the reader.** `.agents/notes/archived/feature/2026-09-05-sidebar-text-preview-and-file-tree.md:44` — the body compares the loaded version with the observed version and shows a change bar; "Reload rereads only this tab … and does not mutate shared resource metadata or another tab." The rejected alternative is the interesting part: refreshing under the reader "loses their place, and a file the agent is writing changes repeatedly."

- **One constant for a bound, read by every place the bound is stated.** `.agents/notes/archived/feature/2026-09-24-fixed-rate-floor-one-minute.md:14` — `MIN_EVERY_INTERVAL_SECONDS` is read by the Host decoder, the create and update validation, the `every_seconds` tool parameter description and the refusal message, "so one change moves the bound everywhere the Host states it"; the client keeps its own copy for per-unit floors. August's budget/round/tool-output ceilings are stated in many places (tool descriptions, refusal messages, UI hints, docs) — this is the shape that keeps them from drifting.

- **Read the environment from the account record, interactively, and protect the app's own namespace.** `.agents/notes/archived/feature/2026-09-28-desktop-login-shell-environment.md:14` — one delimited `env -0` dump through `<shell> -ilc` using the **account record's** login shell (not `$SHELL`, which a Dock launch inherits from launchd), in interactive mode (because `~/.zshrc` is only read by interactive shells), with `DSH_*` and `ELECTRON_*` protected from being replaced — "Desktop resolves `DSH_HOME` and its profile paths before the read". The delimiter is the right completion signal: "waiting for stdout to close" turns every read into a timeout when a startup file backgrounds a process.

- **Publish the *preference*, not the resolved value, when a native surface must keep following the OS.** `.agents/notes/archived/feature/2026-09-13-macos-hidden-titlebar-vibrancy.md:20` — `html[data-ds-theme-source]` carries `light` / `dark` / `system`, and forwarding `system` "lets macOS keep following the OS appearance natively", while forwarding `light`/`dark` would "freeze the window material at the value resolved at send time". August's theme and native-window decisions should carry the intent, not the resolution.

- **Suppress only the ring paint; keep the DOM focus.** `.agents/notes/archived/feature/2026-09-20-focus-ring-brand-primary.md:22` — in pointer modality, `:focus-visible:not(:read-write)` controls use a transparent ring colour while "selected-state borders and elevation shadows remain, and editable text controls keep their own focus feedback on click. DOM focus stays on the control." The rejected alternative explains it: calling `blur()` "would hide its ring but also remove the target for subsequent Enter or Space activation". A generalisable UI rule for August's desktop surface.

- **A dismissed surface stays dismissed: give the dismissal an identity, not just a flag.** `.agents/notes/archived/feature/2026-09-14-composer-selection-keyboard.md:28` — `InputTriggerController` records the identity of the hit the user closed (Escape / Shift+Tab, a pointer dismissal, or a settling pick), and a re-track of that same token with the same query leaves the menu closed, "so restoring the caret after a dismissal (or a settled command closing the surface it opened) cannot revive it. A new query or another token re-arms it." August's composer/panel surfaces reopen on focus and re-render; a token-keyed dismissal rule is what stops a dismissed panel from springing back.

- **A keyboard contract that mirrors the surface it belongs to, applied once and inherited everywhere.** `.agents/notes/archived/feature/2026-09-14-composer-selection-keyboard.md:18` — Enter/Tab settle, Escape/Shift+Tab leave, and the *shared* `Menu` primitive adopts the pairing, so the composer's permission seat, the preset chip, file cards and the settings dropdowns all get it "at once"; and the composer's own `focus()` is used to restore the caret "where the draft left it rather than at the start", because "the owner of the caret is the only party that can restore it". August's own composer surfaces should share one primitive and one focus-return method rather than each re-implementing dismissal.

- **A denial that asks for no additional permission should return immediately; a denial that asks for more must not be silent.** (Sandbox and update-policy pairing.) `.agents/notes/archived/feature/2026-09-11-desktop-mandatory-update-client.md:18` — a flattened `40005` establishes blocking independently of the optional title/detail/page fields, and "Transport, JSON, business-code, or HTTP failures cannot clear a known block. Only a valid fresh no-force response clears it." The transferable pattern: a *block* may be established by a minimal code, but only a complete, fresh, valid response may lift it — every failure mode must leave the block in place.

- **A failure that is confirmed but unsuccessful is a distinct outcome from a failure that is not confirmed.** `.agents/notes/archived/feature/2026-09-11-desktop-mandatory-update-client.md:32` — "Host exit and successful task teardown are separate outcomes. The process owner reports confirmed but unsuccessful exit with a dedicated error type. Backend cleanup can complete for that outcome while installation still fails; the shell restores the current-version Host and requires fresh installation confirmation without clearing mandatory policy." August's turn-end reasons (`finished | length | cap | stall-stop | budget | error | interrupted | awaiting-input`) already encode this idea; the transferable part is the *cleanup* half — a confirmed teardown still permits backend cleanup, and the retry does not need to redo it.

- **A change is announced by a diffable, bounded artifact, not by a re-render of the thing under the user.** `.agents/notes/archived/feature/2026-09-11-turn-changed-files-card.md:14` — the `workspace/changes` event "is log-only and never model-visible", and the summary is served through a service rather than the log. August's turn summary should be served, not logged, whenever it carries content — and the same split explains why the log carries only a turn number.

- **Give a model a *code* to look up, and a durable id to group by — never encode structure in free text.** `.agents/notes/archived/feature/2026-09-08-feedback-dialog-and-categories.md:26` — "a prefix in free text is not filterable without parsing and would leak into the verbatim note that telemetry uploads; a durable id in the payload is what a consumer can group by." The companion rule is that the taxonomy must be **restated** in the client as a `Record<Category, true>` because the client-bundle purity gate forbids a value import from a Host package, with completeness checked by the compiler. August's skill categories, memory kinds and tool taxonomies should follow both halves.

- **A tool call that asks for the mode already in force must not be fatal — and the argument contract stays mandatory.** `.agents/notes/archived/feature/2026-09-16-sandbox-same-mode.md:14` — `approveEscalation` returns the effective mode when the requested mode matches it, while "Argument pairing remains mandatory at the tool. Wider modes still require approval; narrower and unsupported targets still fail."

- **Model-input changes are applied through a *draft* until the user starts, and the completion marker is written last.** `.agents/notes/archived/feature/2026-09-16-desktop-onboarding.md:18` — "Completion applies Chat and shared developer-tool preferences before saving the done marker, so a refused preference write cannot silently finish onboarding"; and the three writes are ordered but **not one transaction**, so a retry can re-apply the same preference after a failed completion write. August's own settings+onboarding paths should use the same order and be honest that the sequence is not atomic.

- **Per-model capability declaration must be non-empty and must be the same gesture in every adapter.** `.agents/notes/archived/feature/2026-09-16-unified-model-input-controls.md:24` — "DeepSeek rejects an empty list and pi-ai treats it as inheritance. Keeping a nonempty selection prevents the same gesture from meaning different things across adapters." The companion: an undeclared field must *display* the inherited capability without materialising an override on open, and disabling a capability must also clear the settings the adapter refuses to save with it (DeepSeek's image limits).

- **A shared "capability" switch that changes *what is rendered*, not merely what is visible.** `.agents/notes/archived/feature/2026-09-17-developer-tools-settings.md:18` — turning the switch off filters the available View roster and **remounts** the HTML context, because "previously selected diagnostic content and already-running scripts would survive the toggle"; the basic mode strips `href` attributes, resource hints and SVG animation and mounts an iframe with a CSP denying scripts and external resources, while the advanced mode gains no parent-origin, popup, form or top-navigation privileges.

- **A file that changed under the user is not an error — it is a different file.** `.agents/notes/archived/feature/2026-09-08-file-display-through-filesystem.md:30` — "the local sandbox provider constrains mutations and permits reads; an authenticated client therefore has broader access than registered workspace roots." The same note's "Encoded byte limits do not bound decoded pixel dimensions" is the kind of limit that must be *stated* rather than assumed: a 20 MiB compressed image can still be a decompression bomb.

- **A `present`-style delivery must be a snapshot, and the authorization must be a saved coordinate triple — never a browser-supplied path.** `.agents/notes/archived/feature/2026-09-09-present-filesystem-access.md:18` and `.agents/notes/archived/feature/2026-09-08-web-explicit-file-delivery.md:16` — download and native-open requests authorize a reference by "the viewed Session, event sequence, and file index"; the event stores no Session ID, so a forked history uses the child's own log. And a native open must require a *verified round trip* through the composed filesystem — "a same-named local file never substitutes for an unmapped provider file."

- **The API of a tool should discriminate its result shape, and the two shapes should share a name.** `.agents/notes/archived/feature/2026-09-01-workflow-run-in-background.md:21` — the output schema becomes a `kind`-discriminated union (`background` | `foreground`), with the foreground envelope gaining `kind: 'foreground'` "for symmetry". A consumer can then branch on one field instead of sniffing for the presence of a job id.

- **An advertised address is not an authorised address.** `.agents/notes/archived/feature/2026-09-07-public-web-deployments.md:14` — `--public-url` supplies the printed URL, `DSH_WEB_URL` and the web-surface orientation "and configures no routing, client transport, or cookie scope"; the browser-visible authority must be named with `--trusted-host` and the fence still validates `Host` and `Origin` per request, "so advertisement grants neither identity nor authentication".

- **Make a note's *value* explicit, so a future reader can tell whether the decision still applies.** The shard's own corpus demonstrates it: every note carries `Status:` and, once archived, an `Archived:` line, and the sidecar pins both language sides so the two cannot drift. `.agents/notes/archived/feature/2026-09-09-headless-machine-readable-run-surface.md:80` (the deferred list, naming the unimplemented `--model` override, the cold-start cost, the stderr-colllector blind spot and the 8 KiB/32 KiB caps) is the model to copy: a decision record that names what is *not* done is one a future agent can act on, and one whose alternatives are recorded can stop a re-litigation.
