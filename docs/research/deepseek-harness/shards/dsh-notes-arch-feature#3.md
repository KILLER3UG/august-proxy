# deepseek-harness / dsh-notes-arch-feature#3

## Shard shape

This shard is the **archived `feature` decision log** of the deepseek-harness repo, restricted to the window 2026-08-05 → 2026-09-01. It contains 260 files in exactly three shapes per decision: the **English agent note** (`.md`, 87 files — the substance), its **Chinese translation** (`.zh.md`, 87 files), and a **bilingual-pair consistency record** (`.i18n.yaml`, 86 files — the git blob hash of each side plus the `pnpm run verify-translation-pairing --write` command). The one exception is `2026-08-05-per-agent-tool-presentation`, the oldest note in the shard, which predates the i18n pairing records and therefore has no `.i18n.yaml` sibling. Every note follows the same five-part template — `Problem` / `Decision` / `Alternatives considered` / `Consequences` (plus `Testing` or `Verification`) — and every note records *rejected* alternatives with the reason, not just the chosen design.

The modules the shard covers, in descending order of depth: **(1) subagent delegation and continuable children** — interrupt, settlement delivery, policy inheritance, approval pinning, parallel dispatch, model-selected routes, human inbox control, named instances, one-shot background tasks, bounded failure facts, minimal out-of-process diagnostics; **(2) the background-job / shell execution runtime** — job registry, whole-snapshot frames, completion-wakes-owner, human kill, `execute()` projection, activity observation seam, unified task list; **(3) the Web client surface** — composer, transcript folding, tool cards, turn rail, stats pills, settings pages, theming, manifests; **(4) provider/adapter surfaces** — pi-ai per-model reasoning declarations, pi-ai wire-compat drift gate, DeepSeek identity headers, MCP client reconnect; **(5) durable session primitives** — arbitrary-seq fork, per-turn token usage, route-priced image pressure, telemetry consent.

The architectural through-line is: **the harness treats a decision as finished only when the *rejected* options are written down with their failure modes, and treats a UI feature as finished only when the model-visible surface and the human-visible surface are separated by an explicit seam.** Almost every note's "Alternatives considered" section is a catalogue of bugs the current design is shaped to avoid.

### English notes — the substance (`.md`)

### `.agents/notes/archived/feature/2026-08-05-per-agent-tool-presentation.md`
- **Purpose:** Give an agent *preset* a per-agent tool *presentation* (how tools reach the model) without moving the tool registry out of the host plane.
- **Key abstractions:** `ToolRuntime.presentAs(mode)` — scoped-only, mirrors `restrict()`, writes one cell on the calling scope's `ToolLayer` through `ScopedLayers.effect`; `modeFor(scope)` takes the nearest declaration on the chain.
- **Data flow:** A preset row (`@deepseek-ai/dsh-agent-tool-presentation`, body is a single `presentAs` call) mounts a standing scope → every agent joined to that preset inherits the mode → the three readers (wire schemas, `run_code` visibility entry, generated SDK section) take the scope's mode.
- **Non-obvious design decisions:** The registry stays host-plane because `dsh-agent-loop` reads a private scheduler seam, `dsh-apiproxy` reads its presenters, and every tool plugin registers into it — the stack's own rule is a service moves into a preset only when *all* its consumers move with it. `run_code` is appended *per scope* (a native agent must not find it because another agent in the process presents it) and the transport is built lazily. The reserved name `run_code` became unconditionally reserved, because any agent may now select PTC mode.
- **Edge cases / failure handling:** A PTC mode against a runtime-less deployment fails where an operator can act — the row waits for `ctx.codeRuntime` through `ctx.inject` and `dsh-agent-presets` already reports an unusable mount *by name*.
- **Surprising:** `ctx.tools.schemas(agent)` remains the agent's *capability* catalog and is unchanged by presentation; only the assembly collapses. Tests asserting what the model receives must read the assembly, not the schema list.

### `.agents/notes/archived/feature/2026-08-05-pwsh-ui-bash-parity.md`
- **Purpose:** Make the pwsh tool's human-visible result card identical to bash's (terminal card + parsed exit-status pill) rather than a generic `console` fence.
- **Key abstractions:** `parseExitStatus` / `ParsedExitStatus` — moved from `dsh-tool-bash`'s private render module into the `@deepseek-ai/dsh-shell` Service Definition package.
- **Data flow:** Completed foreground pwsh result → `presentResult` → `terminal` card view → the client's terminal-card bridge (`terminal-card-model` in `dsh-client-ui-conversation`) renders it; `classifyTool('pwsh')` yields the shell-family row.
- **Non-obvious design decisions:** The parse was *moved*, not duplicated, so one Service-Definition-owned inverse can never drift between the twins. Importing it from `tool-bash/src/render.ts` was rejected: workspace imports stay external in built bundles, so `tool-pwsh` would gain a hard runtime dependency on its twin in every consumer closure.
- **Edge cases / failure handling:** Background acknowledgements, `isError` results and multi-block results stay generic `console` cards / `undefined` — the parity is call-for-call, not blanket.
- **Surprising:** The shell's marker emission and the exit-status parse are the *same* contract; a copy would drift silently, which is exactly the defect this note closes.

### `.agents/notes/archived/feature/2026-08-06-agent-teams-web.md`
- **Purpose:** Expose the experimental Agent Teams runtime to the Web GUI without adding Team contracts to any stable package.
- **Key abstractions:** `ctx.agentTeams` owning generated `agentTeams/view|createTask|updateTask` Remote methods; a browser-safe Team view/mutation-result type set owned by the Team package.
- **Data flow:** A Team service method → generated Remote → `ctx.remote.agentTeams` → the experimental client-ui package renders roster, model, diagnostics and the task board.
- **Non-obvious design decisions:** Views deliberately omit pending mailbox content and deleted-task tombstones. Rejections cross Remote as *closed business results* (`team-task-conflict` for a stale revision, `team-rejected` otherwise), not as transport errors. Teammate navigation reuses the existing `{ parentSessionId, childSessionId, mode: 'continuable' }` address with no Team tag, so stable Client/Subagent contracts stay uncoupled from experimental mailbox policy.

- **Surprising:** A top-level Agent Teams profile *cannot* replace stable Web preset registrations, so the experimental composition may expose both a Team roster and legacy child controls — a documented limitation, not a bug.

### `.agents/notes/archived/feature/2026-08-06-continuable-subagent-interrupt.md`
- **Purpose:** Let a human or an ancestor stop a *running* continuable subagent without destroying it.
- **Key abstractions:** `ctx.subagents.interrupt(targetSessionId, authority)`; a closed two-variant authority union `{ kind: 'user', parentSessionId } | { kind: 'ancestor', agent }`; Host RPC `subagent.interrupt`.
- **Data flow:** RPC → core primitive → synchronous authorization → `Agent.cancel(cause, { keepInbox: true })` → returns `void` (fire-and-return: the signal is *issued*, quiescence is not awaited).
- **Non-obvious design decisions:** `keepInbox` parks the unclaimed pending queue at idle, so an interrupt never auto-starts the next queued follow-up — resuming is an explicit human act, which keeps the stop observable. Authority is deliberately *wider* than delivery authority because stopping a turn is idempotent and delivers no content; `send_message` keeps exact-direct-parent authority. The `{kind:'user'}` variant matches the live target's `session.header.parentSession` and touches no live parent Agent, catalog read or persistence — that is exactly what keeps a child stoppable while its parent is offline.
- **Edge cases / failure handling:** An absent id — unknown, one-shot or naturally settled — is an accepted no-op, which uniformly covers completion races and repeat requests without leaking durable-catalog information. A target whose disposal transaction is already open is an accepted no-op after authorization. A mismatched parent address maps to `subagent-unauthorized`; unexpected failures map to `internal` without leaking error text.
- **Surprising:** The postcondition is deliberately weak — `accepted` means "signal issued", so a target may remain visibly `running` until it observes the signal, and clients must render that honestly.

### `.agents/notes/archived/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md`
- **Purpose:** Give a parent a reliable account of how each continuable child ended — the one async operation a model could start but could not reach the end of.
- **Key abstractions:** `createSettlementMessage()` (in `dsh-session/continuation-messages.ts`); the notice kind `subagent-settled` with `form: 'notice'`; `foldConsumedWork()` in `dsh-agent`; `epochStopReason()`.
- **Data flow:** Child Activation settles → `notifySettlement()` inside the disposal transaction → resolves the durable direct parent → sends one **user-role** message (outcome sentence + closing text, or "It left no closing message.") → parent claims it as a normal inbox message.
- **Non-obvious design decisions:** *The send happens before `releaseOwnership`* — afterwards the settlement predicate can succeed and race a watcher that disposes an Agent whose `cancel()` clears the very inbox the notice sits in, producing a silently missing message with no error anywhere. A resident parent receives it through its *private* `SubagentInbox`, because the wrapper checks the closing promise immediately before the synchronous waking send. The account is derived from the **epoch's own log**, not from live state: `Inbox` logs every mutation with `removedCount` and marks cancellation `outcome: 'canceled'`, so a turn that claimed its input can be distinguished from work dropped unrun. Delivery is *unconditional* — it does not consult whether the child reported — which is what lets the tool description promise a runtime notice.
- **Edge cases / failure handling:** A materialization rolled back before its first accepted message stays silent (the caller was told the child was not established). A parent whose own teardown began gets an *inject* rather than a wake, because waking would start a real model request on an Agent about to be destroyed, once per tree layer. A busy parent is *steered* at its nearest step boundary, so four children settling together cost one step rather than four turns. Delivery never blocks or fails teardown: a rejected send is logged and dropped, because retaining a child to retry a notice would pin its whole ancestry in `waiting` forever.
- **Surprising:** The notice is a **user-role** message with a `subagent-settled` source, deliberately *not* the `agent-message` kind — merging them would credit the child with words it never wrote and would make a durable log unable to distinguish "the child said it was done" from "the harness observed that it stopped". Stop-reason attribution is best-effort over the log's splice vocabulary and errs toward a parent double-checking a finished child, never toward trusting an unfinished one.

### `.agents/notes/archived/feature/2026-08-06-mcp-client-auto-reconnect.md`
- **Purpose:** Recover a crashed stdio MCP server without a human editing config or restarting the Host.
- **Key abstractions:** A per-instance connection supervisor in `packages/mcp/mcp-client/src/connection.ts`; client/transport *generations*; the `isCurrent` fence; `resolveReconnectPolicy()`; a `reconnect { enabled, initialDelayMs, maxDelayMs, maxAttempts }` config block.
- **Data flow:** `client.onclose` fires (stdio child exits) → supervisor arms a retry → fresh transport + fresh `Client` per generation → one serialized `syncTools` queue → atomic dispose-previous/register-next swap.
- **Non-obvious design decisions:** The **stability window is derived** from `maxDelayMs` (the longest configured backoff spacing) rather than being a fifth tunable: a connection that survives that window resets the outage budget, so an occasionally-crashing server recovers indefinitely while a crash loop whose connects briefly succeed cannot launder its budget into a restart storm. A failed attempt cannot enter backoff until *both* `Client.close()` has settled *and* the transport has reported `onclose` — for stdio that proves the child exited, and a missing close signal stops reconnection rather than allowing two server processes to overlap. The last-good generation stays registered during an outage, so the model-visible schema prefix stays stable instead of flapping.
- **Edge cases / failure handling:** Failure signals are idempotent per generation (a connect rejection racing its own transport close schedules exactly one retry). The activation attempt, not the first queue entrant, owns strict startup registration, so an early `list_changed` cannot consume `failOnStartupError`. Disposal flips the fence, cancels the timer, closes the client, then awaits the in-flight attempt *and* the sync queue before unregistering — quiescence, not a request to stop. The reconnect timer is `unref`'d.
- **Surprising:** `StreamableHTTPClientTransport` fires `onclose` only for deliberate closes, so HTTP servers are effectively *outside* supervisor restarts — a limitation recorded in the package README rather than papered over.

### `.agents/notes/archived/feature/2026-08-06-session-completed-done-dot.md`
- **Purpose:** Signal that a delegated session finished while the operator was looking elsewhere.
- **Key abstractions:** A client-side completion-reminder set owned by `SessionManager`, a sibling of the pending-interaction bit.
- **Data flow:** A running→idle edge of a *non-selected* session arms the reminder → `select()`/`selectSubagent()` consume it → the bit rides `SessionListEntry` → `SessionSummary` (optional) → the workspace browser renders the existing `StateDot` `done` state.
- **Non-obvious design decisions:** The reminder is in-memory and per browser: it survives connection generations (a transport blip does not invalidate "you have not looked yet") but not a page reload. The completion edge is detected *eagerly at every list mutation and pull* — a snapshot-build-time-only pass would collapse two consecutive status frames into one observation and miss the completion.
- **Edge cases / failure handling:** Starting a new run disarms the reminder and its completion re-arms it; removal prunes it.
- **Surprising:** The sidebar now carries three disjoint signals — green = finished and unviewed, amber = awaiting input, blue = running — and no wire, on-disk or configuration format changed (`SessionSummary.completed` is optional).

### `.agents/notes/archived/feature/2026-08-06-web-queue-steer-all-gesture.md`
- **Purpose:** Replace N clicks with one gesture to steer every queued message into the running turn.
- **Key abstractions:** `ComposerKeyboard.steerQueue()`; `SessionInputShell.steerQueue()`.
- **Data flow:** Empty-draft Cmd/Ctrl+Enter → `InputBar.onKeyDown` decodes the accelerated chord → the hub re-reads the authoritative `session/queue` snapshot → filters `placement: 'queued'` → applies the queue dock's exact `session.updateQueue(itemId, { kind: 'steer' })` operation *sequentially*, so FIFO is guaranteed at the host.
- **Non-obvious design decisions:** The gesture and the per-row button are the *same* host operation, so races and failure semantics stay identical; the client gate is advisory and the host stays authoritative. The queued rows are steered sequentially because arrival order at the host is not guaranteed and steering order is model-visible.
- **Edge cases / failure handling:** A `steer-unavailable` (turn closed mid-flush) or `queue-item-not-found` (row claimed meanwhile) converges silently; any other failure surfaces one composer notice.
- **Surprising:** The gate is strictly the accelerated chord — plain Enter with an empty draft stays a no-op even under the busy-Enter Steer preference, and draft content outranks the queue (accelerated Enter steers only the draft).

### `.agents/notes/archived/feature/2026-08-06-web-skill-tool-row.md`

### `.agents/notes/archived/feature/2026-08-07-default-model-follows-the-picker.md`
- **Purpose:** Make the session model picker and the deployment default one preference, not two layers.
- **Key abstractions:** `ctx.agentDefaultModel` / `AgentDefaultModelConfig`; the `agent-default-model` Settings section; `ApiProxyDefaults.defaultModelSelection()` / `saveDefaultModelSelection()` closures.
- **Data flow:** `session.selectModel` applies the `ModelSelection` to the session *and* calls `saveDefaultModelSelection()`; `selectionFor(agent)` resolves its tiers on every read: a process-local session selection → the session's latest logged `request/header` → the live Agent default.
- **Non-obvious design decisions:** `reasoningEffort` belongs to the Settings section but *not* to the plugin config, because Settings layers merge by field and a configured effort would survive a user selection that omits it. `saveSelection()` therefore writes the *complete* user section, so absence clears a stored effort. A deployment-wide effort default belongs to the adapter profile, which resolves it per model. The stored selection does not require catalog membership — catalogs are advisory and may omit requestable models.

- **Surprising:** `session.prompt` refuses with `model-unavailable` before opening a turn when no adapter serves the session's provider — that method, not the disabled composer, is the enforcement boundary.

### `.agents/notes/archived/feature/2026-08-07-web-inline-file-mentions.md`
- **Purpose:** Make a file named in inline code in the closing message clickable.
- **Key abstractions:** `producedFileMentions`; the optional `chatFileMentions` service; the `MarkdownFileMentions` resolver contract; the static `ui:deliverable-file-references` prompt section.
- **Data flow:** `MarkdownText` consults the resolver for inline-code tokens (after URL promotion, never inside an anchor) → the resolver matches an exact path, or a basename that is the basename of exactly one produced path → the link opens the file.
- **Non-obvious design decisions:** The renderer owns *no vocabulary* — the provider (ui-deliverables) decides what names a file, so one `cordis.yml` line composes the row and the prose links in or out together, and `ui-primitives` gains no session concepts. The provider also owns the *model guidance* for its accepted syntax, so the renderer and its prompt cannot drift or be composed independently. - **Surprising:** The prompt section is constant for the package mount and therefore **remains cacheable across Turns** — a UI feature that does not damage the provider prefix cache.

### `.agents/notes/archived/feature/2026-08-08-dsh-run-headless-command.md`
- **Purpose:** Give one-shot headless execution a single unambiguous top-level verb.
- **Key abstractions:** `RunInvocation` as a distinct `DshInvocation` member; `dsh run [--profile <name>] [--patch <path>...] <task...>`.
- **Data flow:** Commander joins the variadic task arguments → `runProfile` supplies the task → the headless profile executes one fresh persisted Session and prints the final assistant text on stdout.
- **Non-obvious design decisions:** A root grammar that accepts optional task text makes one argv shape mean either a long-lived process or a terminating task according to a plugin row discovered only after composition — so the `run` verb owns one-shot execution and application-file launch requires a distinct command name. `--profile` defaults to `headless`; `--patch` is repeatable and occupies the normal overlay layer.
- **Edge cases / failure handling:** Commander rejects a missing or blank task before boot. A one-shot profile without `headless-runner` fails through the composed-row check; profile boot containing that row without a task points to `dsh run --profile <name> "<task>"`.
- **Surprising:** This note is marked *superseded* (apps now own their command lines) but is retained as the rejected launcher-owned design context — the archive keeps the reasoning, not just the outcome.

### `.agents/notes/archived/feature/2026-08-08-pi-ai-per-model-reasoning-declarations.md`
- **Purpose:** Let a hand-declared or per-catalog model declare which reasoning levels it accepts and how each is spelled on the wire.
- **Key abstractions:** `PiAiModelProfile.reasoningEfforts` — *each key is a level the selector offers, its value the spelling dispatch sends*; `modelOverrides`; `compat.thinkingFormat` / `compat.supportsReasoningEffort` at route and model level.
- **Data flow:** The declaration translates to pi-ai's `Model.reasoning` + `thinkingLevelMap` with all seven levels decided explicitly → `getSupportedThinkingLevels` reports the declared levels → `resolveModelInfo` surfaces them through the same seam catalog metadata uses → the composer effort pane works with zero UI change.
- **Non-obvious design decisions:** The **key set is the offer** — the profile author never needs pi-ai's asymmetric defaulting rule (absent means "supported" for the five base levels but "unsupported" for `xhigh`/`max`). `off` is the one three-state key: left out → no Off is offered and an explicit Off request is refused; declared valueless → Off is offered and dispatch sends nothing; declared with a value → that value goes on the wire. The "disable" spelling is `false`, not `{}`, because schemastery materializes an absent dict as `{}`. `modelOverrides` reshapes individual catalog models *without replacing the served set* — unlike Pi's own config layer, an override that lands nowhere is refused.
- **Edge cases / failure handling:** A bare `reasoningEfforts:` (YAML null) slips through the `z.union([z.const(false), dict])` unvalidated, so resolution refuses it explicitly. A smuggled `id` in an override value would quietly rename the model — the schema passes unknown keys through, so it is refused.
- **Surprising:** The route-level `reasoning` knob is a *default selection*, not a capability set; it stays, and a declared model's efforts now bound what it can select. 66 of 1230 installed map entries are non-identity (`off→none`, `minimal→low`, `low→LOW`, `high→default`), which is why a bare level list cannot express the real cases.

### `.agents/notes/archived/feature/2026-08-08-user-explicit-skill-invocation.md`
- **Purpose:** Make `/skillname` in a user message load that skill, deterministically, on every entry point.

## Ideas worth stealing

- **A cancelled turn must not destroy the work it was running** — `.agents/notes/archived/feature/2026-08-06-continuable-subagent-interrupt.md:14` — `Agent.cancel(cause, { keepInbox: true })` stops *only the current turn*, leaves the Activation, the handle, the descendants and the unclaimed queue intact, and returns `void` because "the cancel signal is guaranteed issued, target quiescence is not awaited". August's `message_agent` / delegated-worker path has the same shape of problem: a stopped child should keep its queued follow-ups and its identity. The transferable trick is the **parked queue**: `keepInbox` parks the pending work at idle so an interrupt never auto-starts the next queued item — the human gets a window to redirect, and an explicit waking send resumes the preserved FIFO.
- **Deliver a settlement notice BEFORE the ownership release, not after** — `.agents/notes/archived/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md:34` — the failure mode is a *silently missing message with no error anywhere*: after `releaseOwnership` the settlement predicate can succeed, a watcher resumes one microtask later, finds itself childless and disposes an Agent whose `cancel()` clears the very inbox the notice is sitting in. August's `message_agent` wake-up path has the identical structure (a parent waiting on a child that settles), so the ordering rule and the "the manager holds the parent reference throughout disposal" principle transfer directly.
- **Derive "did the child's work actually run" from the durable inbox log, never from live state** — `.agents/notes/archived/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md:58` — "The missing fact was never the turn's; it was the inbox's." `Inbox` logs every mutation with `removedCount` and marks cancellation `outcome: 'canceled'`, and `foldConsumedWork()` folds both vocabularies into one answer. An earlier version sampled the manager's own Activation immediately before cancelling, which could only ever see cancellations that manager was about to perform — so an ancestor's interrupt or an unloading plugin left the sample false and the notice still saying `finished`. August's `turn_outcomes` ledger and settlement notices are exactly the place this belongs.
- **Make the reconnect budget reset on *uptime*, not on a successful connect** — `.agents/notes/archived/feature/2026-08-06-mcp-client-auto-reconnect.md:20` — the stability window is *derived* from `maxDelayMs` rather than being a fifth tunable, and a connection that survives it resets the outage budget. This is the difference between "an occasionally-crashing server recovers indefinitely" and "a crash loop whose connects briefly succeed launders its budget into a restart storm" — a distinction a naive consecutive-failure counter cannot make.
- **Fence stale generations and serialize the resync queue** — `.agents/notes/archived/feature/2026-08-06-mcp-client-auto-reconnect.md:18` — a fresh transport and `Client` per generation, an `isCurrent` fence that makes stale generations inert, and one per-supervisor queue that serializes every `syncTools` call. Without the queue, two rapid `list_changed` notifications re-synced concurrently and the dispose-previous/register-next swap could double-dispose one generation and leak another. This is the general shape August needs for any reconnection or re-registration path (MCP, provider, plugin).
- **Choose the completion-delivery lane from the owner's state, not from a preference** — `.agents/notes/archived/feature/2026-08-11-background-job-completion-wakes-an-idle-owner.md:22` — "A busy owner is injected, unchanged. An idle owner is woken with `followup()`." This is the exact fix for August's documented symptom that the model is told "you are notified in-session when a task finishes" and then the turn ends before the notice exists. The note also supplies the bound: an opt-in `maxConsecutiveWakes` cap restored by *claiming* a user message (not by its arrival), because the chain is self-exciting — a woken turn can start the job whose completion wakes it again.
- **A timeout should bound the WAIT, not the work; and nothing should change hands at the timeout** — `.agents/notes/archived/feature/2026-08-26-shell-execute-projection-and-jobs-at-start.md:26` — "Nothing changes hands at the timeout: not the process, not the abort signal, not the output." A foreground call starts the *same* job it would have started in the background and waits on it; if the wait expires the call returns `{ kind: 'promoted', jobId, timeoutMs, output }` and the job simply keeps running. August's foreground shell currently *kills* a timed-out command and discards the work, which the note identifies as "the single most common way a long build or install failed under the agent". The companion rule — register the job **at start**, not at the timeout — is what makes a human kill possible from the first second.
- **A human's cancellation must not claim the model's delivery** — `.agents/notes/archived/feature/2026-08-26-human-job-kill.md:18` — "A delivery claim means 'the terminal state has a committed delivery path to the model'". A human kill records the reason and leaves the settlement to the normal reporter, so the model still learns the task stopped. The note names the exact failure this prevents (Claude Code's shape: "the model learns nothing") and notes that a `notify: boolean` option was rejected because the registry cannot promise a notice — quiet delivery, unowned jobs and owner teardown all legitimately drop one.
- **Give the human a NON-CONSUMING read of the same stream the model drains** — `.agents/notes/archived/feature/2026-08-24-activity-observation-seam.md:36` — "The model keeps its consuming cursors (`job_output` semantics unchanged, zero prompt or tool changes anywhere in this work); observers get absolute offsets any number of readers can hold." The companion invariant is stated as a test, not a convention: "**No web path calls `ctx.jobs.read()`.** It consumes the single output cursor, so a browser read would silently take bytes the model's `job_output` will never see" (`.agents/notes/archived/feature/2026-08-08-web-background-job-display.md:101`). August's `job_output` has exactly this single-cursor property, so the two-regime split is a direct template for adding a live "watch this build" panel without stealing bytes.
- **Price compaction pressure with the ROUTED model's own projection, while storing route-neutral facts** — `.agents/notes/archived/feature/2026-08-24-route-priced-image-request-pressure.md:18` — the meter's surface fold stores route-neutral facts per node and `measure()` prices them under the effective envelope's route on every call; the anchor holds its *raw materials* rather than a precomputed baseline, so a matching header reprices both the anchor and the current surface and the signed delta compares like with like. This is the template for August's image-dense compaction trigger, and for any future per-model cost difference: the replay stays single-pass and measurement stays O(surface).
- **Make the config's key set literally the set the model may choose** — `.agents/notes/archived/feature/2026-08-08-pi-ai-per-model-reasoning-declarations.md:16` — "each key is a level selectors offer, its value the spelling dispatch sends on the wire", with `off` as a deliberate three-state key. August's per-model reasoning-effort support has the same failure mode waiting: a route-level default that a model cannot take fails the request, and the operator needs a way to say "this model accepts exactly these levels, spelled this way on the wire" without knowing the provider SDK's asymmetric absent-key rule.
- **Refuse an unknown configuration key instead of warning about it** — `.agents/notes/archived/feature/2026-08-18-pi-ai-wire-compat-surface.md:42` — "That is the posture that hid this defect for the life of the surface: an accepted write and an unchanged failure teaches the operator that the switch does not work, not that the name is wrong." The companion mechanism is a **drift gate** that classifies every upstream field as `offer` or `withhold` (`:18`) so a provider SDK upgrade fails compilation until someone classifies the new field. August's provider-adapter config has the same exposure: a schemastery-passthrough unknown key that validates, persists and is then silently dropped.
- **Make a user gesture a host-side pre-step injection with closed-set matching** — `.agents/notes/archived/feature/2026-08-08-user-explicit-skill-invocation.md:16` — scan the step's claimed messages for whitespace-bounded `/name` tokens, resolve them against a *registry* (never a guess), check `isUserInvocable`, and append the injection after every other injection of the step. The transferable part is that the gesture works identically from every entry point (typed, menu pick, TUI) and cannot be forged by external text, because only `source.kind === 'user'` messages are scanned.
- **Do not let a route change silently destroy a fork's prefix cache** — `.agents/notes/archived/feature/2026-08-18-model-selected-subagent-routes.md:24` — a fork inherits the parent's provider and model "so its copied conversation prefix remains eligible for provider-side KV Cache reuse", and changing either component "requires the new route to prefill that inherited history again, and that recomputation can dominate the delegated task's cost". This is a direct, quantified answer for August's "cache-preserving forked children" question, and the note names the only acceptable future change: a route change that retains reuse, or an interface that makes the recomputation cost explicit and bounded.
- **Declare delegation concurrency-safe only when it is structurally safe** — `.agents/notes/archived/feature/2026-08-09-parallel-subagent-delegations.md:16` — `isConcurrencySafe: () => true` justified by structure (a child works in its own session; the run never mutates the parent session; the one shared write is a commutative insertion) rather than by a runtime check. August's fail-closed parallel tool-call scheduler needs exactly this kind of structural argument, and the note's gate test (two children blocking until both have started, so hidden serialization deadlocks rather than passing silently) is the shape of test that proves it.
- **Pin a delegated child's approvals to `never` and TELL the child so** — `.agents/notes/archived/feature/2026-08-10-subagent-approval-pinned-never.md:18` — "Every in-process child is told, not trapped": a scoped `subagent:delegation` runtime-context statement says the scope was fixed at start, approval-requiring operations are rejected automatically, and a task needing wider access should end with a reported limitation instead of retries. The statement is a runtime-context contribution rather than a system-prompt section, so the deployment's system prompt stays uniform across parents and children.
- **Let the durable child log own the delegation-time policy snapshot** — `.agents/notes/archived/feature/2026-08-10-continuable-subagent-policy-inheritance.md:16` — capture before the first await, and on cold resume append nothing, because "replaying the log IS the state". The consequence is the one August needs: "a parent switch between residency epochs never retroactively changes a durable child."
- **Exploit the forward-only, line-based nature of tokenizers to make streaming cheap** — `.agents/notes/archived/feature/2026-08-20-web-streaming-fence-highlight.md:17` — "a line's tokens depend only on its own text and the grammar state entering it, so appended text never changes a completed line's tokens", so the session caches completed lines' spans *plus* the grammar state after them and publishes only newly completed lines. The general lesson — look for the monotonicity in the expensive operation and cache the boundary, not the result.
- **Refuse to show a partial subtotal where a complete bill is implied** — `.agents/notes/archived/feature/2026-08-24-web-per-turn-token-usage.md:16` — every started attempt must close with safe non-negative integer usage *and* an exact total; "incomplete or contradictory evidence produces no row", because "a lower-bound subtotal presented in a completed Turn footer is indistinguishable from a complete bill". Directly applicable to August's per-turn usage chip, where the same reasoning applies to the *cached-hit* percentage.
- **Disambiguate "finished while you were away" with three disjoint signals** — `.agents/notes/archived/feature/2026-08-06-session-completed-done-dot.md:14` — green = finished and unviewed, amber = awaiting the operator's input, blue = running, with the reminder owned by the manager (so every surface projects the same bit), surviving connection generations but not a page reload, and detected eagerly at every list mutation and pull because "a snapshot-build-time-only pass would collapse two consecutive status frames into one observation and miss the completion".
- **Give the model a *reversible* stop on a child, and keep the human's window open** — `.agents/notes/archived/feature/2026-08-06-continuable-subagent-interrupt.md:14` (see first bullet) — the authority union is deliberately *wider* for stop than for delivery, because stopping is idempotent and delivers no content; and the address-based `{kind:'user'}` variant touches no live parent, which is what keeps a child stoppable while its parent is offline.
- **Model-visible and human-visible surfaces need separate seams, and the provider owns both** — `.agents/notes/archived/feature/2026-08-07-web-inline-file-mentions.md:18` — the renderer owns no vocabulary; the provider behind an optional service decides what names a file *and* registers the prompt paragraph that asks the model to use the accepted spelling. The result is a feature whose model-visible half is a **constant** prompt section, so it "remains cacheable across Turns" — a UI nicety that does not damage the provider prefix cache.
