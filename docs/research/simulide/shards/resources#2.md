# simulide / resources#2

## Shard shape

This shard is **all Qt Linguist catalogue** — seven files, 2,000,334 bytes, 49,388
lines of UTF-8 XML in the `<TS version="2.1">` format, all in `resources/translations/`:
`simulide.ts` (the `lupdate` template), `simulide_en.ts`, `simulide_de.ts`,
`simulide_es.ts`, `simulide_pt_BR.ts`, `simulide_zh_CN.ts`, `simulide_zh_TW.ts`.
There is no source code here at all. What makes the shard worth reading is that a
Qt catalogue is not a flat string table: each `<context>` is the owning C++ class
(181 of them), each `<message>` is one user-visible string, and each `<location
filename="…" line="…"/>` points back into the tree. Parsed in full, the seven files
agree on a single inventory — **1,260 live messages, 775 distinct live source
strings, 190 distinct source files** — and differ only in how much of that
inventory each locale has actually translated, and in how many stale
`vanished`/`obsolete` records each accumulated. The catalogue is therefore a
**machine-readable index of SimulIDE's entire user-visible surface**, generated by a
standard tool, version-controlled, and cheap to re-derive. The build wires it in at
`SimulIDE.pri:17` (glob → `TRANSLATIONS`) and `SimulIDE.pri:157`–`SimulIDE.pri:161`
(`lrelease` → move `.qm` into `resources/qm/`); the results are embedded through
`src/application.qrc:11`–`src/application.qrc:25`.

This is also where the shard's most useful negative result lives: the `<location>`
pointers are a **snapshot that has drifted**, and the drift is *measurable and
structured*. Across the template's 1,189 single-location messages, only 871 (73.3%)
still resolve to a line containing that string. The accuracy is not uniform — it
tracks how much the file has been edited since the catalogue was generated:
`src/components/**` is 90.5% accurate, `src/gui/**` 44.4%, `src/microsim/**` 20%,
and `src/mainwindow.cpp` 0%. The miss is not noise: it is a **uniform positive line
offset per file** (`editorwidget.cpp` +60 for the whole action-menu block,
`mainwindow.cpp` +3 then +9, `component.cpp` +9), which is the signature of code
inserted *above* the call site after the catalogue was cut. So the catalogue is
reliable as a *feature index* and unreliable as a *line index* — a distinction that
matters for any agent that wants to use it as a map.

## Per-file notes

### resources/translations/simulide.ts

- Purpose: the `lupdate` **template** — the canonical, fully-untranslated snapshot of every user-visible string in SimulIDE. Root element `<TS version="2.1">` (`resources/translations/simulide.ts:3`) with **no `language` attribute**, which is exactly how Qt marks a template. 6,968 lines, 280,227 bytes, 181 `<context>` blocks, 1,260 `<message>` records, 1,357 `<location>` references into 190 distinct `.cpp`/`.ui` files.
- Key abstractions: `<context>` → `<name>` is the *translation context* = the owning class name (`ADC`, `MainWindow`, `CircuitWidget`, `Component`, `QObject`, `EditorWidget`, `MCUMonitor`, `QemuDevice`, `asDebugger`, `SubPackage`, `TruthTable`, …). `<message>` = one translatable string; `<source>` = the English text; `<translation>` carries the target text **and its state in the `type` attribute** — `type="unfinished"` (not translated), `type="vanished"` (the source string no longer exists; the translation is kept for reference), `type="obsolete"` (superseded), and **no `type` attribute at all = finished** (this last form matters: a finished translation is a plain `<translation>text</translation>`, and the two plural-aware messages use a `<numerusform>` child instead).
- Data flow: `tr("…")` in the C++ source → `lupdate` → this file → Qt Linguist / `lrelease` → `simulide.qm` → `resources/qm/` → `src/application.qrc` → embedded in the binary → `QTranslator` at runtime. The two plural-aware strings are `Found %n occurrence(s)` (`resources/translations/simulide.ts:2529`) and `Replaced %n occurrence(s)` — the only numerus messages in the whole application, and they belong to the find/replace dialog.
- Non-obvious design decisions: **the template is the canonical inventory but a stale snapshot of the UI.** All 1,260 of its messages are `type="unfinished"` with an empty body, so it contributes zero runtime text; its value is entirely as the index. Its `<location line=…>` values are *not* uniformly current — see "Edge cases" below. The **28** shared component-library category names live under the **`QObject` context**, not a component context, because the code calls `QObject::tr("Meters")` (`resources/translations/simulide.ts:4639` → `src/gui/componentlist/itemlibrary.cpp:153`); the full taxonomy (Meters, Sources, Switches, Passive, Resistors, Resistive Sensors, Reactive, Active, Rectifiers, Transistors, Other Active, Outputs, Leds, Displays, Motors, Other Outputs, Micro, Sensors, Peripherals, Logic, Gates, Arithmetic, Memory, Converters, Other Logic, Connectors, Graphical, Other) is therefore readable as one list *only* in the catalogue. The `QObject` context holds 41 messages in total — the 28 categories plus 13 that leaked in from the same `QObject::tr` call site (`Edit Pin`, `Delete Pin`, `Warning: elf file doesn't exist:`, `Main`, `Type`, `Screen`, `Cpu`, `Producer`, `CMOS`, `Single cycle I/O`, `Interrupt Vector 0xFF`, `Invert Pin`), which is itself evidence that the context is a *call-site* label rather than a *feature-area* label.
- Edge cases / failure handling: the **template's line pointers are only 73.3% accurate** (871 of 1,189 single-location messages still point at a line containing the string). By directory: `src/components/**` 90.5%, `src/gui/**` 44.4%, `src/microsim/**` 20.0%, `src/mainwindow.cpp` 0%. The drift is a uniform positive offset per file, e.g. `src/gui/editorwidget/editorwidget.cpp` is +60 for the entire action-menu block (`resources/translations/simulide.ts:2080` says `editorwidget.cpp:708`; the `tr("&New\tCtrl+N")` call is actually at `src/gui/editorwidget/editorwidget.cpp:768`), `src/mainwindow.cpp` is +3 for the crash-recovery block (`resources/translations/simulide.ts:3878` says `mainwindow.cpp:102`; the call is at `src/mainwindow.cpp:105`), and `src/components/component.cpp` is +9 (`resources/translations/simulide.ts:1265` says `component.cpp:337`; the call is at `src/components/component.cpp:346`). One location points past the end of its file. **Use the catalogue as a feature index, not as a line index.**
- Surprising: the file-dialog **filters are translatable strings** — `Circuits (*.sim*);;All files (*.*)` (`resources/translations/simulide.ts:778`) is a `<source>` with a `<translation>`, which means a translator who "helpfully" translated it would break the Open dialog (Qt matches filters by literal string). The family of sidecar formats is equally visible here: `VCD files (*.vcd)` (`:3335`), `All files (*.*);;Hex Files (*.hex)` (`:4037`), `VarSets (*.vst)` (`:4975`), `Packages (*.package)` (`:5905`), `img files (*.img)` (`:5167`), `Wav files (*.wav)` (`:6759`).

### resources/translations/simulide_en.ts

- Purpose: the English catalogue, root element `<TS version="2.1" language="en">` (`resources/translations/simulide_en.ts:3`). It exists so "English" appears as a selectable entry in the app's language list; the compiled `simulide_en.qm` is embedded (`src/application.qrc:13`).
- Key abstractions: identical schema to the template; 181 contexts, 1,260 `<message>` records, **775 distinct live source strings — exactly the same inventory as the template**, plus two numerus messages.
- Data flow: same `lupdate` → `lrelease` path; `QTranslator` loads it and every lookup falls through to the `<source>`.
- Non-obvious design decisions: **every one of the 1,260 translations is `type="unfinished"` with an empty body** (`resources/translations/simulide_en.ts:9` is the first), so Qt falls back to the `<source>` for 100% of strings. The file's only observable effect is the *presence* of English in the picker — the English text itself comes from the compiled binary. The one curiosity is two messages whose body is non-empty *despite* being unfinished: `<translation type="unfinished">Logic</translation>` at `resources/translations/simulide_en.ts:4647` (and the same at `:5939`), where the translator typed the English word into an unfinished slot.
- Edge cases / failure handling: none needed — the file is deliberately a no-op. If someone later "fixed" it by pasting the English text into every `<translation>`, the file would double in size and gain nothing.
- Surprising: **the file is not a byte-copy of the template — it is the same content in a different order.** A full multiset diff shows the two files differ in exactly **five line-multiset counts**: the root element (`<TS version="2.1">` ×1 in the template vs `<TS version="2.1" language="en">` ×1 in en); the empty `<translation type="unfinished"></translation>` line (×1,258 in the template vs ×1,256 in en); `<translation type="unfinished">Logic</translation>` (×0 vs ×2); and `<numerusform></numerusform>` (×2 vs ×4). Everything else is a permutation — 912 of 1,260 messages occupy the same position, and the first divergence is at message index 20 (template `<source>Aip31068 I2C</source>` vs en `<source>Main</source>`). A naive positional line diff therefore reports ~5,000 differing lines for two files that hold the same content. Two different `lupdate` runs (or one run under different tool versions) emitted the same inventory in a different sequence. The `<numerusform>` difference is the only *semantic* one: English has two plural forms, so the English catalogue declares both (`resources/translations/simulide_en.ts:2531`–`2532`) where the template declares one (`resources/translations/simulide.ts:2531`) — both empty, because neither is translated.

### resources/translations/simulide_de.ts

- Purpose: German catalogue. Root element `<TS version="2.1" language="de_DE" sourcelanguage="en_US">` (`resources/translations/simulide_de.ts:3`) — **the only file in the shard that declares a `sourcelanguage`**.
- Key abstractions: 1,307 `<message>` records; 544 finished, 716 unfinished, 32 `vanished`, 15 `obsolete`; **103 of the 181 contexts contain at least one finished translation** (56.9%). Live coverage is 544 / 1,260 = **43.2%** — the least complete of the four locales that have any translation at all (de, es, zh_CN, zh_TW), but still a usable partial one.
- Data flow: `lupdate` → Qt Linguist → `lrelease` → `simulide_de.qm` → `src/application.qrc:12` → runtime `QTranslator`.
- Non-obvious design decisions: German is deliberately a **partial** translation — untranslated strings fall back to English silently, which is why the file still works and why the build never fails on it. Real German is confirmed throughout: `Größe` (`resources/translations/simulide_de.ts:20`), `Referenzspannung` (`:25`), `I2C Adresse` (`:135`), `UND Gatter` (`:161`). The shared component-library categories *are* translated in the live `QObject` context — 20 of the 28 — `Meters` → `Messgeräte` (`resources/translations/simulide_de.ts:4824`), `Sources` → `Eingänge und Quellen` (`:4804`), `Gates` → `Gatter` (`:4883`).
- Edge cases / failure handling: the crash-recovery banner is translated *with a translator-added emoji* — `resources/translations/simulide_de.ts:4023`: `<translation>Es scheint als wäre SimulIDE gechrasht 😢...</translation>`. Nothing in the schema forbids a non-ASCII emoji in a translation and `lrelease` accepts it. All `%n` placeholders and all `&` mnemonics survive in the German file (0 of 6 and 0 of 12 dropped), which makes it the reference "clean" locale.
- Surprising: the German file is the *least* stale of the non-English catalogues in one respect (it has no `*.sim1` filter record), yet it still carries 47 stale records for other strings (`Animate`, `Arduino`, `Quality`, `Manage Components`, `Clock Inverted`, `Reset Inverted`, `Set/Reset Inverted`, `File explorer`, `Led display`, `Other IC`). The stale records use `type="obsolete"` where Spanish and the Chinese catalogues use `type="vanished"` for the *same* component-category strings — the two states mean "superseded by a newer source string" versus "the source string was removed", and different translators' files ended up in different states for the same event.

### resources/translations/simulide_es.ts

- Purpose: Spanish catalogue. Root element `<TS version="2.1" language="es_ES">` (`resources/translations/simulide_es.ts:3`).
- Key abstractions: 1,325 `<message>` records — the joint-largest inventory in the shard alongside zh_TW; 1,225 finished, 35 unfinished, 64 `vanished`, 1 `obsolete`; **178 of 181 contexts have at least one translation** (98.3%). Live coverage is 1,225 / 1,260 = **97.2%** — the most complete locale here by a wide margin.
- Data flow: as above; `simulide_es.qm` is embedded via `src/application.qrc:14`.
- Non-obvious design decisions: the Spanish catalogue translates **both** shared vocabularies: the live `QObject` component-library categories — **all 28 of them** (`Meters` → `Medida`, `resources/translations/simulide_es.ts:4893`; `Sources` → `Fuentes` `:4873`; `Switches` → `Interruptores` `:5026`; `Connectors` → `Conectores` `:5031`) — *and* the `ComponentList` context. It is also the only locale whose stale set is dominated by `vanished` (64 of 65), i.e. the Spanish translator's work was lost to *removals* in the source rather than to rewording.
- Edge cases / failure handling: **this file drops the Qt `&` mnemonic marker in 10 of its 12 ampersand-bearing strings, and 9 of those 10 drops are real losses**: `&Open Circuit\tCtrl+O` → `Abrir Circuito\tCtrl+O` (`resources/translations/simulide_es.ts:908`), `&Save Circuit\tCtrl+S` → `Guardar Circuito\tCtrl+S` (`:918`), `Save Circuit &As...\tCtrl+Shift+S` → `Guardar Circuito Como...\tCtrl+Shift+S` (`:928`), `&Open...\tCtrl+O` → `Abrir...\tCtrl+O` (`:2211`), `&Save\tCtrl+S` → `Guardar\tCtrl+S` (`:2221`), `Save &As...\tCtrl+Shift+S` → `Guardar Como...\tCtrl+Shift+S` (`:2231`), `Cu&t\tCtrl+X` → `Cortar\tCtrl+X` (`:2241`), `&Copy\tCtrl+C` → `Copiar\tCtrl+C` (`:2251`), `&Paste\tCtrl+V` → `Pegar\tCtrl+V` (`:2261`). The mnemonic is what Qt underlines and what Alt+key activates, so the Spanish menu bar loses its keyboard accelerator hints. (The tenth drop is *correct*: `Use RCO & RBO` → `Usar RCO y RBO`, where the `&` is a literal "and", not a mnemonic.) The 64 `vanished` records keep the string that vanished *and* its translation, so the catalogue preserves the format's own version history: `Circuits (*.sim1);;All files (*.*)` survives at `resources/translations/simulide_es.ts:856` and `:1019` alongside the live `Circuits (*.sim*);;All files (*.*)` at `:852`.
- Surprising: the most complete translation in the shard is also the one with the most broken accelerators. Coverage and correctness are independent axes, and a single "is this locale finished?" metric reports 97% for a file that silently dropped 9 menu mnemonics. Real Spanish confirmed throughout: `Principal`, `Tamaño`, `Voltaje de referencia`, `Salidas`, `Tiempos`.

### resources/translations/simulide_pt_BR.ts

- Purpose: Brazilian Portuguese catalogue. Root element `<TS version="2.1" language="pt_BR">` (`resources/translations/simulide_pt_BR.ts:3`).
- Key abstractions: 1,324 `<message>` records, but **0 live translations**: 1,260 unfinished, 64 `obsolete`, 0 `vanished`. The locale therefore ships and is selectable, and every string falls back to English.
- Data flow: as above; `simulide_pt_BR.qm` is embedded via `src/application.qrc:15`.
- Non-obvious design decisions: this is the shard's clearest demonstration of the `obsolete` mechanism. The 64 obsolete records **do carry real Portuguese** — `Elétrico` at `resources/translations/simulide_pt_BR.ts:34`, `:183` and `:566`; also `Chinês:`, `Russo:`, `Animação` — a translator's work that is preserved but not wired up. The reason it is obsolete rather than live is a `lupdate` timing accident: the string was absent from the source when the file was last regenerated, and has since come back. `Electric` is live again today (`src/components/active/comparator.cpp:61`), and the old Portuguese sits there unused.
- Edge cases / failure handling: an all-unfinished `.ts` compiles to a valid but near-empty `.qm`; the app starts, the language list shows "Português (Brasil)", and nothing changes on screen. Nothing detects or reports this. **This is the file that proves the shard's most important lesson: a locale can be fully present in the build and fully absent in the product.**
- Surprising: pt_BR is the **only** file in the shard whose stale records are all `obsolete` rather than `vanished` — 64 vs 0. That single difference is the whole story of this locale: a translation pass happened, and then all of it was superseded.

### resources/translations/simulide_zh_CN.ts

- Purpose: Simplified Chinese catalogue. Root element `<TS version="2.1" language="zh_CN">` (`resources/translations/simulide_zh_CN.ts:3`).
- Key abstractions: 1,271 `<message>` records; 1,115 finished, 145 unfinished, 10 `vanished`, 1 `obsolete`; **165 of 181 contexts touched** (91.2%), live coverage 1,115 / 1,260 = **88.5%**.
- Data flow: as above; `simulide_zh_CN.qm` is embedded via `src/application.qrc:17`.
- Non-obvious design decisions: the file is genuinely Simplified Chinese, not a copy of another locale — `模数转换器ADC`, `主要`, `位宽`, `二极管` (`resources/translations/simulide_zh_CN.ts:1834`), `仪表` for `Meters` (`:4691`), `源` for `Sources` (`:4696`). It translates 24 of the 28 shared component-library categories (zh_TW and es translate all 28). Its two plural-aware strings each supply a **single** `<numerusform>`, which is correct for Chinese (no plural inflection) — `找到 %n 个匹配项` and `已替换 %n 个匹配项`.
- Edge cases / failure handling: this file contains **two live defects that no linter in the project would catch**. (1) **Nine translation bodies replaced the TAB inside the "label\tshortcut" string with a literal U+2192 RIGHTWARDS ARROW** — e.g. `resources/translations/simulide_zh_CN.ts:2138`: `<translation>&amp;保存→Ctrl+S</translation>`, where the source is `&Save\tCtrl+S` with a real U+0009. The Chinese menu therefore renders "保存→Ctrl+S" instead of a tab-aligned "保存      Ctrl+S". The same substitution appears at `:2118`, `:2128`, `:2138`, `:2148`, `:2158`, `:2168`, `:2178`, `:2188`, `:2198`. (2) The file-dialog filters are marked translatable: `All files (*.*);;Hex Files (*.hex)` appears at `resources/translations/simulide_zh_CN.ts:4084` and `:4928`, and the superseded `Circuits (*.sim1);;All files (*.*)` survives as `vanished` at `:793` and `:999` — a translator who actually translated a filter string would break the Open dialog. The Chinese translator happened to leave the filters identical, so nothing breaks today.
- Surprising: the stale records here include **both** copies of the old circuit filter, marked `vanished` with the translation body retained (`<translation type="vanished">Circuits (*.sim1);;All files (*.*)</translation>`), so the catalogue is an archive of the change from a single circuit extension (`.sim1`) to a family (`.sim*`). And the arrow substitution is a *silent* corruption: the XML is well-formed, `lrelease` accepts it, the string count is right, and the only visible symptom is a misaligned menu.

### resources/translations/simulide_zh_TW.ts

- Purpose: Traditional Chinese catalogue. Root element `<TS version="2.1" language="zh_TW">` (`resources/translations/simulide_zh_TW.ts:3`).
- Key abstractions: 1,325 `<message>` records; 1,075 finished, 185 unfinished, 61 `vanished`, 4 `obsolete`; **164 of 181 contexts touched** (90.6%), live coverage 1,075 / 1,260 = **85.3%** — the second-least complete of the four locales that have any translation at all, and the file with the most stale records after es.
- Data flow: as above; `simulide_zh_TW.qm` is embedded via `src/application.qrc:16`.
- Non-obvious design decisions: it is a **real translation, not a copy of zh_CN** — of the 1,029 live-finished strings the two files share, **54 are identical and 975 differ**, and the differences are genuine script and register conversions rather than transliteration: `二极管` (CN) → `二極體` (TW, `resources/translations/simulide_zh_TW.ts:1945`), `电容` → `電容值`, `图像` → `圖片`, `调试` → `除錯` (a different *word*, not just a different script), `发送值：` → `發送數值:`. It translates **all 28** of the shared component-library categories. The zh_TW translator also favours a traditional-Microsoft register — `序列終端機(監視器)` for "Serial Terminal" — and reworks the mnemonics: `&Save\tCtrl+S` becomes `儲存(&S)\tCtrl+S`, moving the `&` to the conventional Chinese position.
- Edge cases / failure handling: 61 `vanished` records, including both copies of the old `*.sim1` circuit filter (`resources/translations/simulide_zh_TW.ts:847` and `:1054`). Unlike zh_CN, this file **keeps the tab** in its accelerator strings and keeps every `&` mnemonic (0 of 14 dropped), so the Traditional Chinese menu renders correctly where the Simplified Chinese one does not. All 8 of its `%n`-bearing strings keep their placeholder.
- Surprising: it is the only locale in the shard where the *translation* is systematically longer than the source (`序列終端機(監視器)` vs "Serial Terminal"), i.e. the catalogue doubles as a place where UI string *growth* across locales is measurable — and a place where the label/accelerator separator has to survive translation, which zh_CN proves it does not always.

## Ideas worth stealing

- **A translation catalogue is a free, machine-readable index of an entire application's UI surface — 181 classes, 190 source files, 775 strings, no code execution required.** `resources/translations/simulide.ts:4` — the `ADC` context alone names the class, points at `src/components/logic/adc.cpp`, and lists each user-visible label. For August: a harness that must reason about a GUI app it cannot run can parse one XML file to get the feature inventory (context = feature area) and the code hooks (`<location>` = where to look). This is the cheapest "what can this app actually do" index available, and it is already in the repo, version-controlled, and regenerated by a standard tool.

- **The catalogue's `<location>` pointers are a SNAPSHOT with a measurable drift, and the drift is a uniform per-file line offset — so treat the catalogue as a feature index, not a line index.** `resources/translations/simulide.ts:2080` says `editorwidget.cpp:708`; the actual `tr("&New\tCtrl+N")` is at `src/gui/editorwidget/editorwidget.cpp:768` — a clean **+60** offset held across 20 consecutive menu entries, because 60 lines were inserted above that block after the catalogue was cut. The same holds for `src/mainwindow.cpp` (+3, `resources/translations/simulide.ts:3878` → `src/mainwindow.cpp:105`) and `src/components/component.cpp` (+9, `resources/translations/simulide.ts:1265` → `src/components/component.cpp:346`). Overall accuracy is 73.3%, but **90.5% under `src/components/**` and 44.4% under `src/gui/**`**. For August: any skill that says "the string table tells you which file to open" is right; any skill that says "…and at which line" is wrong unless it re-verifies. A harness that trusts a stored pointer without re-checking will open the wrong function — and the failure is silent, because the file is still openable.

- **Bind every user-visible string to its exact source line, so the string table doubles as a code map — but re-verify the binding, and score the binding.** `resources/translations/simulide.ts:7` — `<location filename="../../src/components/logic/adc.cpp" line="25"/>`, which still resolves exactly (`src/components/logic/adc.cpp:25` is `tr("ADC")`). For August: "which file produces this label?" becomes a lookup instead of a grep. The *scoring* is the stealable part: because `lupdate` emits the pointer for free, you can measure, per file, how much of the map is still true, and treat a catalogue whose accuracy has fallen below a threshold as a signal to re-run the generator rather than as ground truth.

- **The locale file itself is where UI-string defects live, and they are all detectable by comparing the TRANSLATION to the SOURCE's structural characters.** Two concrete instances: (a) `resources/translations/simulide_zh_CN.ts:2138` — `<translation>&amp;保存→Ctrl+S</translation>` where the source is `&Save\tCtrl+S`; the TAB (U+0009) was replaced by a literal U+2192 arrow in nine strings (`:2118`–`:2198`). (b) `resources/translations/simulide_es.ts:908` — `&Open Circuit\tCtrl+O` → `Abrir Circuito\tCtrl+O`; the `&` mnemonic was dropped in nine menu strings (`:908`, `:918`, `:928`, `:2211`, `:2221`, `:2231`, `:2241`, `:2251`, `:2261`). For August: a **l10n lint** that asserts "the translation preserves the source's tab, its `%n` placeholders and its `&` mnemonic" is a twenty-line check that catches two live shipping bugs in a mature 2.0.0 codebase. Note the false-positive boundary the data gives you for free: `Use RCO & RBO` → `Usar RCO y RBO` is *correct* (`&` before a space is a literal), so the rule must distinguish the two.

- **An accelerator that is concatenated outside the `tr()` call is invisible to the translator — and the catalogue proves it.** `src/components/component.cpp:346` is `menu->addAction( m_theme->icon(":/copy.svg"),tr("Copy")+"\tCtrl+C");` — the label is inside `tr()` but the `\tCtrl+C` is not, so `lupdate` captures only `Copy`. The catalogue shows the consequence exactly: the `Component` context records bare `Copy`/`Cut`/`Remove`/`Rotate CW`/`Horizontal Flip` (`resources/translations/simulide.ts:1265`, `:1270`, `:1275`, `:1280`, `:1295`) while the `EditorWidget` context records the full `&Copy\tCtrl+C` (`resources/translations/simulide.ts:2130`). The same user action is therefore two different translatable strings depending on where the shortcut was typed. For August: when a harness generates or reviews UI, the rule "the shortcut must live *inside* the translatable string, or it will silently vanish in every non-English locale" is a concrete lint, and this repo is the worked example.

- **The circuit project format is a wildcard family, and the format's own version history is retained in the data.** Live: `resources/translations/simulide.ts:778` — `Circuits (*.sim*);;All files (*.*)`. Superseded but kept as stale records: `resources/translations/simulide_zh_CN.ts:793`, `resources/translations/simulide_es.ts:856`, `resources/translations/simulide_zh_TW.ts:847` — `Circuits (*.sim1);;All files (*.*)`. So the app went from exactly one circuit extension (`.sim1`) to a family (`.sim*`), and the current generation is `.sim2` (the crash-recovery backup file is `backup.sim2`, `src/mainwindow.cpp:101`). The sibling formats are `.vst` (component sets, `resources/translations/simulide.ts:4975`), `.package` (IC packages, `:5905`), `.vcd` (waveform dump, `:3335`), `.hex` (firmware, `:4037`), `.img`, `.wav`. For August: a skill that teaches "how to open a SimulIDE circuit" can state the format family, the sidecar formats, and — because the format is suffix-versioned — can say "a `.sim1` file is the old single-version format" without reading any code.

- **Localisation coverage is a per-locale completeness metric you can compute with one parse, and it exposes locales that ship but do nothing.** `resources/translations/simulide_es.ts` = 1,225 of 1,260 live strings finished, 178 of 181 contexts touched; `resources/translations/simulide_de.ts` = 544 of 1,260 and 103 of 181; `resources/translations/simulide_zh_CN.ts` = 1,115 of 1,260 and 165 of 181; `resources/translations/simulide_zh_TW.ts` = 1,075 of 1,260 and 164 of 181; `resources/translations/simulide_pt_BR.ts` = **0 of 1,260** (its 64 "translations" are all `obsolete`). For August: this is a ready-made template for a "feature completeness" readout on any localized surface — count live-and-finished records over live records, and report both a string percentage and a context percentage. pt_BR is the proof that the metric catches a real defect (a shipped, selectable, entirely inert locale) that no other check would notice. The `type=` attribute is what makes it a one-liner: finished = no `type`, unfinished = `type="unfinished"`, stale = `type="vanished"` or `type="obsolete"`.

- **Provenance rides on the record itself: `unfinished` / `obsolete` / `vanished` are attributes of the value, not entries in a side ledger.** `resources/translations/simulide_zh_CN.ts:794` (`type="vanished"`), `resources/translations/simulide_pt_BR.ts:34` (`type="obsolete"`), `resources/translations/simulide_en.ts:9` (`type="unfinished"`). For August: agent-generated content can carry its own provenance in-band — "machine-drafted but unverified" vs "human-approved" vs "retired" — instead of a parallel ledger that can disagree with the payload. The stale-record mechanism here is exactly that, and it survives regeneration: the Spanish file still holds its own Spanish `*.sim1` translation at `resources/translations/simulide_es.ts:856`, long after the source string changed to `*.sim*`, so the history of the format survives the loss of the string.

- **The keyboard map is recoverable from the string table, because the mnemonic, label and accelerator live in one token.** `resources/translations/simulide.ts:829` — `<source>&amp;Open Circuit	Ctrl+O</source>`; also `:819` (`&amp;New C&amp;ircuit	Ctrl+N`), `:839` (`&amp;Save Circuit	Ctrl+S`), `:849` (`Save Circuit &amp;As...	Ctrl+Shift+S`), and the editor's own set at `:2080`–`:2160` (`Undo	Ctrl+Z` at `:2150`, `Redo	Ctrl+Shift+Z` at `:2160`). For August: an agent driving a GUI needs the shortcut map, and here it is in a machine-readable table with the accessible names attached — you can reconstruct the whole keybinding surface of an application by reading one file and splitting on the tab. (With the two caveats above: the tab only survives if the translator keeps it, and the accelerator only exists in the catalogue if the developer typed it inside the `tr()` call.)

- **Undo depth is a user-visible preference, not a hardcoded constant, and undo/redo is exposed in both the canvas and the code editor.** `resources/translations/simulide.ts:311` — `Undo Steps` (catalogue location `appdialog.ui:910`; the string is actually at `src/gui/appdialogs/appdialog.ui:941`) sits in the preferences dialog next to `Auto Backup` (`:301`, actually `src/gui/appdialogs/appdialog.ui:880`) and `Seconds` (`:306`). The canvas verbs are in the `Component` context (`resources/translations/simulide.ts:1260`–`:1300`: `Properties`, `Copy`, `Cut`, `Remove`, `Rotate CW`, `Rotate CCW`, `Rotate 180`, `Horizontal Flip`, `Vertical Flip` from `src/components/component.cpp`), and the canvas's own `CircuitView` context carries the `Undo`/`Redo` actions at `resources/translations/simulide.ts:791` and `:796` — the same two words the code editor uses at `:2150` and `:2160`. For August: an editor-shaped tool should make the undo budget a *setting* rather than a fixed constant — and should expose the same undo vocabulary in both surfaces it edits, so the user learns one word for one concept.

- **The solver's whole numerical regime is present as human-readable preferences, and a restart is explicitly signposted.** `resources/translations/simulide.ts:321`–`:361` (`src/gui/appdialogs/appdialog.ui`): `Speed` (`:321`), `Steps per Second` (`:326`), `Target Step` (`:331`), `Real Step` (`:336`), `NonLinear` (`:341`), `Max. Iterations` (`:346`), `Reactive` (`:351`), `Logic Outputs Edges` (`:356`), `Slope Steps` (`:361`) — and `Restart required to apply new settings.` at `:371`. (Each carries an `<location>` into `src/gui/appdialogs/appdialog.ui`; those `.ui` line numbers are themselves stale — the `.ui` files are only 64.2% accurate, same drift as the `.cpp` ones.) For August: these are exactly the knobs an agent needs to reason about simulation fidelity ("how many steps per second?", "is the timestep adaptive or fixed?", "what is the iteration ceiling?"). A catalogue like this tells you the *entire exposed parameter surface of the engine* without opening a single engine file — which is what makes a simulation skill writable rather than guesswork. The `Restart required…` string is the design lesson: a setting whose effect is deferred must say so in the UI, not just in the docs.

- **Crash recovery is worded as a stated consequence BEFORE the question, and it names the file.** `resources/translations/simulide.ts:3878`–`:3900` (`src/mainwindow.cpp:105`–`109`): *"Looks like SimulIDE crashed..."* / *"There is an auto-saved copy of the Circuit"* / *"You must save it with any other name if you want to keep it"* / *"This file will be auto-deleted!!"* / *"Do you want to open the auto-saved copy of the Circuit?"*. For August: an agent that rewrites a user's file needs exactly this shape — tell the user what the destructive default will do (auto-delete), tell them how to keep it (save under another name), and only then ask. Four of the five strings are the warning; the question is last. (The same discipline appears on the ordinary path: `Circuit has been modified. Do you want to save your changes?` at `resources/translations/simulide.ts:939`.)

- **A template file and a translation file are different kinds of thing, and the build should know the difference.** `resources/translations/simulide.ts:3` (`<TS version="2.1">`, no language) versus `resources/translations/simulide_en.ts:3` (`<TS version="2.1" language="en">`); `SimulIDE.pri:17` globs `*.ts` into `TRANSLATIONS` and `SimulIDE.pri:157`–`SimulIDE.pri:161` runs `lrelease` on all of them, but `src/application.qrc:11`–`src/application.qrc:17` embeds only the seven real locales — the template's `.qm` is compiled on every build and never shipped. For August: when a harness drives a build, "the file that is an INPUT to a tool" and "the file that is an ARTEFACT" should be distinguishable by naming, not by which tool last touched it.

## Files skipped (with reasons)

**No file in this shard was skipped** — all seven were opened and fully characterised.

For the audit trail, though, the method differs from the rest of the repository and
should be stated plainly: **none of the seven was read line by line.** Each is
~7,000 lines of machine-generated XML with a rigid four-element grammar, so instead
of reading them sequentially I parsed each file in full — enumerating every
`<context>`, every `<message>`, every `<location>`, every `<source>` and every
`<translation>` (including its `type=` state and whether its body is empty) — and
then read representative regions with the `read`/`grep` tools to confirm what the
machine counts meant. Every number quoted above (context, message, location,
distinct-source-file and per-state counts; the per-locale coverage percentages;
the 73.3% location-accuracy figure and its per-directory breakdown; the
five-count multiset difference between the template and the English catalogue;
the 54/975 zh_CN-vs-zh_TW identical/differing split; the 9 tab-to-arrow
substitutions; the 9 mnemonic drops) comes from a complete enumeration of the
file, not from sampling.

The other reason these files are not read line by line: they are **generated
output** of `lupdate`, and the same information is available in the C++/`.ui`
sources themselves — the catalogue's value to this study is precisely as an
*index* over those sources, not as independent content. Where the index makes a
checkable claim about the sources (the location pointers, the accelerator
strings, the mnemonic markers), the claim was checked against the source file
rather than assumed.

## Uncertainties

- **The location-pointer drift is characterised, not modelled.** I measured that 871 of 1,189 single-location messages in the template still resolve to a line containing the string, and that the misses cluster into uniform per-file offsets (+60 in `editorwidget.cpp`, +9 in `component.cpp`, +3/+9 in `mainwindow.cpp`, +3/+21/+22 in `qemudevice.cpp`, +8 in `codeeditor.cpp`, +1/+3 in the settings blocks). I did **not** reconstruct the individual commits that caused each offset, and I did not diff against git history. A handful of "actual" positions reported by my search are unreliable because I matched the *first* occurrence of the string in the file rather than the enclosing `tr()` call (this affects, for example, `Copy` in `src/components/component.cpp`, whose first textual match is inside the word "Copyright" in the file's header comment at line 2) — the *offsets* are reliable because they hold across many consecutive entries, but any single-message line number quoted from that analysis should be re-checked by hand. Every line number I actually cite in this report was opened and read directly.
- **I could not confirm which `.ts` file is used as the translator's working template in practice.** `resources/translations/simulide.ts` has no `language` attribute (the standard lupdate-template shape) and `simulide_en.ts` is a near-duplicate of it, but no file in this shard states the convention and I did not find any `.lpro`/`.lpj` project file or a documented `lupdate` invocation in the tree. My reading that it is the template rests on the missing `language` attribute plus the fact that it is the only catalogue that is 100% unfinished.
- **The precise per-locale `lupdate` generation order is inferred, not proven.** Every file has the same 1,260 live messages and the same 775 distinct live sources; the stale-record sets differ (de 47 records, es 65, pt_BR 64, zh_CN 11, zh_TW 65), which implies the files were regenerated at different epochs. I did not reconstruct the exact chronological order beyond that, and I did not check whether the upstream project keeps a documented translation workflow.
- **`resources/qm/` ships only a `readme`** ("All qm files for translations will be copied here."), i.e. no `.qm` file is committed. `SimulIDE.pri:157`–`SimulIDE.pri:161` is the `runLrelease.commands` recipe and `SimulIDE.pri:164` adds it to `PRE_TARGETDEPS`, so `lrelease` runs before **every** build and the `.qm` files are generated artefacts. I did not run the build, so I have not observed that step happen; the `PRE_TARGETDEPS` wiring is what makes it the default. This resolves the previous pass's open question on the point, but by reading the recipe, not by executing it.
- **`src/application.qrc` line attribution was verified by reading the file**, not inferred: `simulide_cz.qm` at line 11, `simulide_de.qm` at 12, `simulide_en.qm` at 13, `simulide_es.qm` at 14, `simulide_pt_BR.qm` at 15, `simulide_zh_TW.qm` at 16, `simulide_zh_CN.qm` at 17, then the Qt-supplied `qt_*.qm` at 19–25. There is **no `simulide.qm` entry**, confirming the template is compiled but never shipped. Note that the manifest assigns `resources/translations/simulide_cz.ts` (the Czech catalogue, 286,714 bytes) to `resources#1`, not to this shard — I checked and that assignment is consistent with the file set, so it is not a manifest error.
- **I did not read the `.cpp`/`.ui` sources the catalogue points at** (they belong to other shards), except for the spot-checks the accuracy measurement required: `src/components/logic/adc.cpp`, `src/gui/componentlist/itemlibrary.cpp`, `src/mainwindow.cpp`, `src/components/component.cpp`, `src/components/active/comparator.cpp`, `src/gui/editorwidget/editorwidget.cpp`, `src/microsim/cores/qemu/qemudevice.cpp`, `src/gui/editorwidget/codeeditor.cpp`, and `src/gui/appdialogs/appdialog.ui` (line numbers only, read for verification). Any claim about what a component *does* beyond what its strings and locations show is out of scope for this shard.
- **The `resources/translations/qt/qt_*.ts` files are in `resources#1`, not here.** They are Qt's own catalogue (the `qt_en.ts` there is 98 bytes, i.e. essentially empty) and the `resources/qm/readme` / `resources/readme` files are also in `resources#1`. I read the two readme files (four lines total) because they bear directly on the build wiring, and I did not read the seven `qt_*.ts` catalogues.
- **The two Chinese locales' divergence is measured on strings, not on meaning.** The 54-identical / 975-differing split compares the translation *text* for the 1,029 context-and-source keys both files have finished; it says nothing about translation *quality*, and I did not attempt to assess whether either Chinese rendering is correct. The `调试` (CN) vs `除錯` (TW) pair for "Debug" is a lexical difference I noticed, not a judgement.
- **The `&`-mnemonic-drop count is 9 for Spanish, not 10.** The tenth dropped `&` is in `Use RCO & RBO` → `Usar RCO y RBO`, where the `&` is a literal "and" and the translator was right to remove it. Any detector built on this finding must distinguish `&` before a letter (mnemonic) from `&` before a space (literal), or it will produce exactly that false positive.
