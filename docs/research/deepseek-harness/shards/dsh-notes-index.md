# deepseek-harness / dsh-notes-index

## Shard shape

This shard is the **specification of the Agent Note system** — the repo's durable decision-record format — and nothing else. It is four files: `.agents/notes/AGENTS.md` (the subtree standing order, 7 lines), `.agents/notes/README.md` (the 125-line English spec that defines where a decision record lives, when one is written, how it is classified, how it is archived, and what exact in-file shape it must have), `.agents/notes/README.zh.md` (the Chinese counterpart, structurally identical), and `.agents/notes/README.i18n.yaml` (the machine-checked **bilingual sidecar**: one YAML entry per heading section holding a hash of the English blocks and a hash of the Chinese blocks). Together they are the *input contract* for three sibling gates that live outside this shard — `scripts/agent-note-tree.ts` (closed lifecycle/class tree, no central index), `scripts/verify-agent-note-format.ts` (header, `Status:` grammar, per-lifecycle required/banned headings, alternatives mandate), and `scripts/verify-archived-agent-notes.ts` (frozen archive with an append-only hash-sealed manifest) — plus `scripts/verify-translation-pairing.ts`, which owns the sidecar. The module fits together as **path-encoded metadata → one canonical status grammar → a per-section hash sidecar that turns "the two languages must agree" into a mergeable, reviewable file**.

**Lens coverage note:** this shard contains no agent-loop, streaming, prompt-construction, compaction, or model-adaptation mechanism. Its contribution to the requested lenses is indirect but real: it is the repo's **memory/learning mechanism for decisions** (a durable store whose only mutation rules are "update facts in place" and "never edit a decision into its opposite"), it is a **config** mechanism (the closed class set and the `Status:` grammar are machine-enforced vocabularies), and it is an **eval/testing** mechanism (a required-section gate with a dated, exact, self-terminating exemption). Two ideas from it transfer straight into August's brain facts and into August's doc gates.

## Per-file notes

### .agents/notes/AGENTS.md

- **Purpose:** The standing order for the `.agents/notes/` subtree — the 7-line ruleset every agent must have in context before writing anything in the note tree.
- **Key abstractions:** "Agent Note" defined as *an RFC written by agents*: "durable proposals and decision records that preserve rationale, alternatives, consequences, and required verification" (`.agents/notes/AGENTS.md:3`). Three non-negotiables: the documentation standard, the Agent Note rules, and the supersession check.
- **Data flow:** Nothing here executes. It is a pointer file: it routes to `../../docs/AGENTS.md` (the doc standard) and `README.md` (the rules) and `../skills/dsh-archive-agent-notes/SKILL.md` (the archive workflow) and marks `archived/` as out of scope.
- **Non-obvious design decisions:** (1) **Every new note triggers a supersession check, and qualifying implemented triplets are archived in the SAME PR** (`.agents/notes/AGENTS.md:5`) — the audit is not deferred to a later corpus sweep, because a sweep is how a corpus ends up with two notes owning one decision. (2) **Partial supersessions stay active and are cross-linked** rather than being consolidated (`.agents/notes/AGENTS.md:5`) — consolidation is reserved for *full* supersession, because merging a partial pair destroys the narrower note's independent value. (3) Archived files are "frozen historical snapshots: never edit them or treat them as current authority" (`.agents/notes/AGENTS.md:7`) — a frozen note is evidence, not a spec.
- **Edge cases / failure handling:** The file is a gate on *behaviour*, not on file contents; the mechanical half of the rule (closed tree, format, sealed archive) is delegated to the three sibling scripts. "Never edit archived files" is stated as a hard prohibition rather than a preference.
- **Surprising:** The whole note tree's anti-entropy is one sentence long. There is no scheduler, no index, no registry — the *filesystem layout* is the registry, and the anti-entropy is "when you add a note, look for the one it replaces."

### .agents/notes/README.md

- **Purpose:** The canonical English specification of the Agent Note system: layout and naming, the closed class vocabulary, the archiving/deletion policy, the creation criteria, and the exact in-file format that `pnpm run verify-agent-note-format` enforces.
- **Key abstractions:**
  - **Path = two axes + a date**: `{lifecycle}/{class}/yyyy-mm-dd-topic-title.md` (`.agents/notes/README.md:9`). Lifecycle (`proposed` / `implemented` / `rejected`) *is* the status; class (`feature` / `bug-fix` / `simplification` / `architecture` / `process` / `testing`) *is* the kind of decision (`.agents/notes/README.md:11-33`).
  - **The three lifecycles** differ in *what a file is allowed to contain*, not just in a label: `proposed` may speak in the future tense (`.agents/notes/README.md:91`), `implemented` is present-tense fact and is kept current with what shipped (`.agents/notes/README.md:13`, `:103`), `rejected` is the proposal frozen with the verdict moved onto the `Status:` line (`.agents/notes/README.md:107`).
  - **The header block** is exactly three lines plus a blank: `# Agent Note: <title>` / `` / `Status: <status>` (`.agents/notes/README.md:60-66`).
  - **The body skeleton** is per-lifecycle: `## Problem` always, then `Proposal`+`Acceptance criteria`+`Risks` / `Decision`+`Consequences` / `Proposal` only (`.agents/notes/README.md:78-107`).
  - **`## Alternatives considered` is mandatory** in every note (`.agents/notes/README.md:111`).
  - **The archived tree** — `archived/{class}/…`, path-encoded, deliberately dropping the `implemented` segment because only implemented notes may enter it (`.agents/notes/README.md:40`).
- **Data flow:** A contributor writes a note into `lifecycle/class/date-title.md`; `scripts/agent-note-tree.ts` walks the tree and rejects unknown lifecycle folders, unknown class folders, wrong depth, bad filename, and the existence of a central `INDEX.md`; `scripts/verify-agent-note-format.ts` then reads each discovered note and checks the header grammar, the required and banned `##` headings, and the alternatives mandate; `scripts/verify-translation-pairing.ts` separately checks the `.zh.md` counterpart and the `.i18n.yaml` sidecar; the archive path adds `scripts/verify-archived-agent-notes.ts`, which seals the whole triplet into `archived/manifest.json`. The README is the prose side of that contract; the scripts are the enforcement side, and each sentence here that says "the gate rejects…" names a specific script.
- **Non-obvious design decisions (with the stated reasoning):**
  - **No central `INDEX.md`** (`.agents/notes/README.md:19`): "it duplicates path metadata and makes unrelated note changes contend on one generated file." A generated index is a merge-conflict magnet that carries zero information the tree does not already carry.
  - **Cross-references must be relative markdown links, never bare prose or numbers** (`.agents/notes/README.md:17`): "so they are mechanically checkable and survive moves between folders." The link form is what lets a note be moved between lifecycles without a human re-fixing every reference.
  - **The date in the filename is the FIRST-PROPOSED date, per git history** (`.agents/notes/README.md:17`), and **`Status:` carries no dates and no parentheticals** (`.agents/notes/README.md:74`): "the filename holds the first-proposed date, git holds everything else." Timestamps live in one place each, so a status edit never rewrites history metadata.
  - **The rejection reason is the one status with content** (`.agents/notes/README.md:74`): "a rejected Agent Note's verdict is the fact readers come for." A rejected note's value is the *why it lost*, so the verdict goes where a reader's eye lands first.
  - **The `architecture` / `process` boundary is drawn at "shipped source" vs "surrounding tooling"** (`.agents/notes/README.md:30-34`), and **`refactor` is deliberately absent** from the class set because it overlaps `simplification`, whose discriminator ("does observable behavior change?") already covers it. A closed set plus an explicit answer to "why isn't this a class?" is what stops the vocabulary from drifting.
  - **Alternatives are recorded, never invented** (`.agents/notes/README.md:113`): a pre-2026-07-05 note whose alternatives cannot be reconstructed carries an exact machine-readable comment instead, and the gate accepts that comment *only* for notes dated before 2026-07-05 (`.agents/notes/README.md:113-117`). The exemption is dated, so it self-terminates.
  - **An implemented note may not contain proposal-era headings** — `## Proposal`, `## Plan`, `## Migration plan`, `## Acceptance criteria` are banned there (`.agents/notes/README.md:103`). "Spec-speak" is a rot vector: a shipped decision that still reads like a plan will be read as a plan.
  - **"An Agent Note is never edited into a *different decision*"** (`.agents/notes/README.md:48`): supersede it with a new note and cross-link. Changing your mind is an *add*, never an in-place rewrite.
  - **A feature-addition note may be consolidated into a later removal note only under a full-absence test** (`.agents/notes/README.md:52`): absent from production code, configuration, schemas, durable or wire formats, migration, and compatibility behavior; no current documentation presents it as available; no test exercises it as supported behavior. "Removing one transport, default, implementation, or presentation is partial supersession."
  - **Archival permits exactly four content changes and no more** (`.agents/notes/README.md:40`): move the complete English/Chinese/sidecar triplet, retain `Status: implemented`, insert the same `Archived: YYYY-MM-DD` line immediately below it in both language files, re-record the sidecar, and repair inbound links. "Existing title punctuation, blank-line layout, and language-switcher wording do not block archival; preserve them with the body."
  - **Sealed archive notes are permanently frozen and are not authority for current behavior** (`.agents/notes/README.md:42`): "Do not edit, translate, reformat, update, move, or delete it." Active prose may still *link into* an archived note when it intentionally cites history, and the doc gates skip archived sources including their outbound links.
  - **Deletion criteria are semantic, not quantitative** (`.agents/notes/README.md:38`): "Use the calibrated `dsh-archive-agent-notes` workflow rather than word count, age, or a target quota." A local bug fix, performance change, new capability, or substantive behaviour decision does not qualify for deletion "merely because its implementation is small." And: "Never archive a proposed note: reject an obsolete proposal" — a proposal is a live claim, so it is settled, not filed away.
  - **The format gate skips `.zh.md`; the pairing gate checks consistency** (`.agents/notes/README.md:125`) — one gate per concern, so a Chinese note is not format-gated twice under two grammars.
- **Edge cases / failure handling:**
  - **Moving between lifecycles** is spelled out as a mechanical rewrite (`.agents/notes/README.md:121`): `proposed` → `implemented` rewrites `## Proposal` into present-tense `## Decision`, folds `## Acceptance criteria` and `## Risks` into `## Consequences` (or a present-tense `## Testing`/`## Verification`), and drops plans in favour of what shipped. `proposed` → `rejected` only adds the reason to the `Status:` line and freezes the file. The gate fails a move that does not re-satisfy the target skeleton.
  - **Consolidation** requires the owner to preserve *every* unique rationale, alternative, consequence, required verification, and named coverage gap; repair every inbound link; and delete the Chinese counterpart **and** the consistency record in the same change (`.agents/notes/README.md:50`). "Consolidation must not rewrite the old file into its opposite or rely on git history as the only copy of rationale."
  - **Inbound-link repair is part of every mutation** — deletion, archiving, and consolidation each require repairing or removing inbound links (`.agents/notes/README.md:38`, `:40`, `:50`).
  - **Implementation-status annotations are excluded from the note corpus** — the doc standard (linked from `:3`) keeps "implemented!"/"future" prose out of docs, and this README's own archive section repeats it: archived notes "are frozen history, never current authority."
  - **Pre-format notes** are the one grandfathered case, and the exemption is bounded by a date (`.agents/notes/README.md:113-117`).
- **Surprising:**
  - The three lifecycles have *different document grammars*, not different labels — a rejected note is explicitly allowed to keep `## Acceptance criteria` and `## Plan` (`.agents/notes/README.md:107`), because a rejection's job is to preserve the proposal that lost.
  - The doc **excludes** `refactor` on purpose (`.agents/notes/README.md:34`) — most vocabularies add a class; this one removed one, with a stated discriminator.
  - "Implemented" notes must be **kept current with what shipped** (paths, names, structure — not the decision), so an implemented note is a *living fact document* with a *frozen verdict* (`.agents/notes/README.md:13`).
  - The spec is enforced by four separate scripts with disjoint concerns, and every claim in the prose names the script that owns it — the README is a contract with pointers, not a wish.

### .agents/notes/README.zh.md

- **Purpose:** The Simplified-Chinese counterpart of the Agent Note specification — the same rules, in the other language, under the repo's bilingual-pairing contract.
- **Key abstractions:** The same vocabulary as the English file (`生命周期` / `类别` / `提议` / `已交付` / `已否决`, the six-class table, the three body skeletons, the mandatory 「曾考虑的替代方案」 section), plus one bilingual-specific mechanism: **explicit HTML anchors** `<a id="classification"></a>`, `<a id="when-to-write-one"></a>`, `<a id="the-file-format"></a>` (`.agents/notes/README.zh.md:21`, `:46`, `:58`).
- **Data flow:** The `.zh.md` is a *peer*, not a subordinate: the i18n contract says "Both languages carry equal authority" and the pair is three sibling files (`foo.md`, `foo.zh.md`, `foo.i18n.yaml`). The machine-checked header tokens (`# Agent Note: ` and the `Status:` line) stay in English verbatim in both languages (`.agents/notes/README.zh.md:131`); the body is free to be Chinese. The sidecar hashes this file section-by-section against the English one.
- **Non-obvious design decisions:**
  - **The anchors are manual on purpose.** The English file relies on GitHub's auto-generated heading slugs; the Chinese file's headings translate to different slugs, so the cross-references that point at *sections* (not files) would break. The `<a id="…">` anchors carry the **English** slug so the same in-document links work in both files (`.agents/notes/README.zh.md:21`).
  - **The English canonical header tokens are deliberately not translated** (`.agents/notes/README.zh.md:131`): the format gate's regexes and the pairing gate's structural signature both match on them, so a translated `Status:` line would make the file invisible to its own gate.
  - **The archive manifest's vocabulary is expanded in-line** — "append-only frozen-content manifest（元数据清单）" (`.agents/notes/README.zh.md:44`) — because a half-translated governance term loses its referent, and the reader of this file is an agent that must act on it.
  - **The feature-removal consolidation test is translated at the same granularity as the English** (`.agents/notes/README.zh.md:56`), including the negative clause that a surviving durable-data or compatibility path makes the removal *partial* supersession.
- **Edge cases / failure handling:** Mirrors the English file's policy exactly — deletion moves the English/Chinese/sidecar triplet together and repairs inbound links (`.agents/notes/README.zh.md:40`); archival inserts the same `Archived:` line in both language files (`.agents/notes/README.zh.md:42`); sealed archived triplets are permanently frozen and documentation gates skip them, including their outbound links (`.agents/notes/README.zh.md:44`). The pre-2026-07-05 grandfather comment is present verbatim in the Chinese file too, in the same fenced form (`.agents/notes/README.zh.md:119-123`), so the format gate and the pairing gate see the same structure on both sides.
- **Surprising:** The Chinese file is *longer* than the English (131 lines vs 125) despite carrying the same content — the extra lines are the three manual anchors plus the parenthetical glosses the English does not need (e.g. `（元数据清单）`). A "faithful translation" is not a line-for-line copy; it is a structural mirror plus whatever the target language needs to be unambiguous.

### .agents/notes/README.i18n.yaml

- **Purpose:** The machine-checked **bilingual-pairing sidecar** for `README.md` / `README.zh.md` — the third member of the "pair is three sibling files" contract.
- **Key abstractions:** One YAML entry per heading section that still contains language-specific content. The key is the **English heading-slug path** (`/agent-notes/layout-and-naming`, `/agent-notes/the-file-format/the-header-block`), with `~2`, `~3` … suffixes for repeated paths. Each entry holds a 16-hex hash of the English blocks and a 16-hex hash of the Chinese blocks in that section (`.agents/notes/README.i18n.yaml:5-46`).
- **Data flow:** It is **generated**, not authored: `pnpm run verify-translation-pairing --write .agents/notes/README.md` recomputes the hashes from the two Markdown files and rewrites the sidecar (`.agents/notes/README.i18n.yaml:3-4`). The pairing gate then compares the recorded entries against the entries computed from the current contents; a section whose recorded hash differs from the computed one is reported as "changed since confirmation" and the pair is out of sync. The comment header in the file states the whole contract and the repair command, so the file explains itself to whoever opens it.
- **Non-obvious design decisions:**
  - **The sidecar is keyed by SECTION, not by file.** `scripts/translation-pairing-record.ts:1-6` states the reason directly: "A record holds one entry per heading section with translated content, so independent edits to different sections change separate record lines and merge with Git's default text merge." A single whole-file hash would turn every two-language PR into a conflict; a per-section record makes the record itself mergeable, and a conflict appears only when both branches touched hashed content *in the same section*.
  - **Code fences and generated regions are excluded from the hash** because the pairing gate already requires them to be byte-identical on both sides; content that merely *happens* to be identical is still hashed (`.agents/notes/README.i18n.yaml:1-2` describes this).
  - **The section key uses the English slug even though the hash covers Chinese content** — the English side is the addressing scheme, so the key is stable when the Chinese wording changes.
  - **The regeneration command is written into the artifact it regenerates** (`.agents/notes/README.i18n.yaml:3-4`), so the fix for a red pair is in the file that went red.
- **Edge cases / failure handling:** A section whose content became empty on both sides loses its entry; a section that exists on one side only is a heading-count mismatch and the recorder throws; duplicate keys make the whole record unparseable and therefore invalid (the record parser returns `undefined` rather than a partial map). A "changed since confirmation" is a *per-section* message naming which side moved, so the repair is scoped to the section, not the file.
- **Surprising:** A 46-line YAML file that contains no prose and no human meaning is nevertheless a **first-class committed artifact whose diff is the review act** — re-recording a pair is the moment a human approves that the two languages now say the same thing. It is also a **mergeable** artifact, which is a genuinely unusual property for a generated file.

## Ideas worth stealing

- **Encode the state in the path and forbid the generated index; let the tree be the registry.** `.agents/notes/README.md:19` — "Do not add a centralized `INDEX.md`: it duplicates path metadata and makes unrelated note changes contend on one generated file." The enforcement is a one-line error at `scripts/agent-note-tree.ts:47-49` that turns the existence of `INDEX.md` into a build failure, and an unknown lifecycle folder into an error at `scripts/agent-note-tree.ts:53-54`. *Why it transfers to August*: August's own docs layer already fights a "one generated file everyone touches" pattern; a path-encoded state machine (`lifecycle/class/date-title.md`) makes `git log --oneline -- <dir>` the query, makes status legible from a file listing, and removes a whole class of merge conflicts — and the "no index" rule is only ten lines of gate code to enforce.
- **A required section with a dated, exact, self-terminating exemption.** `.agents/notes/README.md:111` makes `## Alternatives considered` mandatory in every note; `.agents/notes/README.md:113-117` defines the exact escape hatch — `<!-- agent-note-format: alternatives-not-recorded (pre-format Agent Note) -->` — and the gate accepts it **only** for notes dated before `2026-07-05` (`scripts/verify-agent-note-format.ts:13`, `:79-82`), while also refusing a file that carries *both* the section and the comment (`:80`). *Why it transfers*: this is the exact shape August needs for "every August plan doc must record the alternatives it beat" without grandfathering a growing pile forever, and it teaches the paired rule — a grandfathering escape hatch must carry an exact string, an exact date bound, and a mutual-exclusion check, or it becomes a permanent loophole.
- **Ban stale spec-speak by heading name, per lifecycle.** `.agents/notes/README.md:103` — in `implemented/`, the headings `## Proposal`, `## Plan`, `## Migration plan`, `## Acceptance criteria` are forbidden, because "an 'accepted in amended form' note is body content" and the filename/git already carry the timeline. The gate is one regex (`scripts/verify-agent-note-format.ts:36`) and one loop (`:72-76`). *Why it transfers*: this is August's "no Part 28 in a comment" rule turned from a convention into a mechanical ban; the same trick generalises to any documentation that must stop describing shipped behaviour in the future tense.
- **Cross-check the self-declared status against the folder that holds it.** `.agents/notes/README.md:68` — the `Status:` value "must agree with the lifecycle folder the file sits in — the gate cross-checks them" — implemented at `scripts/verify-agent-note-format.ts:22-26` (per-lifecycle regex) and `:57-60`. *Why it transfers*: August has exactly this failure mode in the brain (a fact that says "implemented" living in a "proposed" bucket, or a doc that says "shipped" for an unbuilt feature). A duplicated state in two places is a bug generator; make the second copy *checkable* rather than trusted.
- **Never edit a decision into its opposite — supersede and cross-link instead, with a full-absence test for removals.** `.agents/notes/README.md:48` ("An Agent Note is never edited into a *different decision*: supersede it with a new one, and keep both notes cross-linked"), the consolidation contract at `.agents/notes/README.md:50` (preserve every unique rationale, alternative, consequence, verification and named coverage gap; repair every inbound link; delete the counterpart **and** the sidecar in the same change), and the feature-removal test at `.agents/notes/README.md:52` (absent from production code, configuration, schemas, durable/wire formats, migration and compatibility behaviour; no current doc presents it as available; no test exercises it as supported behaviour; "removing one transport, default, implementation, or presentation is partial supersession"). *Why it transfers*: this is the missing mutation law for August's durable memory. August's `remember` overwrites a fact in place, so a decision that changes is silently restated; and August's "forget" retires a row with no record of what it displaced. A supersession rule (new fact + link to the fact it replaces) plus a full-absence checklist for deletion would make the brain's history legible and would make "I removed the feature" auditable in the same way the note tree makes it auditable.
- **Make a bilingual/dual-source contract a mergeable, reviewable artifact instead of a gate assertion.** `.agents/notes/README.i18n.yaml:1-4` — the sidecar names itself, its scope, and the exact command that re-records it; `.agents/notes/README.i18n.yaml:5-46` is one entry per heading section with an `en` and a `zh` hash. The design rationale is in `scripts/translation-pairing-record.ts:1-6`: "one entry per heading section with translated content, so independent edits to different sections change separate record lines and merge with Git's default text merge." *Why it transfers*: the generalisable mechanism is **section-scoped, hashed, committed sidecars for any two artifacts that must agree**. August's `check:brain-config` asks the backend which brain keys it accepts and what ranges they take; a sidecar of `{key: {backend_hash, panel_hash}}` recorded per key would turn "the Settings panel and the backend agree" into a diff a human reviews — and, because it is per key, two PRs touching different keys merge cleanly instead of colliding on one generated blob. The same trick works for the desktop/backend protocol contract, where the frontend and `backend-py` are two copies of one schema.
- **Seal the frozen history with an append-only, hash-manifested archive that can only grow.** `.agents/notes/README.md:40` (archival permits only the triplet move, the `Archived: YYYY-MM-DD` line in both language files, the sidecar re-record and inbound-link repair) and `.agents/notes/README.md:42` ("`verify-archived-agent-notes` enforces the closed class tree, complete triplets, archive metadata, sidecar hashes, and the append-only frozen-content manifest"). The enforcement is `scripts/verify-archived-agent-notes.ts:87-99` (compare against a trusted baseline — `DSH_ARCHIVE_BASE_REF` in CI, `HEAD` locally — and only *extend*) and `:107-112` (write mode adds new artifacts and leaves existing seals unchanged). *Why it transfers*: this is the pattern for August's own audit trail. An append-only manifest of hashes for decisions, prompts and tool schemas gives (a) tamper-evidence — you can prove a shipped prompt was not quietly edited, (b) a cheap diff for "what changed since the last release", and (c) a migration story for the next version, because a seal that may only be extended is a seal whose *history* is reconstructible. The `DSH_ARCHIVE_BASE_REF` detail is the one to copy: CI must compare against a **trusted pre-change commit**, not against whatever the working tree happens to contain, or the check is theatre.
- **Make the vocabulary closed, and document why the tempting class is absent.** `.agents/notes/README.md:23` (the class set is closed in `scripts/agent-note-tree.ts`; the gate rejects other folders), `.agents/notes/README.md:30-34` ("`architecture` is about the source we ship; `process` is about the surrounding tooling" and "`refactor` is deliberately absent — it overlaps `simplification`, whose discriminator, 'does observable behavior change?', already covers it"), enforced at `scripts/agent-note-tree.ts:19` and `:71-73`. *Why it transfers*: the pattern is not "have a taxonomy", it is "have a closed taxonomy, a gate that rejects anything outside it, and a written answer to the one question a reader will ask — why isn't X a category?" August's brain `kind` values and its tool-name vocabulary have the same drift pressure, and the same answer.
- **Use size only as a discovery aid, never as a criterion — and calibrate with worked examples.** `.agents/notes/README.md:38` ("Use the calibrated `dsh-archive-agent-notes` workflow rather than word count, age, or a target quota") with the examples in `.agents/skills/dsh-archive-agent-notes/SKILL.md:35-52`: a 533-word note is deleted while a 628-word note is kept, a 334-word note is kept because it names a reintroduction condition, and a 972-word rejected note is deleted because its premise is obsolete. *Why it transfers*: this is exactly the rule August's memory consolidation needs. Any automatic "keep the top-N facts by score" or "retire facts older than N days" policy is size-as-criterion, and the August AGENTS.md already shows the failure mode (a fact dropped for budget silently vanishing from the recall tail). A semantic keep/delete/archive classification with calibrated examples is the alternative — and the "keep it because it names the *reintroduction condition*" criterion is a good one to steal verbatim for durable facts.
- **Freeze the archive's *outbound* links too — a historical snapshot may not be repaired, only preserved.** `.agents/notes/README.md:42` ("Documentation gates skip archived sources, including their outbound links; active prose may still link into an archived note when it intentionally cites history") and `.agents/notes/archived/AGENTS.md:5` ("Do not inspect, verify, or repair links out of archived notes"). *Why it transfers*: the link checker in `scripts/verify-md-links.ts` demonstrably ignores broken links inside archived notes (see its fixture at `scripts/verify-md-links.spec.ts:53`). Any August archive — a frozen prompt, a retired tool schema, a superseded plan — should be excluded from live linting, because "fixing" a frozen artifact is how a historical record starts lying.
