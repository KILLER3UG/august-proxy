# deepseek-harness / dsh-platform#1

## Shard shape

This shard is the **platform layer of the DeepSeek Harness plugin system**, split into two
families plus two small utility groups:

1. **`packages/extensions/` — the "Cordis" dynamic-plugin subsystem (4 packages, 96 files).**
   `cordis-host-runner` owns the *host* half: a process-local registry of immutable
   "packages" (versions of a dynamic plugin), a `node:vm` sandbox in which a model's
   host-half code is evaluated, a registration guard (schema normalization, a whitelisting
   `ctx` facade, a marker-guarded tool-registration pair), and the approval round trip that
   suspends a run until a human says yes. `cordis-client-runner` owns the *browser* half:
   it evaluates the browser half as a closure, mounts it through the same loader the
   static plugins use, and answers run requests. `tool-cordis` exposes two read-only
   model-facing tools (`cordis_inspect_list` / `cordis_inspect_query`) so an agent can
   discover the runtime API surface before writing plugin code. `ui-cordis` renders the
   frame-wide approval/control panel and the historical tool cards.
   The shape is: *definitions are immutable versions, activations are runs, and every
   observable fact (labels, status, failures) is owned by exactly one side* — host owns
   process-wide truth, page owns page-local truth, and the two are never derived from
   each other.
2. **`packages/host/` — the web-GUI host half (9 packages, 93 files).** An HTTP(S) route
   registry with an index-injection mechanism and a single fallback seat; the SPA dist
   server that owns that seat; the workspace-directory-picking *seam* with a native
   backend, a browse backend and an adaptive boot-time chooser; the "open in app"
   application probe/launch routes; a read-only projection of the Cordis Loader tree; and
   an explicit product-telemetry adapter.
3. **`packages/settings/` + `packages/identity/` (26 files).** Schema-derived live
   configuration forms with revisioned, optimistic-concurrency writes and structural
   secret redaction; and one anonymous per-harness-home correlation id.

Everything in this shard is **host/browser infrastructure**: nothing here builds a model
prompt, parses reasoning content, compacts a context window, or runs a subagent. The
"agent loop" appears only as the *surface the platform offers the loop* — two read-only
inspection tools, a tool-registration boundary, a session-steering channel, and a
human-approval gate in the middle of a tool call.

### packages/extensions/cordis-client-runner/src/client/evaluator.ts
- Purpose: evaluate a browser half's source, which is the *body of an async function*.
- Key abstractions: `evaluateClientHalf`, `DynamicCordisStyles`, `DYNAMIC_CLIENT_REDIRECTS`, `isDynamicCordisPlugin`.
- Data flow: `new Function(...params, 'return (async () => {…})()')` → the closure receives `React`, a tagged `console`, `styles`, `host`, a `harness` trap, and one trap per withheld global → the returned value must be a plugin (function or `{apply}` object).
- Non-obvious design decisions: the *parameters shadow the ambient globals*, so reaching `setTimeout` throws a message that names the real capability instead of silently working; `host.call` with no argument travels as `null` because `undefined` is not JSON (evaluator.ts:199).
- Edge cases / failure handling: a `SyntaxError` from the browser is rewritten into a "plain JavaScript, no JSX/TypeScript" teaching error; a non-`Error` rejection is stringified; a circular `console` argument becomes `[unserializable console argument]` rather than throwing.
- Surprising: the same redirect table is reused later to enrich a *render crash* message, so the author gets the same advice whichever way they hit the wall (see `runtime.ts:504`).

### packages/extensions/cordis-client-runner/src/client/guard.ts
- Purpose: the whitelist facade a loaded browser half's `apply` receives in place of the real `ctx`.
- Key abstractions: `dynamicCordisContext`, `guardedSlots`, `guardedTheme`, `guardedService`, `denyContext`.
- Data flow: `ctx.get(name)` is an optional lookup; `ctx.<service>` property access is gated by the fiber's `inject` declaration; timer verbs additionally require `inject: ['timer']`.
- Non-obvious design decisions: `theme.overrideTokens(source, tokens)`'s `source` is **replaced** with the package id so a dynamic package can never impersonate or evict another source's layer (guard.ts:176); the slots seat assigns the shadowing priority itself so a later registration always wins (guard.ts:129); the `tool.view.cordis` slot accepts only `key: 'self'` and the guard rewrites it to the package identity (guard.ts:119).
- Edge cases / failure handling: a service that returns a cordis `Context` is refused (the classic escape); a context-valued *promise* resolution is refused too; the facade is read-only; `in` answers reachability without throwing.
- Surprising: the file's own header says this is **API discipline, not a security boundary** — a dynamic package is as trusted as the host process that accepted its definition.

### packages/extensions/cordis-client-runner/src/client/index.ts
- Purpose: the browser plugin entry.
- Key abstractions: `CordisRunnerFace` (the service a UI surface reads and calls), `invokeFailure`/`invokeError`/`wireFailure` (teaching-error builders).
- Data flow: subscribes `cordis/request-run`, `cordis/request-run-resolved`, `cordis/dynamic-retract`, `cordis/inspect-query`, `cordis/inspect-query-resolved`; provides `dynamicCordisRunner`; registers the inspect providers.
- Non-obvious design decisions: the two failure layers are kept apart — a *carrier* error means the call never reached the host, while the namespace's own `ok:false` is the host half answering with a refusal; the teaching text is added here because this is the only place that still knows which call it belonged to (index.ts:212-215).
- Edge cases / failure handling: render-failure and guard-failure reports are fire-and-forget and their failures are logged, never surfaced — one crash must not become two.
- Surprising: the plugin declares `remote.dynamicCordisRunner` in `inject`, so it parks until the host namespace exists and therefore can never load a browser half whose host half it could not reach.

### packages/extensions/cordis-client-runner/src/client/inspect-registry.ts
- Purpose: the browser-side registry of read-only inspect providers.
- Key abstractions: `ClientCordisInspectRegistry`, `ClientCordisInspectProviderRegistration`, `ClientCordisInspectQueryContext`.
- Data flow: `register()` publishes the complete manifest (microtask-coalesced, then chained through `syncChain` so manifests never interleave) → the host mirrors it → a query arrives → the provider runs → the first valid answer settles.
- Non-obvious design decisions: the manifest is published **complete**, never patched, so the host's mirror cannot drift; a duplicate provider id or a repeated method name throws at registration.
- Edge cases / failure handling: a missing provider or method becomes a structured refusal rather than a throw; an abort converts a late result into `{ok:false, reason:'cancelled'}`; `close()` aborts a local query another page already answered.
- Surprising: the answer is `accepted` only for a *valid success* — a failed page returns `accepted:false` and does not block another page from answering successfully.

### packages/extensions/cordis-client-runner/src/client/orchestrator.ts
- Purpose: drive a run from request to exactly one resolution.
- Key abstractions: `CordisRunOrchestrator`, `CordisRunActivity` (`awaiting-approval` | `orchestrating`), `CordisRunFailure`, `CordisRunHostSeam`.
- Data flow: `open()` registers the request (and auto-starts it when no approval is required) → `approve`/`decline`/`startUserRun` → `drive()`: host half → fetch client code → load browser half → one resolution (or a failure answer).
- Non-obvious design decisions: the *host half always runs first* so a host-half failure short-circuits before the browser has moved; a host-only definition never fetches source (asking for source that does not exist would report a successful run as a failed half it never had — orchestrator.ts:432); the activity map is keyed by **plugin id**, not by request, so an affordance survives a remount.
- Edge cases / failure handling: a second approve joins the orchestration already in flight; a late decline is refused because the decision was already made; a failure the host refuses to record is logged and dropped, and the run settles anyway.
- Surprising: `reconcileApprovals` rebuilds pending approvals from an authoritative host inventory, so a page that missed an event still shows the right affordance.

### packages/extensions/cordis-client-runner/src/client/providers.ts
- Purpose: the first-party browser inspect providers.
- Key abstractions: `clientInspectProviders`, `CLIENT_BUILTIN_INSPECTION`.
- Data flow: `Service` and `Event` read the generated catalogs; `Builtin` lists the exact closure symbols; `Slots` projects the live slot tree; `Theme` exports the current token names.
- Non-obvious design decisions: the "exact" input schemas are *per-provider* and closed (`additionalProperties:false`), so a typo is a rejection rather than a silent null.
- Edge cases / failure handling: a missing `slots` or `theme` service throws a named error rather than returning an empty tree.
- Surprising: the `Slots` provider's tree projection carries `replaceRisk` per slot — a model is told before it registers whether it will replace shipped UI.

### packages/extensions/cordis-client-runner/src/client/runtime.ts
- Purpose: the browser load engine.
- Key abstractions: `DynamicCordisPackageRunner`, `DynamicCordisLoadResult`, `DynamicCordisRenderFailure`, `CordisObservable`.
- Data flow: evaluate → guard → `modules.invalidate(moduleId)` → `window.__ModuleLoader__.load({id, factory})` → `loader.create({name})` → `fiber.await()` → seat the record; unload is loader-entry removal (fiber disposal cascades) → factory invalidation → style removal.
- Non-obvious design decisions: **invalidate-then-register** keeps re-loading legal because the module table throws loudly on a duplicate factory (runtime.ts:371); loads **converge by run identity against live state, not history** — reloading the same activation is a no-op that still *answers* (a replayed run must not look unacknowledged, runtime.ts:293); the record is seated only after `fiber.await()` so an error mirrored during `apply` cannot claim the package is live.
- Edge cases / failure handling: three failure stages (`evaluate` / `module-import` / `activate`) each with their own cleanup; the per-plugin queue's tail swallows rejections so one failure does not wedge later operations (runtime.ts:339); a retracted revision is ignored and a superseded one survives.
- Surprising: the `owners` WeakMap keys ownership by **component identity** (runtime.ts:202) — the header enumerates why each alternative (a parallel ledger, `entry.registrant`, the assigned priority) fails, including that a package could otherwise impersonate another.

### packages/extensions/cordis-client-runner/src/client/timer.ts
- Purpose: the browser timer service dynamic packages inject.
- Key abstractions: `ClientTimerService` (extends cordis `Service`, mixes six helpers onto `ctx`).
- Data flow: every pending timer is a `ctx.effect`, so it dies with the plugin's fiber; `timeout(delay)` returns a promise; `interval(delay)` returns an async iterator.

### packages/extensions/cordis-host-runner/src/guard.ts
- Purpose: the boundary between sandboxed model code and the live runtime.
- Key abstractions: `sandboxDefineTool`, `sandboxRegisterTool`, `normalizeHandler`, `sandboxContext`, `guardedPlugin`, `cloneJson`, `normalizeParameterSchemaSpec`.
- Data flow: `harness.defineTool(options)` normalizes the schema into a host-realm `ParameterSchemaSpec`, wraps `execute`/`render`/`presentationMeta` in a cross-realm JSON clone, tags the tool with a private `DYNAMIC_TOOL` symbol, and `harness.registerTool(ctx, tool)` verifies that symbol before handing it to the registry.
- Non-obvious design decisions: `ctx.tools.get(name)` returns a **schema view**, never the live `ToolDefinition` — exposing the definition would hand package code the tool's `execute` function and let it bypass `ToolRuntime.execute` and every guard around dispatch (guard.ts:648); `cloneJson` is an explicit stack of work frames rather than recursion, so a deeply nested schema cannot blow the stack, and it refuses non-JSON values with an error that names the *executable next step* ("return a plain object built from the values you need, or `return null`", guard.ts:122).
- Edge cases / failure handling: unsupported JSON-Schema vocabulary fails at *registration* with a teaching error; a circular schema is detected; a value with a non-plain prototype is rejected rather than silently coerced.
- Surprising: the file documents the one place it deliberately duplicates the browser half's guard, and argues the duplication is the right call: "Moving the rule into a shared package would move a security invariant out of the halves that enforce it" (guard.ts:663-667).

### packages/extensions/cordis-host-runner/src/index.ts
- Purpose: `DynamicCordisRunnerService` — the registry, the lifecycle verbs, the approval round trip, the inspect bridge and the steering channel.
- Key abstractions: `Config` (`vmTimeoutMs`, `clientInspectTimeoutMs`), `DynamicCordisSnapshotRow`, `ActivationPlan`.
- Data flow: `define` prechecks both halves' syntax and mints ids; `run` either activates a host-only package immediately or arms an approval request and emits `cordis/request-run`; the page answers `runHostHalf` → `getClientCode` → `resolveRequestRun`; `commitActivation` sets `currentPackageId`.
- Non-obvious design decisions: `resolveRequestRun` refuses a resolution naming a run that is not the live one (index.ts:438) — a stale success is *not* accepted; the `run`/`update` mode check is a real state machine (`invalid-mode` with a message naming the right mode); a runtime failure is steered to the owning session **once per (platform, kind, message)** via `claimRuntimeFailure` (index.ts:1136), keyed by a NUL-joined string so the same failure cannot spam the transcript.
- Edge cases / failure handling: `stop` retracts the live dispatch and keeps the definition runnable; `undefine` also forgets it; a failed start leaves nothing running; the `latestRun` attempt record keeps the phase, message and stack for every failure.
- Surprising: `steerRunOutcome` and `injectUserContext` write *user* messages into the session — the model's own history is not rewritten, so the prompt prefix stays cache-stable (index.ts:1062).

### packages/extensions/cordis-host-runner/src/inspect-registry.ts
- Purpose: the host registry of model-visible read-only capability providers.
- Key abstractions: `CordisInspectRegistryService`, `CordisInspectProviderRegistration`, `PendingClientQuery`.
- Data flow: host providers register locally; the client manifest is mirrored wholesale; a client query is validated against the method's JSON Schema, broadcast as `cordis/inspect-query`, and settled by the first valid page answer or a timeout.
- Non-obvious design decisions: a *failed* page's answer is retained as the first diagnostic but does **not** settle the query, so another page can still answer successfully (inspect-registry.ts:155); the query is refused up front when the gateway has no live client, rather than waiting out the timeout.
- Edge cases / failure handling: the input and output are both schema-validated at the boundary; a non-JSON output is rejected; disposal settles every pending query as cancelled.
- Surprising: the timeout message distinguishes "no page answered" from "the first page failed", which are different user actions.

### packages/extensions/cordis-host-runner/src/lifecycle.ts
- Purpose: start a sandbox-produced plugin as a child fiber under the `cordis-dynamic` group.
- Key abstractions: `startHostHalf`, `missingServices`.
- Data flow: `await group.await()` → `group.ctx.plugin(guardedPlugin(...))` → `fiber.await()`; on failure the fiber is disposed before the error is rethrown.
- Non-obvious design decisions: a failed fiber is **never left mounted**; an "already registered" collision is rewritten into the *replace recipe* (stop the old package, then run the new version) rather than a bare conflict.
- Edge cases / failure handling: a settled-but-pending fiber is a legal success whose missing services are reported by name (`missingServices`).

### packages/extensions/cordis-host-runner/src/registry.ts
- Purpose: the process-local definition registry.
- Key abstractions: `DynamicCordisRegistry`, `DynamicCordisPlugin`, `DynamicCordisDefinition`, `DynamicCordisRun`, `DynamicCordisPendingRequest`.
- Data flow: `mintPluginId`/`mintPackageId`/`mintPluginRunId`/`mintApprovalRequestId` mint never-reused ids; `armRequest`/`peekRequest`/`claimRequest`/`disarmRequest` manage approvals; `ofSession` filters by owning session.
- Non-obvious design decisions: the plugin id carries a *semantic prefix* the model chose (`clock-1`, `dyn-1`), minted so a prior suffix is never reused; `claimRequest` deletes on claim, so the first answer wins by construction.
- Edge cases / failure handling: `approvedClientPackages` and `clientVersionUpdatesApproved` record two distinct kinds of human authorization (this version, or future versions).

### packages/extensions/cordis-host-runner/src/sandbox.ts
- Purpose: the `node:vm` realm a host half evaluates in.
- Key abstractions: `createSandbox`, `evaluateHostCode`, `precheckCode`, `parseErrorMessage`, `syntaxErrorContext`.
- Data flow: `createContext(sandbox)` with a tagged console, `harness` registration verbs, `btoa`/`atob`/`TextEncoder`/`TextDecoder`, and callable traps; `runInContext('(async () => {…})()', …, {filename, timeout})`.
- Non-obvious design decisions: a **dual-realm `instanceof` patch** (sandbox.ts:34) so `args.items instanceof Array` is true for host-realm values passed into the sandbox — without it, a tool's `execute` sees silently-false checks; only *function-valued* globals are trapped, so a data-valued `process` stays `undefined` rather than detonating the ubiquitous `typeof process` feature probe.
- Edge cases / failure handling: cross-realm `SyntaxError` detection uses the `name` property, not `instanceof` (sandbox.ts:124); the define-time precheck compiles the source and runs nothing, so unparseable code never reaches the registry; the TypeScript heuristic is scoped to the **offending line only** so an ` as ` inside an ordinary description string cannot mislabel a plain syntax error (sandbox.ts:155).
- Surprising: `precheckCode` uses `new Function` as the gate (works without a real `node:vm`) and `vm.Script` only as a best-effort prettifier for the caret prelude — and it documents the accepted syntax-face difference as a deliberate cost.

### packages/settings/settings/src/index.ts
- Purpose: the `ctx.settings` service — schema-derived forms and revisioned edits.
- Key abstractions: `SettingsForms`, `SettingsDescriptor`, `SettingsConflictError`, `SettingsPathOp`, `cloneJsonShaped`, `mergeLayers`.
- Data flow: `describe()` walks the config editor's entries → for each active entry, project the volatile form, compute a revision, project the live value / base / user layers, redact secrets → the client edits via `update` / `replace` / `mutate` → `write()` re-reads the descriptor, compares the revision, validates that every written path is volatile, strips the non-volatile fields back out and delegates to the config editor.
- Non-obvious design decisions: the revision is a **monotonic counter over a hash of `(fiber uid, schema, raw config)`**, so a stale editor is refused rather than silently overwriting a concurrent change (settings/src/index.ts:313-318); `SettingsPathOp` exists *because* the client never received the secret fields — "a wholesale `replace` rebuilt from a redacted document silently deletes every secret the wire never returned" (settings/src/index.ts:85-90); `cloneJsonShaped` is stricter than `structuredClone` because YAML/JSON storage silently distorts Dates, Maps, BigInts and cycles on the reload round-trip (settings/src/index.ts:143-154).

- Surprising: `describe()` emits `settings/document-updated` when a form's raw content or its `autoGenerate` policy changes, and bumps the revision when an entry disappears — the form clients learn about both by re-reading.

- Data flow: walk the schema and the value together → remove every `role('secret')` field → collect `{path, set}` for each removal.
- Non-obvious design decisions: the walker visits **every union branch** and conservatively removes any field declared secret by a branch; object-property secret slots are enumerated *even when unset* so a form knows the slot exists, while dict entries and array items are only listed where the value has them; a secret-role *container* is one opaque leaf.

- Key abstractions: `plainConfig`, `volatileForm`, `projectForm`, `isVolatilePath`, `plainSchema`.
- Data flow: `volatileForm(schema)` keeps only the subtrees whose nearest volatile ancestor makes them editable → `plainSchema` strips `meta.volatile` and removes secret defaults → `projectForm(form, value)` keeps only schema-declared fields.
- Non-obvious design decisions: a raw config node that is an unevaluated `!!js` expression is kept **whole** rather than projected field by field, so a config expression is not mangled by a form edit (schema.ts:50-52); a schema default that is itself a secret is redacted out of the *schema* too, not just the value.
- Edge cases / failure handling: an object schema with no declared fields yields `undefined` (no form); `isVolatilePath` answers whether a field path lies beneath a declared volatile node, and it is the write fence.

## Ideas worth stealing

- **A "capability façade" that denies by default and *teaches* each denial** — `packages/extensions/cordis-host-runner/src/guard.ts:718` — a `Proxy` over an empty object exposing only lifecycle verbs and *declared* services, where a denial names the fix ("Declare it: inject: ['x', …] on your plugin, so cordis parks this dynamic package if the provider later goes away"). August's sandbox equivalents (code runner, tool surface) can adopt the same shape: a whitelist facade whose every refusal carries the exact declaration the caller must add.

- **Deny a service that returns a live context handle, on both the sync and the promise path** — `packages/extensions/cordis-host-runner/src/guard.ts:669` — `denyContext` wraps every service method and checks the *resolved* value, which closes the "service.ctx.root" escape that a naive `instanceof` check on the raw return would miss. The browser half repeats the rule against *its own* `Context` class, and the file explains why the duplication is deliberate (guard.ts:663-667) — each half must test against the class of its own face.

- **Expose a tool's *schema*, never its `execute`** — `packages/extensions/cordis-host-runner/src/guard.ts:648` — `ctx.tools.get(name)` returns the same name/description/parameters view as `schemas()`, so untrusted code cannot call another tool directly and bypass the dispatch-time guards (identity protection, pre-policy, monotonic guards, post-policy, result normalization). August's tool registry should expose a read-only view to any sandboxed caller, not the live definition.

- **Make a *withheld capability* throw a message that names where it really lives** — `packages/extensions/cordis-client-runner/src/client/evaluator.ts:43` — the closure's parameters shadow `setTimeout`/`fetch`/`require` with traps whose error text redirects to the sanctioned route ("Declare inject: ['timer'] on the returned plugin …"). This converts a silent failure into a self-correcting model turn, and it is the same pattern August needs for "you cannot shell out directly; use the sandboxed `run_command`".

- **Reuse one redirect table to enrich a *later* error the model actually sees** — `packages/extensions/cordis-client-runner/src/client/runtime.ts:504` — a render crash whose text merely *names* a withheld global gets the same redirect appended (and only if it is not already there). The author gets the same advice whether they hit the trap directly or reached the global around it.

- **Converge loads by identity against live state, and always answer** — `packages/extensions/cordis-client-runner/src/client/runtime.ts:288` — re-issuing the exact activation already live is a no-op that still returns a success receipt, because "a replayed run must not look unacknowledged". August's tool/subagent registries should answer a duplicate request from live state rather than from history, and should never leave a caller waiting.

- **A per-item operation queue whose tail survives a failure** — `packages/extensions/cordis-client-runner/src/client/runtime.ts:334` — `this.queues.set(id, next.then(() => {}, () => {}))`: one rejected operation would otherwise wedge every later operation on the same item. A one-line pattern that removes a whole class of "the tool is stuck forever" bugs.

- **Attribute a crash by the *identity of the thing that crashed*** — `packages/extensions/cordis-client-runner/src/client/runtime.ts:202` — a `WeakMap` from the seated component to its owner, with a comment enumerating why each alternative (a parallel ledger, `entry.registrant`, the assigned priority) fails. Any August subsystem that lets a caller register a callback and later wants to report "your callback crashed" should key on the callback's identity.

- **Progressive API disclosure with a *referenced type closure*** — `packages/extensions/cordis-client-runner/src/client/api-catalog.ts:1101` and `:1128` — list a compact directory of services and method signatures, then one exact contract, then **only the types that contract mentions**, transitively. This is the pattern to copy for any model-facing API surface: directory first, exact contract second, transitive types third.

- **Pin a capability's *identity* so a caller cannot impersonate or evict another** — `packages/extensions/cordis-client-runner/src/client/guard.ts:154` — `theme.overrideTokens(source, tokens)`'s `source` argument is *replaced* with the package id, and the disposer is hung on the calling fiber so unload restores even when the caller drops the handle. The same "you may not name yourself" rule appears for the `tool.view.cordis` slot key (guard.ts:119).

- **A per-verb, per-service facade for a client half that mirrors the host half** — `packages/extensions/cordis-client-runner/src/client/guard.ts:1` — the two halves implement the *same* whitelist contract in two programs, which is what lets an author meet "one contract on both halves". August's browser/host split (if it has one) should define the contract once in prose and implement it twice, rather than inventing one per plane.

- **Refuse a resolution that names a run that is not the live one** — `packages/extensions/cordis-host-runner/src/index.ts:438` — `resolveRequestRun` returns `{accepted: false}` when the resolution's `pluginRunId` is not the live activation. A stale success is not accepted, and the caller is told why; the browser half does not read the acknowledgement, so the *host* must be the authority. August's approval round trip needs the same rule.

- **Report a runtime failure to the owning session *once* per (kind, message)** — `packages/extensions/cordis-host-runner/src/index.ts:1136` — `claimRuntimeFailure` keys on a NUL-joined string and checks the attempt's status, so a repeatedly failing handler cannot spam the transcript with the same message. The steering message is a *user* message, so the model's prompt prefix is untouched (index.ts:1075).

- **A write door that is a *path* operation, because the client never received the whole document** — `packages/settings/settings/src/index.ts:85` — `SettingsPathOp` (`set`/`unset` at a path) exists so a UI holding a *redacted* view can change one field without restating (and thereby deleting) the secrets the wire never sent. Any August settings surface that redacts secrets on the way out must accept path-addressed writes for the same reason.

- **Secret redaction returns *presence*, not value** — `packages/settings/settings/src/redact.ts:106` — a `role('secret')` field is removed from the value and a sidecar records `{path, set}`; unset object-property slots are still enumerated so a form knows the input exists. A UI can therefore render a write-only secret input without ever holding the secret.

- **Optimistic concurrency on configuration writes, keyed by a content hash** — `packages/settings/settings/src/index.ts:313` — the revision is a monotonic counter over `(fiber uid, schema, raw config)`, and a write carrying a stale revision is refused with `SETTINGS_CONFLICT` plus both revisions. August's config writes should refuse a stale editor rather than clobber a concurrent change.

- **Validate the *shape* of a config write stricter than `structuredClone`** — `packages/settings/settings/src/index.ts:143` — `cloneJsonShaped` rejects Dates, Maps, BigInts, non-finite numbers and cycles, because "YAML/JSON storage then silently distorts them on the reload round-trip". A config door that accepts anything `structuredClone` accepts will corrupt data quietly.

- **A single-flight read with a *generation* counter, and a failed read that keeps its rows** — `packages/extensions/ui-cordis/src/client/inventory.ts:61` — the generation is bumped on reset so a read belonging to the previous connection publishes nothing (neither its success nor its failure), and a failed read keeps what was shown and adds the reason, because "dropping the rows would turn a transient wire failure into 'nothing is defined'".

- **The surface that blocks the model must be reachable from anywhere** — `packages/extensions/ui-cordis/README.md:56` — "the panel is global because a run request blocks the model and can name a definition belonging to a session nobody is looking at; an approval reachable only inside that session's transcript would be unreachable exactly when it blocks the model." A direct rule for where a blocking affordance may live.

- **Re-read on an announcement instead of patching a cache** — `packages/extensions/ui-cordis/README.md:75` — the announcements carry no labels and a definition can appear or disappear between them, so a patch-in-place cache would drift into showing definitions the host no longer holds. Cheap reads beat clever caches when the event payload is thin.

- **A fixed status vocabulary with one function mapping it to the UI** — `packages/extensions/ui-cordis/src/client/CordisPanel.tsx:77` — `panelDotState` is the only place a status becomes a colour, so no row can invent its own. Combined with `data-cordis-status` attributes on the DOM, this is also a *test* surface.

- **A tool description that carries the workflow and the limit** — `packages/extensions/tool-cordis/src/index.ts:24` — the description says to call the list tool first, to select provider and method *from its result*, and "Do not guess names or treat an Inspect method as a business Service that Plugin code can call". August's model-facing tool descriptions are the cheapest prompt surface there is; this one teaches ordering and refusal in the description rather than in a system prompt.

- **Register the provider once per process, and the tool once per session** — `packages/extensions/tool-cordis/src/host.ts:16` and `packages/extensions/tool-cordis/src/index.ts:21` — the registry keys by provider id and rejects a duplicate, so the process-global registration and the per-session tool row are separate entries. A duplicate-registration error is a design error here, not an accident to be tolerated.

- **A Config provider that reports *why* a plugin has no config** — `packages/extensions/tool-cordis/src/config.ts:16` — five explicit statuses (`schema` / `absent` / `unsupported` / `tree` / `inactive`) instead of one "no config", so a model can tell "this plugin takes no config" from "this entry is disabled" from "this is a loader carrier". Status vocabularies like this are worth copying for any discovery surface.

- **Parse-time teaching, scoped to the offending line** — `packages/extensions/cordis-host-runner/src/sandbox.ts:151` — the error carries the offending source line and caret, and the TypeScript-removal heuristic is applied to **that line only** so an ` as ` inside a description string cannot mislabel a plain syntax error (sandbox.ts:155). A bracket-balance hint covers the single most common model mistake (closing a returned object with `});`).

- **Compile the code at define time so unparseable code never reaches the registry** — `packages/extensions/cordis-host-runner/src/sandbox.ts:184` — `precheckCode` constructs the function (parsing without running) at *define* time, so the model fixes its code and defines again instead of discovering the failure at run time. Cheap, and it moves the error to the turn where it is fixable.

- **A dual-realm `instanceof` patch so a sandbox's `instanceof` is not silently false** — `packages/extensions/cordis-host-runner/src/sandbox.ts:34` — host-realm values passed into the sandbox otherwise fail `args.items instanceof Array` without any error. Any August sandbox that crosses a realm boundary needs this.

- **Trap only *function-valued* globals** — `packages/extensions/cordis-host-runner/src/sandbox.ts:63` — a data-valued global such as `process` stays `undefined` rather than becoming a throwing accessor, because a throwing accessor "would detonate the common `typeof process` feature probe at resolution time".

- **Refuse a wildcard bind address at load, with the reason spelled out** — `packages/host/webserver/src/index.ts:284` — "binding every interface would expose remote code execution to the network". A configuration validator that refuses a dangerous value *and explains the danger* is a pattern August's server/host surfaces should copy.

- **Parse an address the way the socket will read it** — `packages/host/webserver/src/index.ts:133` — `ipaddr.js` reads `::0.0.0.1` as the IPv4-mapped `::ffff:0:1` while `getaddrinfo` (and therefore `listen`) reads it as the low 32 bits, so the tail is rewritten before parsing to keep the parsed value equal to the bound value. A general lesson: classify addresses by value, never by spelling.

- **Contain a per-request failure instead of letting it exit the process** — `packages/host/webserver/src/index.ts:443` — a handler that throws answers 400 (or destroys the socket when headers are out) and logs a warning; "one malformed request" must never kill the server. August's HTTP/stream entry points need the same last-resort guard.

- **Bound a listing by *value*, not by count** — `packages/host/directory-picker-browse/src/index.ts:76` — a name-sorted streaming window with a `maxEntries + 1` slot, so memory stays O(keep) for an arbitrarily large directory, an in-window extra row proves the cut, and a candidate beyond the tail is rejected in O(1) instead of a window scan.

- **Refuse a path that is not *fully qualified*, on every platform** — `packages/host/directory-picker-browse/src/index.ts:50` — on Windows that excludes `\foo`, `/foo` and incomplete UNC prefixes, which `isAbsolute` accepts but which resolve against the process's current drive. A wire path must never resolve against process state.

- **Race every filesystem await against the caller's abort, and swallow the abandoned settlement** — `packages/host/directory-picker-browse/src/index.ts:108` — a stalled network filesystem must not keep a departed caller's request alive, and the abandoned read's late settlement must not surface as an unhandled rejection.

- **Detach a launched child with a credential-scrubbed environment, and never kill it for surviving the watch window** — `packages/host/open-in-app/src/resolver.ts:80` — the child gets `scrubbedParentEnv()` (no `*KEY*`/`*SECRET*` variables), and a launcher still running when the watch window closes is unrefed and counted launched, because GUI applications legitimately stay in the foreground for their whole lifetime.

- **Ask the trust fence *first*, before any work** — `packages/host/open-in-app/src/index.ts:185` — every route calls `connection.requestRejection(req)` before resolution, icons or launches; the open route then validates media type, body size, catalog id and directory at the wire. "The complete trust story has one home" is the comment — August's route registration should have the same single entry point.

- **Resolve expensive detection exactly once, lazily** — `packages/host/open-in-app/src/index.ts:155` — the catalog is resolved on the first request that needs it and cached for the plugin's life, so a click, a menu open or a page reload never re-runs detection; a missing executable re-resolves only that one entry.

- **A traversal check against the *platform* separator** — `packages/host/frontend-static/src/index.ts:80` — `resolve()` emits backslash paths on Windows, where a `'/'` suffix would reject every legitimate subpath as traversal. A security check that is wrong on one platform is worse than none, because it looks like coverage.

- **Settle a concurrent first launch with an exclusive-create write** — `packages/identity/anonymous-user-id/src/index.ts:79` — `writeFileSync(..., {flag: 'wx'})`; the loser rereads and adopts the winner's id, and persistence failure is best-effort so the feature is never blocked by an unwritable home.

- **Drain a telemetry channel under a deadline and *cancel* the pending export** — `packages/host/product-telemetry-otel/src/index.ts:99` — the shutdown effect arms an `AbortController`; on expiry it aborts the export and warns that events may be lost, so a stalled collector cannot hold the host open. Any August background reporter needs the same deadline-and-cancel shape.

- **Say what the tool cannot do, in the tool's own description** — `packages/extensions/tool-cordis/README.md:71` — "Inspection cannot invoke service methods, configure plugins, or execute generated code." Explicit capability negatives in the tool description are cheap and prevent a whole class of model overreach.

## Uncertainties

- **Reasoning / thinking content is absent from this shard.** I checked every source file for handling of reasoning, thinking, or `reasoning` blocks: the only hits are the *tool-call* `content` block shapes in the UI cards (`packages/extensions/ui-cordis/src/client/card-model.ts:71-77`, which JSON-stringifies a non-text content block for display) and the tool-result content model. - **Prompt construction and KV-cache behaviour are only described, not implemented, here.** Every README in this shard has a "Model Experience" section with "Token effect" and "KV Cache effect" paragraphs, and those are the only statements I found — e.g. `packages/extensions/cordis-host-runner/README.md:127` ("A host half that registers tools changes the next request's tool view, which invalidates prefix reuse from the first changed schema token") and `packages/extensions/ui-cordis/README.md:99-101`.
