# deepseek-harness / dsh-apps-web#4

## Shard shape

This shard is the **browser-side acceptance lane** of the DeepSeek Harness web client: 30 Playwright/Vitest end-to-end specs under `apps/web/tests/` plus the two build-config files that make that lane possible (`apps/web/vite.config.ts`, `apps/web/tsconfig.json`). The specs are not thin UI smoke tests — they boot the **real Host composition** in-process (`launchWebScaffold` from `apps/web/tests/scaffold.ts`, owned by shard `dsh-apps-web#3`, 86 KB) against a **replayed model stream** and assert both the browser's ARIA/DOM surface *and* the Host's durable state (`sessionPersistence`, `workspaceRegistry`, `subagents`, `llm`). The recurring architectural idea is **event sourcing as the contract**: every spec asserts on `session/event` streams (`turn/start`, `step/start`, `assistant/message`, `tool/call`, `tool/result`, `subagent/catalog`, `turn/end`) and on the *persisted* JSONL log, never on a UI string alone. The shard covers six product surfaces: workspace/session management (list, group, rename, archive, recency, folding), the **subagent/parallel-execution** surface (spawn, fork, catalog tree, FIFO follow-up admission, per-child interrupt), **mid-turn steering** (Queue vs Steer gestures, the pending-steering mirror), turn rendering (the icon-action footer, usage readout, the collapsible Turn process, reasoning typography, streaming code fences), virtualization of the Trajectory ledger, and peripheral surfaces (voice input, web search, worktree opt-in, macOS window-drag geometry). A small group of specs (`trajectory-image-display.expected.e2e.ts`, `todo-row.expected.e2e.ts`, `submission-echo.e2e.ts`) run in **jsdom against the BUILT client graph** instead of Chromium, and one (`subagent-interrupt.e2e.ts`) is **browserless**, exercising the RPC surface over plain HTTP.

## Per-file notes

### apps/web/vite.config.ts
- **Purpose:** the Vite build for the web shell — chunk layout, worker bootstrap emission, and the guard that makes the shell unusable without a boot manifest.
- **Key abstractions:** five local plugins — `rejectStandaloneServe`, `clientDocumentTitle`, `brandFontLicense`, `emitPreviewPage`, plus the `manualChunks` resolver; `npmPackageOf(id)` maps a resolved module id to its npm package name by splitting on the last `node_modules/`.
- **Data flow:** `manualChunks` buckets a module into the `vendor` chunk when its npm package is in `VENDOR_PACKAGES` (katex, shiki, the micromark/mdast markdown pipeline); `@shikijs/langs` is split by *file* — the three boot grammars (`dist/typescript.mjs`, `dist/shellscript.mjs`, `dist/json.mjs`) go to vendor, the lazy read-card grammars stay unassigned so each keeps its own on-demand chunk.
- **Non-obvious design decisions:** *only packages workspace code imports directly* need listing — their private transitive deps (oniguruma, character tables) are pulled into vendor automatically by rollup's chunk colouring, and a dependency shared with index-side code falls back to index "a few kB of dilution, never a correctness problem". Every vendor member must be **React-free**: rollup folds a module shared between the entry and a manual chunk into the manual chunk, so one react-importing member would drag the single shared react copy into vendor. `resolve.dedupe: ['react','react-dom']` exists because a bare specifier otherwise resolves from the importer's directory and ships a second React, splitting hook and element identity.
- **Edge cases / failure handling:** `emitPreviewPage` throws if the `bootstrap` entry is missing from the bundle or if the built `index.html` lost its module entry tag, rather than emitting a preview page that cannot boot. `rejectStandaloneServe` throws in the `config` hook for `command === 'serve'`, i.e. *before* a dev/preview server can expose a boot-manifest-free shell.
- **Surprising:** the build target is `es2022` only because the worker bootstrap holds its page at top-level await; `process.versions.node` is defined as `"0.0.0"` to make the vendored Cordis loader's `fromInternal()` probe take neither branch, which is exactly the empty internal slot the shell boot fills.

### apps/web/tsconfig.json
- **Purpose:** the client-registered TypeScript project for `apps/web`.
- **Key abstractions:** extends `../../tsconfig.base.json`; `include: ["src","tests"]`; project `references` to the six workspace packages the tests import.
- **Data flow:** n/a — a compile-time boundary.
- **Non-obvious design decisions:** the ~190-entry `exclude` list exists because the web e2e lane (scaffold + replay specs) boots the **host spine** and reads its Context merges, which are host-plane programs checked in `tsconfig.host.json`; "one program cannot see both sides of the cordis Context merges", so the client-registered project must not also hold them. Note that the excluded list includes three files that are in *this* shard: `tests/voice-input.e2e.ts`, `tests/voice-setup.e2e.ts`, `tests/voice-download.e2e.ts`, `tests/steering.e2e.ts`, `tests/trajectory-virtualization.e2e.ts`, `tests/terminal-command-browser.ts`, `tests/subagent-fork-schedule.snapshot.ts`, `tests/streaming-fence-highlight.e2e.ts`, `tests/workspace-new-session-folding.e2e.ts`, `tests/workspace-management.e2e.ts`, `tests/workspace-recency.e2e.ts`, `tests/stats-paged-history.e2e.ts`, `tests/subagent-conversation.e2e.ts`, `tests/subagent-interrupt.e2e.ts`, `tests/subagent-interrupt-ui.e2e.ts`, `tests/window-drag-coverage.e2e.ts`, `tests/workflow-run.e2e.ts` — i.e. this shard's files are host-plane programs, which is why they can read `scaffold.ctx.*` directly.
- **Edge cases / failure handling:** n/a; exclusion is the mechanism.
- **Surprising:** the file is 234 lines of which ~190 are exclusions — the config's real content is a list of files that must NOT be type-checked by this project.

### apps/web/tests/support.ts
- **Purpose:** shared plumbing for the web smoke tests — dist location, free-port probe, failure screenshots, browser page construction, clock pinning, composer helpers, tooltip z-order measurement.
- **Key abstractions:** `requireBuilt(name)` (resolves a *built* workspace package through the dsh installation's own `require`, so its module map is shared with the Host plugins that import it), `pinHostClock()` / `pinBrowserClock(page)`, `newEnglishPage(browser, height)` / `connectFreshWorkspaceZh`, `writeComposerDraft`, `expandTurnProcesses` / `expandOwningTurnProcess`, `expectTooltipOnTop`, `conversationContextKey`.
- **Data flow:** `requireBuilt` uses `createRequire(join(REPO_ROOT, 'apps/cli/package.json'))`; `DIST_INDEX` points at `../dist/index.html`; `probeFreePort` binds `:0` on 127.0.0.1 and releases it.
- **Non-obvious design decisions:** *Playwright's `page.clock` is deliberately not used* — its server records clock state with the Vitest worker's `Date.now`, which `pinHostClock` replaces, so after a navigation the page clock replays the gap between the real and fixture days and hands a **negative delay** to native `setTimeout`; the browser truncates that to a 32-bit int and in about half of dates the result is a positive delay of weeks that stops every page timer. Hence the `Date` Proxy override installed via `addInitScript` + `evaluate` (support.ts:90-104). `writeComposerDraft` types **per key** rather than calling `fill()`: `fill()` issues select-all and insertText inside one task, and right after a trigger-menu or chip interaction Lexical's internal selection has not yet absorbed the DOM selection, so the batched edit lands on a null selection and is silently dropped, leaving the previous draft in place. It gates on `contenteditable="true"` rather than `isEnabled()`, because `isEnabled()` reports `true` for a `<div>` regardless of the attribute.
- **Edge cases / failure handling:** `saveFailureShot` wraps the screenshot in a try/catch — "a dead page/browser at failure time must not mask the real assertion error". `requireDist()` fails loud on a stale checkout instead of testing yesterday's bundle.
- **Surprising:** `conversationContextKey` is **restated** rather than imported: the specs live in the Host compiler aggregate, which must not reach the Client plane, so a drift between the two copies makes the key miss its rendered node and the assertion fails loudly.

### apps/web/tests/support/listen-probe.mjs
- **Purpose:** a 9-line Node preload that records every `Server.prototype.listen` call to a marker file, used to prove a server was never started.
- **Key abstractions:** `DSH_LISTEN_PROBE_MARKER` env var; monkey-patches `Server.prototype.listen` before delegating to the original.
- **Data flow:** `appendFileSync(marker, 'listen\n')` on every listen call.
- **Non-obvious design decisions:** the probe exists so `vite-entry.e2e.ts` can assert `existsSync(marker) === false` — i.e. that Vite refused *before* binding a port, not merely that it printed an error afterwards.
- **Edge cases / failure handling:** the marker env var being undefined disables the probe entirely (`if (marker !== undefined)`).
- **Surprising:** a test helper that proves a negative about the *network* using a prototype patch injected via `NODE_OPTIONS=--import`.

### apps/web/tests/workspace-management.e2e.ts
- **Purpose:** the workspace lifecycle spec — adding a workspace through the composed directory dialog (including its own "New folder" affordance), the path editor's pane-walking, rename over the wire with a duplicate-name pre-check, delete-keeps-data, flat vs tree grouping, the session hover card, row menus, and the archive round trip.
- **Key abstractions:** `browseTo(path)`, `addNewFolderWorkspace(parent, name)`, `adoptDirectory(path, {waitForAgent})`, `clickHoverAction(row, name)`, `seededSessionRow()`; seeds from `snapshots/web/seeded-history/session.v3.jsonl` rather than a new recording.
- **Data flow:** the dialog writes through the real `workspace.create` / `workspace.rename` / `workspace.archiveSession` host RPCs into `scaffold.ctx.workspaceRegistry`; the spec asserts both the registry (host durability) and the rendered tree, then reloads and re-asserts.
- **Non-obvious design decisions:** deleting a workspace **keeps** the folder, the session log and the messages — the dialog copy is asserted verbatim ("folder and session logs will be kept", "sessions will appear under Ungrouped") and the spec then re-reads `a.txt` and `stat`s the seeded log path to prove it. Re-registering the same path after a delete mints a **fresh Workspace id** and does *not* re-adopt the retained session ("no cwd-based blank reuse exists, so the account is never empty"). The `holdAttachment` websocket interceptor holds the session-attachment frame so the spec can prove the row was not yet visible when the delete ran.
- **Edge cases / failure handling:** the spec hunts for transient error surfaces with a `MutationObserver` on `[data-slot-error]` *and* `[role="alert"]`, plus a console listener for `/slot entry crashed/i`, and asserts both are empty — i.e. a delete must not flash an error. Golden capture is made deterministic by pointing the in-process host's `HOME` **and** `USERPROFILE` at the scaffold cwd so the breadcrumb collapses to a Home crumb.
- **Surprising:** the directory dialog's typed path drives a two-pane Miller view that follows the *draft*: a directory part no pane lists walks the panes to it, erasing back past the separator walks them up, and a tail nobody matches shows the level whole instead of emptying under it.

### apps/web/tests/subagent-conversation.e2e.ts
- **Purpose:** the subagent-catalog spec — a persisted subagent conversation, the catalog tree, human continuation of a child, the one-shot/continuable distinction, forking out of a subagent, and the migration-required legacy catalog.
- **Key abstractions:** `childFixture(source, fixtureId, withContinuation)` (derives a child JSONL from a parent fixture by re-numbering seqs and shifting `turn: 1 → 2`), `waitForAgentToSettle`, `waitForCacheRow`; cold fixtures are pushed into `sessionProjectionCache.coldSnapshot` to simulate a cold read.
- **Data flow:** the parent session's `subagent/catalog` event is the source of truth for the catalog; the child's own `subagent/catalog` event lists the grandchild. The spec asserts `scaffold.ctx.subagents.listChildren(parent.id)` matches the tree, and that opening a child **does not activate it** (`scaffold.ctx.agents.get(childId)` stays `undefined`).
- **Non-obvious design decisions:** the catalog button updates to "2 subagents" via a *push* of the parent's `subagent/catalog` event, and the spec asserts this cost **no** extra `/api/session/projections` request (line 220-230) — an incremental update, not a refetch. A one-shot child is **permanently read-only**: the sidebar shows "One-shot tasks do not accept follow-ups; review the full execution record here." A child whose parent is offline renders "The parent session is offline; reopen it to continue sending messages." — from the descriptor alone, so it says nothing about the transcript below it.
- **Edge cases / failure handling:** the migration-required describe block writes *historical* bytes to disk (zstd frames) so the reader sees `formatStatus === 'migration-required'`; the row shows "Migration required", the expand button is **absent**, `sessionController.projections` is **never called**, and the grandchild is not even observed — but the child itself can still be opened, after which only the child is observed. The files on disk are byte-compared before and after to prove nothing was migrated behind the user's back.
- **Surprising:** `captureStableAria` calls two identical polls stable — including two of "Loading history…" — so a golden can pin a transient loading state; the spec therefore waits for the specific message the golden asserts rather than for the load to finish.

### apps/web/tests/steering.e2e.ts
- **Purpose:** both mid-turn steering entry points — the QueueDock's explicit "Steer queued message" action and the composer shortcuts (Cmd/Ctrl+Enter) — plus the swapped Enter/Cmd+Enter preference and the empty-draft "steer everything" flush.
- **Key abstractions:** `assistantText(events)` (concatenates `text-delta` chunks out of `assistant/message` / `assistant/attempt` via `expandAssistantStream`), `claimedMessages(events, text)`; the `describe.each(['reconnect','delayed-inbox'])` handoff matrix.
- **Data flow:** the steer is admitted at the next step boundary and lands as a durable `user/message`; the spec asserts exactly one claimed message, one `turn/end` with `reason.kind === 'completed'`, and that the model's reply contains the marker word ("BANANA").
- **Non-obvious design decisions:** *Enter is the Queue gesture and Cmd+Enter is the Steer gesture by default, and the mapping is user-configurable* — the third describe block flips the preference in Settings and asserts that Cmd+Enter then *queues* instead. Steering is **not** a second turn: it is drained into the current turn's next request. The empty-draft Cmd+Enter flushes the **whole queue** in FIFO order, which is a different gesture from the per-row Steer button.
- **Edge cases / failure handling:** the 'reconnect' handoff closes the remote socket mid-admission and asserts the submission echo is withdrawn and the pending steering re-renders after reconnect; the 'delayed-inbox' handoff holds the *control* stream while history keeps flowing (FIFO hold of control frames) and asserts the steering is not lost. The recorded-turn gate: "a recording where the live model ignored the steer would replay as a vacuous scenario — reject it and re-record instead" (line 164-168).
- **Surprising:** the `agent/pre-step` hook is used as a *barrier* inside the test — the spec claims the steer message at the pre-step, then blocks there to observe the mid-turn UI before releasing.

### apps/web/tests/window-drag-coverage.e2e.ts
- **Purpose:** geometry coverage for the macOS window-drag surface — which chrome rows drag, which pixels stay content, and that no interactive control is swallowed by the drag band.
- **Key abstractions:** `collectedRegions(page, selector)` (walks every element with a computed `-webkit-app-region` of `drag`/`no-drag`, samples five points, and hit-tests each with `document.elementFromPoint`), `swallowedBoxes(regions)`, `firstRecallPulse(page)`, `settled(page)`, the `CoverageProbe` type.
- **Data flow:** the page is marked `data-platform="darwin"` via `addInitScript` with a fake `window.dshDesktop` preload; regions are read from the live DOM and fed to the *shared* `isDraggableAt(regions, x, y)` model imported from `@deepseek-ai/dsh-client-web/src/window-drag/regions.ts`.
- **Non-obvious design decisions:** CDP-injected clicks cannot decide this class (the swallow happens in Electron's native window), so the claims are **geometry claims decided by the shared composition model** rather than simulated clicks. The `CoverageProbe` carries an optional `gap` field: "a probe whose expectation is not yet met carries `gap` and fails loudly, so a recorded gap shrinks here first and the manifest follows" — a known-fail budget, not a silent skip.
- **Edge cases / failure handling:** the invariant with no gap budget is that a press inside any control box must reach the page instead of dragging the window — asserted as `swallowedBoxes(regions) === []` in every scenario. A pane's programmatic focus target is excluded from the hit test because it *contains* the window-drag strip that owns those pixels.
- **Surprising:** the spec asserts the shell **pulses the drag recall mark** while the right panel slides and clears it after the geometry settles — a mark left set would subtract the whole surface.

### apps/web/tests/subagent-interrupt-ui.e2e.ts
- **Purpose:** the composer's independent Stop button interrupting a running *continuable* child — including the parent-offline variant where Send is disabled but Stop is not.
- **Key abstractions:** `textCompletion(text)` (a scripted text-only model completion), `waitForAbortedTurn(scaffold, childId)`, `waitFor(predicate, what, timeoutMs)`; the replay override is a whole-script replacement `[hang, hang, completion×4]`.
- **Data flow:** the child's model turn is held open by a `hang` entry that writes `readyFile`; Stop posts to `/api/subagents/interruptByParent`; the abort shows up as `turn/end` with `reason.kind === 'aborted'`.
- **Non-obvious design decisions:** the addressed child stops through **its own RPC, never the generic one** — the spec asserts `apiCalls.filter(p => p === '/api/session/cancel')` is **empty** (lines 254 and 352). The interrupt leaves the Activation **resident and idle** with the follow-up parked: `child.inbox.nextTurn` keeps 3 entries and only 2 `turn/start` events exist. Only a waking send resumes the parked queue, FIFO.
- **Edge cases / failure handling:** the parent-offline case is produced by rewriting `/api/session/list` to set `agentAvailable: false` for the parent — the composer then renders disabled-Send-with-Stop while the row's Edit/Remove/Steer buttons remain available. An image-only follow-up is pasted via a synthetic `ClipboardEvent` to prove attachment admission without disturbing the text queue.
- **Surprising:** the spec asserts the persisted log contains the exact ordered user texts and that `turnEndKinds` equals `['aborted','aborted','completed','completed','completed','completed']` — the whole turn ledger, read off the physical JSONL, not the UI.

### apps/web/tests/turn-tail-actions.e2e.ts
- **Purpose:** when the assistant's icon-action footer (Copy / Branch / Usage) appears, and what a completed turn's usage readout shows.
- **Key abstractions:** `launch(buildOverride?, paceMs)` (boots a scaffold with an optional replay-override sidecar), `sendPrompt(timeoutMs)`, `expectFocusTooltip(page, button)`.
- **Data flow:** the recorded turn narrates in plain text *in the same assistant message* as its tool call; a `hang` patch on the **second** model call parks the turn after the narration and the tool result are durable.
- **Non-obvious design decisions:** the icon actions belong to the **settled** answer, so they arrive with `turn/end` and not before — otherwise the footer would sit beside mid-turn narration for the seconds a tool runs and then move down. The recording must carry text in the same message as the tool call, "a Think-only step would leave nothing for the footer to attach to and the scenario would pass against either implementation". `Tooltip` ignores focus while the last input came from a pointer, so the spec presses `Shift` (a key that moves nothing) to clear that flag before focusing.
- **Edge cases / failure handling:** the running golden asserts the *user* bubble owns the only footer (clock + copy) and that no Branch action exists yet; the settled golden asserts the frozen partial takes the seat while the mid-turn narration keeps none. A focused process member must stay open when the completed reply arrives.
- **Surprising:** the usage readout distinguishes exact facts: `Usage 15.8K tok` in the chip, and a dialog naming the model, the cache-hit percentage (49.7%), 7,891 tok in, 7,808 tok out, `112 tok (42 tok reasoning)` and 15,811 tok total — while asserting there is **no** `tok/s`/`TTFT` strip and no "Ran for …" button anywhere.

### apps/web/tests/voice-input.e2e.ts
- **Purpose:** browser dictation end to end — setup guidance, device selection, recording, transcription, and the rule that only *reviewed* text is submitted.
- **Key abstractions:** a fake speech provider registered through `scaffold.ctx.plugin({inject:['speechToText'], apply(ctx){...}})` with a `preparation` object (snapshot/subscribe/prepare/cancel) and a `transcribe` function; `navigator.mediaDevices` is monkey-patched in `addInitScript` to enumerate/exclude/name devices and to capture the acquired streams.
- **Data flow:** the recognizer asserts the audio is a RIFF container (`Buffer.from(input.audio).subarray(0,4).toString() === 'RIFF'`) longer than 44 bytes, and returns the fixture prompt's suffix; the transcript lands in the composer as **text**, and only Enter turns it into a `user/message`.
- **Non-obvious design decisions:** `prepare()` **throws** — "Cached resources must allow recording without preparation" — so the spec proves the cached path never asks for preparation. The setup dialog is focus-trapped: the spec types "NoDraftEdits" and asserts the composer draft is unchanged, so the dialog's typing does not leak into the composer.
- **Edge cases / failure handling:** the `preparation` state machine is driven through `unprepared → checking → failed → standby`, each transition notifying subscribers; the failed state renders "Open voice plugin settings" and the retry must re-run preparation. Losing the selected device makes the option render as "— Unavailable" and disabled, and the level meter hides. The dialog must fit a 420 px viewport.
- **Surprising:** the recorded text is *not* submitted by the recording — the spec asserts `messages === 0` and `recognize` called once after "Stop and transcribe", and only after an explicit Enter does the message count become 1.

### apps/web/tests/thinking-markdown.e2e.ts
- **Purpose:** the typography contract for expanded reasoning — Markdown semantics preserved, but at a *secondary* tier below the answer.
- **Key abstractions:** `thinkingFixture()` builds a closed session whose reasoning block contains headings, lists, a loose list, a quote, a rule, a 21-row table, six KaTeX formulas (short subscript, short scripts, a long `\underbrace`, inline math, display math), a fenced TypeScript block and a long unbreakable token.
- **Data flow:** the fixture is seeded through the real session API; the spec then measures computed styles inside `[data-markdown-variant="compact"]`.
- **Non-obvious design decisions:** headings are **not** promoted — `h1..h6` are all present and count 7, but every prose element uses the secondary font size and line height and the tertiary colour, including `::marker` colour for list bullets. Code typography is pinned to exactly `11px/19px`. A "short" formula must not need a scrollbar and must not be taller than its natural KaTeX baseline (the spec clones the paragraph, applies the secondary font size, and compares heights with a 1 px tolerance because "native KaTeX baselines vary with host fonts; compact adds one pixel for descender ink").
- **Edge cases / failure handling:** the long `\underbrace` atom **must** scroll, and display math **must** scroll; wide content (tables, display math, math lists) is bounded by 7 scroll containers, each no wider than the root. The summary line stays one line tall with `text-overflow: ellipsis` when collapsed.
- **Surprising:** the sticky header of the thinking block must keep receiving pointer events while a tall table scrolls *under* it — asserted by hit-testing the header's centre point against `document.elementFromPoint`.

### apps/web/tests/terminal-command-browser.ts
- **Purpose:** a shared assertion library for terminal cards — selection, copy, wrapping, overflow affordances and the status dot's alignment.
- **Key abstractions:** `expectSelectableTerminalCommand`, `expectWrappedCommandText`, `expectWrappedTerminalCommand`, `expectFirstLineTerminalState`, `expectCommandFocusAfterResize`, `expectNoCommandTabStop`, `expectSelectableCommandText`.
- **Data flow:** everything is measured with DOM `Range` objects (`selectNodeContents` → `getClientRects()`) rather than with screenshots; selection is performed with real mouse down/move/up over the range's head and tail.
- **Non-obvious design decisions:** an overflowing command becomes a keyboard-reachable `role="group"` with an `aria-label` and `tabindex="0"`; when the text *fits*, `expectNoCommandTabStop` demands that the `tabindex`, `role` and `aria-label` are all **absent** — the affordance must not linger. `expectCommandFocusAfterResize` widens the container by the overflow amount and asserts the affordance is withdrawn.
- **Edge cases / failure handling:** `expectWrappedCommandText` writes a sentinel into the clipboard before Ctrl+C, verifies the sentinel survived, then verifies the copied text is exactly the command — so a failed selection cannot be confused with a stale clipboard.
- **Surprising:** `expectFirstLineTerminalState` requires the status dot's vertical centre to be within 1 px of the **first visual line's** centre (`prompt.getBoundingClientRect().top + lineHeight/2`), i.e. the dot tracks the first line of a wrapped command, not the banner.

### apps/web/tests/trajectory-virtualization.e2e.ts
- **Purpose:** the contract for the tail-paged, virtualized Trajectory ledger — row identity across a prepend, bounded DOM, and reachability of every scroll range.
- **Key abstractions:** `logicalRows(page)` (reads `aria-rowcount`), `mountedRows(page)` (counts `tr[data-trajectory-row-key]`), `firstVisibleRow(page)` / `rowTop(page, key)` (semantic anchors, not pixel offsets), `scrollToRatio`, `loadToFirstTurn`.
- **Data flow:** a `/api/session/page` route interceptor holds the *older-page* request open while the spec selects a row, so the prepend lands **under** a live selection.
- **Non-obvious design decisions:** identity is measured **semantically** (the row's `data-trajectory-row-key`) and geometrically (its Y offset within 2 px), and the selection must survive the prepend — the ledger must not rebuild itself under the user's cursor. `MAX_MOUNTED_ROWS = 160` bounds the DOM regardless of logical row count. The "Load earlier history" button is clicked via `evaluate(button => button.click())` so Playwright does not scroll the offscreen first row into the automatic-load threshold.
- **Edge cases / failure handling:** while a history request is in flight the button is `disabled` with `aria-label="Loading earlier history…"`. `loadToFirstTurn` retries up to twelve older-page requests and throws with a specific message rather than looping forever.
- **Surprising:** during a streaming reply the trajectory pane may be re-laid-out at most **5 times** (`streamingScrollCalls <= 5`) — a stream must not fight the user's scroll position.

### apps/web/tests/web-search-round.e2e.ts
- **Purpose:** the shipped `web_search` composition — a real browser, the real provider, and a deterministic local Search API double.
- **Key abstractions:** `startSearchServer(captured)` (a local HTTP server that answers `/api/v1/tools/search` with fixture results and records the request body and `authorization` header), `requestQuery(body)`, the `KEPT_SOURCES` / `DROPPED_SOURCE_URLS` derivation.
- **Data flow:** the credential is set through the real credentials service (`scaffold.ctx.credentials.set(credentialRef('DSH_WEB_SEARCH_E2E_KEY'), ...)`) and the provider sends `Bearer <key>`; the model stream is replayed but the *tool* is real.
- **Non-obvious design decisions:** the model-visible result is **capped** and says so — "(Showing the first N sources. Refine the query for more.)" — while the card draws exactly the sources the model saw. The tool interleaves sources from both queries *before* applying the combined cap, so each query remains represented. `ori_question` is the prompt truncated to 128 characters, asserted exactly.
- **Edge cases / failure handling:** the marker-room check exists because "`overflow-y: auto` clips inline-start overflow with no way to scroll it back, and markers are right-aligned to the content edge, so a marker wider than `padding-left` silently loses its leading digits" — the spec measures the widest three-digit marker in the list's own font with a hidden probe span and requires the shipped padding to hold it (`searchMaxResults` is an unbounded positive integer, so three digits is the worst case).
- **Surprising:** the request body is asserted to be exactly `{query, count, need_content: false, ori_question}` — the tool's wire contract is pinned, not merely its outcome.

### apps/web/tests/workflow-run.e2e.ts
- **Purpose:** the durable workflow Conversation Node — a real workflow tool, worker, subagent provider, session log, browser plugin graph and navigation, all during replay.
- **Key abstractions:** `waitForParentSettlement()` (resolves on a non-subagent `turn/end`, then awaits `agents.get(id).whenIdle()` and `sessions.flush(session)`), `releaseChild` (a `Promise.withResolvers` gate that keeps the live child available), and an `llm/stream` hook that blocks the child's stream.
- **Data flow:** the parent fixture's single user prompt is replayed; the child fixture is a separate file bound through `replayChildFixtures`.
- **Non-obvious design decisions:** the settlement barrier is a **two-stage** wait — `turn/end` is not enough; the agent must be idle and the session flushed, otherwise the terminal record is not yet durable. The workflow card's disclosure rows are asserted to be real `role="button"` elements with `aria-expanded`, operable by Enter and Space, and to keep `cursor: pointer`.

## Ideas worth stealing

- **A `hang` replay entry that parks a model turn and writes a ready-marker file — the marker IS the synchronization** — `apps/web/tests/turn-tail-actions.e2e.ts:151` (and the sibling uses at `apps/web/tests/subagent-interrupt.e2e.ts:87`, `apps/web/tests/subagent-interrupt-ui.e2e.ts:107`) — the spec patches the *second* model call with `{ kind: 'hang', readyFile: marker }` and then waits for `existsSync(marker)`. This turns "the model is mid-tool-call right now" from a timing race into a deterministic fact: the turn is provably parked, so the narration and the tool result are already durable, and any UI state can be asserted without racing the stream. August has no equivalent, and this is the cheapest way to make mid-turn UI states testable at all.

- **Assert the addressed door is the one that was used, by asserting the *other* door was not** — `apps/web/tests/subagent-interrupt-ui.e2e.ts:254` — `expect(apiCalls.filter(path => path === '/api/session/cancel')).toEqual([])`. The UI Stop button must reach the child's own `subagents/interruptByParent` RPC, never the generic session cancel. A positive assertion ("the interrupt worked") would pass even if the generic cancel had been used and had cancelled the wrong thing; the negative assertion pins the *route*. Transfer: in August, every "stop" path should be able to state which of several cancellation doors it used.

- **A steering admission that is Host-authoritative, rendered as its own pending surface, and durable exactly once** — `apps/web/tests/steering.e2e.ts:136` (the `[data-pending-steering]` mirror) with the durable assertion at `apps/web/tests/steering.e2e.ts:173` — the client shows a *pending* steering surface while the Host has not yet admitted it; admission happens at the next step boundary; the steer lands as exactly one `user/message`; the visible bubble and the durable event are the same fact. The empty-draft Cmd+Enter flush (`apps/web/tests/steering.e2e.ts:480`) extends it: one gesture drains the whole queue in FIFO. This is the pattern August's mid-turn interjection needs — a steering *outbox* with a server-authoritative mirror, not a local optimistic bubble.

- **Fixture honesty: a recorded transcript that would make the scenario vacuous is rejected at record time** — `apps/web/tests/steering.e2e.ts:164` — "a recording where the live model ignored the steer would replay as a vacuous scenario — reject it and re-record instead", implemented as `expect(claimedMessages(recorded, STEER)).toHaveLength(1)` and `expect(assistantText(recorded)).toContain('BANANA')` inside the record-mode branch. Every August eval fixture should carry the same guard, or a flaky model can silently produce a green suite that asserts nothing.

- **Whole-log statistics from a projection, never a fold over the loaded window** — `apps/web/tests/stats-paged-history.e2e.ts:132` — the whole strip text is captured before paging and compared byte-for-byte after ("must not move ANY strip figure — counts, wall times, or token groups"), and the first page is deliberately partial so the number *cannot* have come from the loaded messages. The same idea appears as "the sessionStats projection, not the window fold" at line 122. August's usage/turn counters should be projections over the durable log, and the test should be written so a window-fold implementation cannot pass.

- **Semantic row identity + a bounded DOM + a scroll budget for a virtualized transcript** — `apps/web/tests/trajectory-virtualization.e2e.ts:280` (anchor a row, hold an older-page request, release it under a live selection, then assert the row's Y offset moved ≤ 2 px and the selection survived) with `MAX_MOUNTED_ROWS = 160` at `apps/web/tests/trajectory-virtualization.e2e.ts:38` and the streaming-scroll budget `streamingScrollCalls <= 5` at `apps/web/tests/trajectory-virtualization.e2e.ts:347` — three separable guarantees (identity, DOM bound, "a stream does not fight the user's scroll"). The scroll budget is the most directly stealable: it is a number, it is measured by wrapping `scrollTo`, and it fails loudly when a streaming response starts yanking the viewport.

- **A known-fail budget instead of a silent skip: probes carry a `gap` and still fail loudly** — `apps/web/tests/window-drag-coverage.e2e.ts:48` (`readonly gap?: string`) with the rationale at `apps/web/tests/window-drag-coverage.e2e.ts:16` — "a probe whose expectation is not yet met carries `gap` and fails loudly, so a recorded gap shrinks here first and the manifest follows". The failure message names the row, the point and the gap, so a failure is a *task list*, not a mystery. August's static gates would benefit from the same shape: known-unmet expectations stay visible and shrink.

- **Fail before the app can present a bootless shell — and prove the server never bound a port** — `apps/web/vite.config.ts:48` (the `rejectStandaloneServe` plugin) with the proof at `apps/web/tests/vite-entry.e2e.ts:58` — the error names the full host command and the missing `window.__DSH_BOOT__`, and a Node preload that patches `Server.prototype.listen` (`apps/web/tests/support/listen-probe.mjs:6`) proves the refusal happened *before* any network exposure. The technique (patch a prototype via `NODE_OPTIONS=--import` to assert a negative about the network) is reusable for any "must fail early" gate.

- **Vendor-chunk discipline for cache hit rate: only directly-imported packages are listed, and no member may import React** — `apps/web/vite.config.ts:111` (the comment) with the set at `apps/web/vite.config.ts:118` — "editing shell code re-hashes only index and returning clients keep the cached vendor chunk", and the React-free rule exists because rollup folds a shared module into the manual chunk, so one react-importing member would drag the single shared react copy into vendor. This is a concrete, checkable cache-hit optimisation: name the packages, keep the set React-free, put the lazy grammars outside it.

- **Pin the exact system prompt and the exact tool-schema set, so a prompt drift is a diff** — `apps/web/tests/subagent-fork-schedule.snapshot.ts:75` (`expect(tools).toEqual(schemas.initial)`) and `apps/web/tests/subagent-fork-schedule.snapshot.ts:78` (the system prompt compared to `system-prompt.expected.md`), plus `expect(child.requestHeader()).toEqual(parent.session.requestHeader())` at `apps/web/tests/subagent-fork-schedule.snapshot.ts:63` — a fork inherits the *request header*, not merely the messages. August's prompt-construction work needs exactly this: a golden of the assembled system prompt and of the offered tool schemas, asserted on every change, with a forked subagent asserted to inherit the header exactly.

- **Write a rich-text composer with per-key gestures, never `fill()`** — `apps/web/tests/support.ts:250` — "directly after a trigger-menu or chip interaction Lexical's internal selection has not yet absorbed the DOM selection, and the batched edit lands on a null selection and is silently dropped, leaving the previous draft in place". The helper types key by key and gates on `contenteditable="true"` rather than `isEnabled()`, "because `isEnabled()` reports `true` for a `<div>` regardless of the attribute". Any August test that drives a contenteditable composer needs this, or it will pass while doing nothing.
